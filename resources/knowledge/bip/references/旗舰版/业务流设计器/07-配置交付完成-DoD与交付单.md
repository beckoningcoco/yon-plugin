# 配置交付完成：DoD 与交付单

> **定位**：06 管「接单 → 确认单」；本文管「确认单冻结之后 → AI 配置交付完成」。
> **运行期验证与 UAT 由业务员做，不属于 AI 的 DoD**；AI 交付的是「可验证的配置 + 验收指引」。
>
> 配套模板：`bip/assets/businessflow/业务流配置交付单-模板.md`

---

## 一、两段式交付

| 段 | 谁负责 | 完成标志 | 凭证 |
|---|---|---|---|
| **A. AI 配置交付** | AI | 配置一致、已保存、已启用（测试环境）、无冲突、交付物齐全、未验证项明确 | 配置交付单 |
| **B. 业务验收** | 业务员 | 在真实单据上按指引跑通，认可结果 | 验收记录 / 签字 |

**两段不能混**：交付单是「AI 配置交付完成」的凭证，**不是**「业务验收通过」的凭证。
交付单上写「已交付」，不等于业务员已经验过。

---

## 二、AI 配置交付的 6 条硬判据

### D1 配置一致

**判据**
- `getById`：`billCode` = 核心单据；节点数 / 边数 = 确认单 B1；`content.nodes` 中 `isCore=1` 唯一。
- 每条边 `flowRule/list`：`refRuleCode`、`pushOpportunity`、`pushMode`、`createUserType`、
  `srcBizTypeId` / `tarBizTypeId` 与确认单 B2 一致。
- `getRuleByCode`：`makeBillRuleDetailList` 的差异条数与确认单 B4.2 一致；全沿用则 `dataItems` 为空。

**证据**：回读 JSON / 断言输出（存 `回读记录_03-<流id>.md` 或直接贴进交付单第 3 节）。
**不通过**：回施工；若发现是确认单写错，出 v2，不要就地改。

### D2 已保存

**判据**
- `browser_messages` 读到「成功 / 更新成功」。
- 回读内容在（刷新后仍在；或 `updateTime` / `modifierName` 有变化）。

**证据**：保存提示、回读时间戳。
**不通过**：查保存校验——核心单据交易类型（`00E5`）、转换规则完整（`1DDCE88C04600008`）、连线校验（`00D8`/`00DC`/`00DB`）。

### D3 已启用（测试环境）

**判据**
- `status=true`、`isCurrentVersion=true`、版本号 = 确认单。
- 列表「交易类型」列 = 预期（预置流显示 `--` 属正常）。
- 业务员打开单据**能看到按钮**（这一步由业务员确认，但 AI 要保证配置层）。

**证据**：保存提示 + `getById` + 列表截图 / 业务员回执。
**实测状态（2026-10-18，金隅共享）**：
- **保存 ✅**：**开版本控制（`isVerSupport=true`）的流**保存后变未启用，**重新启用时更新版本号**（使用者确认）；
  未开版本控制的流保存后保持启用、`version` 不变。保存本身未观察到 `version` 递增。
- **启用 ✅ 已验证**：列表「启用」→ 确认框「是否启用」→ 确定；`status` false→true，`version` 不变；
  「停用」反向验证可恢复。
- **启用被拦的实测**：同交易类型已被占用时，启用报 `000-533-020003 交易类型不滿足唯一性校验`
  （`JYTD_XS_09` 实例）——所以 D4 的冲突检查必须在点启用之前做。
- **没有独立「发布」动作**：开版本控制的流保存后需重新启用（此时更新版本号）；未开版本控制的流保存后保持启用。
  不要再找「发布」按钮。

### D4 无冲突 / 无副作用

**判据**
- 同 `billCode` + 同 `transactionTypeName` + `status=true` 只有本条，或冲突已按 D6 处理。
- 预置流（`isPreset=true`）未被修改。
- 现有其他流未受影响（改已有流时：改前 / 改后快照 diff）。

**证据**：冲突扫描结果、快照 diff。
**不通过**：停用 / 合并 / 回滚，由业务方决定；AI 不自动做合并。

### D5 交付物齐全

| 文件 | 作用 |
|---|---|
| `业务流需求确认单_01.md`（已确认） | 口径与决策依据 |
| `配置快照_03-<流id>-<日期>.json` | `getById` + 每条边 `flowRule/list` 原样，回读 / 回滚依据 |
| `回读记录_03-<流id>.md` | D1 的证据 |
| `业务流配置交付单_04.md` | 本单 |
| 验收指引（交付单第 5 节） | 业务员照着验 |
| 变更说明 / 回滚方式（交付单第 7 节） | 出问题能退 |

**不通过**：缺哪件补哪件，不交付半成品。

### D6 未验证项明确

**判据**
- 生产环境启用 / 上线、权限、真实推单、UAT 是否列入「未验证项」，逐条写「谁验 / 怎么验」。
- 不能把「没做」写成「已完成」。

**证据**：交付单第 6 节。
**不通过**：补写；未验证项为空反而要怀疑是不是漏了。

## 三、交付单

模板：`bip/assets/businessflow/业务流配置交付单-模板.md`

**填写纪律**

| 节 | 谁填 | 填什么 |
|---|---|---|
| 1 基本要素 | AI | 项目 / 环境 / 流 id / 编码 / 核心单据 / 参照流 |
| 2 配置内容摘要 | AI | 拓扑、每条边规则、字段映射差异、与确认单的偏差 |
| 3 回读证据 | AI | D1–D6 逐条结果 + 证据路径 |
| 4 启用状态 | AI | `status` / `version` / `isCurrentVersion` / 列表列 |
| 5 业务员验收指引 | AI 写，业务员用 | 验什么、怎么验、预期、失败先查什么 |
| 6 未验证项 | AI | 生产环境启用 / 上线 / 权限 / 真实推单 / UAT，逐条写谁验 |
| 7 回滚方式 | AI | 停用 / 快照 / 恢复 / 删除边界 |
| 8 变更记录 | AI | v1、日期、变更点 |
| 9 签字 | AI + 业务员 | AI 交付；业务员**接收**（不写「验收通过」） |

**一句话**：交付单填完 = AI 的活干完了；业务员签字接收 = 东西交到他手里了；验收通过是下一张单的事。

## 四、业务员验收指引（交付单第 5 节）

写给业务员，用业务语言，不出现 `pushOpportunity`、`refRuleCode` 这类字段名。

```text
验什么：<链路，如 销售订单 → 销售发货 → 销售出库单 → 销售发票>

怎么验：
1. 打开「<单据>」，交易类型选「<交易类型>」
2. 单据上应看到「<按钮名>」按钮
3. 点按钮 → 选择来源单据 → 应生成「<目标单据>」
4. 核对：<关键字段，如 数量 / 客户 / 组织 / 物料>
5. <配了回写> 保存后，<来源单据> 的「<字段>」应回写为 <预期>
6. <配了分单> 应按 <分组字段> 拆成 <N> 张

失败先查：
- 看不到按钮：交易类型是否选对 / 流是否启用 / 当前账号有没有按钮权限
- 点按钮报「单据上的业务流和下推按钮不一致」：同交易类型是否还有一条生效流
- 生成后字段为空：转换规则映射 / 必填字段 / 来源单据该字段是否有值
- 数量或金额不对：回写公式 / 分单字段 / 组织权限
```

> 这张指引的价值：业务员不需要懂配置，也能验；AI 也不用替业务员点单据。

## 五、问题回传格式

业务员验出问题，按这五项回传，AI 才能判断是配置错还是业务口径错：

| 项 | 例子 |
|---|---|
| 现象 | 点「订单发货」没反应 / 报某句错 / 生成后数量为 0 |
| 单据号 | 订单号 / 发货单号 |
| 预期 | 应生成 1 张发货单，数量 100 |
| 实际 | 生成了 0 张 / 数量 0 / 报错原文 |
| 时间 + 账号 | `2026-10-18 15:20`，账号 `xxx` |

**不要只发一句「不行」**——没有单据号和预期，只能靠猜。


## 七、什么不算交付完成（反例）

- 保存成功 ≠ 交付完成（还没启用、没回读、没交付单）。
- 保存成功 ≠ 交付完成（保存后还没启用，业务员看不到按钮）。
- 回读通过但没启用 ≠ 交付完成（业务员看不到按钮）。
- 配完没给验收指引 ≠ 交付完成（业务员不知道怎么验）。
- 未验证项没写 ≠ 交付完成（把「没做」藏起来了）。
- 改了预置流 ≠ 交付完成（平台资产被污染）。
- 同交易类型还有第二条生效流 ≠ 交付完成（运行期会报不一致）。

## 八、当前能力边界（诚实）

1. **D3 已实测（2026-10-18）**：开版本控制的流保存后变未启用，重新启用时更新版本号（使用者确认）；
   未开版本控制的流保存后保持启用、`version` 不变；**没有独立「发布」动作**
   （详见 `08-启用与发布-实测.md`）。
2. **权限不在 AI**：业务员看不到按钮时，先查账号权限；AI 只保证配置层（启用 / 交易类型 / 规则）。
3. **运行期验证、生产环境启用 / 上线、UAT 不做**：这些明确写在交付单第 6 节「未验证项」。
4. **测试环境 ≠ 生产**：本文的 D3 指测试环境保存 + 启用；生产环境启用 / 上线由业务员 / 管理员走审批。
5. **改造已有流的回滚**：快照能否灌回未验证；至少保证「停用」可退。

> 这五条不是免责声明，是交付单第 6 节必须如实填的内容。**把边界写清楚，业务员才知道自己接手的是什么。**
