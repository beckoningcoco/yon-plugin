# 表样结构操作：插列 / 删列 / 行，以及"怎么才算真的改成了"

> 实测：2026-10-10，金隅共享 `dev-fssc.bbmg.com.cn`，报表「账户明细表」（`18503d72-…`），
> 动作是"在 W 销户时间与 X 数据日期之间插一列"。
> 关联：[[00-设计器总览与操作纪律]]、[[01-筛选器与参数绑定]]、[[02-取不到数怎么排查]]
>
> **这一篇是被坑出来的**：插一列折腾了很久，绝大部分时间不是花在"点"上，而是花在
> **误判结果**（以为插坏了 / 以为没插成）、**没处理残留弹窗**、以及**用错方式往单元格里写字**上。
> 先读这篇能省一整轮。
>
> **如果只读四件事**：
> ① **§2.1 先拿到 `hot` 实例，之后一切读写都用它**（别数 DOM、别信列头字母）；
> ② **§8 找列只有一个可靠来源** —— `hot.getDataAtRow(1).indexOf('列名')`；DOM 列头字母、`th`/`td` 数量、x 坐标对齐**全都会给你"偏差"**；
> ③ **§6 往单元格写字只能用「编辑 → 粘贴」** —— `setDataAtCell` 存不住，严重时把画布搞成空白；
> ④ **§3 刷新后第一件事是处理弹窗；拿不准就「刷新 + 点否」回到服务端定义**。

## 1. 两条不同的插入入口，行为**不一样**

| 入口 | 行为 | 注意 |
|---|---|---|
| **顶部菜单「插入」→「列」** | **直接插列**（在选中列处），**不一定弹窗** | 实测有时直接落列，有时弹下面的对话框 |
| **右键单元格 →「插入」** | **弹「插入」对话框** | 必须再选一项 + 确定，**光点「插入」不算完** |

**「插入」对话框长这样**（`.wui-modal`）：

```text
插入
  ● 活动单元格右移        ○ 活动单元格下移
  ○ 整行  行数: [1]
  ○ 整列  列数: [1]
                       [取消]  [确定]
```

- **默认没有任何一项被选中** —— 不选就确定，等于什么都没做；
- 插列：选 **「整列」** → 列数保持 **1** → 点 **「确定」**；
- **这一步漏了，就会得到"菜单点了、也关掉了，但画布毫无变化"的假象**（本篇作者卡在这里很久）。

**点列头 vs 点单元格**：菜单内容会变。选中**整列**后右键，菜单里会多出「设置列宽 / 隐藏 / 取消隐藏」等列操作项，可用它**反证"整列是否真的选中了"**。

## 2. ⚠️ 判断"改成了没有"：**不要数 DOM**

这张画布是 **Handsontable 虚拟渲染**，DOM 里的表头/单元格数量**会随滚动变化，与真实列数无关**。
以下判据**全部不可信**（都是实测踩过的）：

| 判据 | 为什么会骗人 |
|---|---|
| `document.querySelectorAll('.ht_clone_top th').length` | 同一张 24 列的表，不同时刻量到 **24 / 36 / 37 / 50** |
| 列头字母（A、B…AW、AX） | 同样被虚拟渲染污染，滚到最右会报出并不存在的 `AX` |
| 每行 `td` 数量 | 含虚拟占位：24 列的表量到 **50** 个 `td` |
| `td.getAttribute('data-col')` | **本平台返回 null**，拿不到真实列索引 |
| **表头"非空文本"个数** | **新插入的列表头是空的**，会被 `filter(Boolean)` 滤掉 → **明明插上了却报"没插成"** |

### ✅ 唯一可靠的读法：React 组件里的 `settings.data`

画布的真实数据挂在 React fiber 的 props 上（`area` / `analysisModel` / Handsontable 的 `settings`）：

```js
// 读表样的"表头行"（第 2 行，index 1）
const el = document.querySelector('.handsontable') || document.querySelector('.ht_master');
const key = Object.keys(el).find(k => k.startsWith('__reactFiber$'));
let f = el[key], settings = null, d = 0;
while (f && d < 25) {
  const p = f.memoizedProps;
  if (p && p.settings && p.settings.data) { settings = p.settings; break; }
  f = f.return; d++;
}
const txt = (c) => c == null ? '' : (typeof c === 'object' ? String(c.v != null ? c.v : '') : String(c));
const headers = (settings.data[1] || []).map(txt);   // 第 1 行是标题，第 2 行才是表头
```

**判读**：
- **表头文本 + 空表头的位置** 才是证据（"销户时间"与"数据日期"之间是否夹着一个空）；
- ⚠️ **`data` 的数组长度可能被预分配**（实测插入后宽到 50），**不能只看 `.length`**；
- 同一组件里还能拿到 `area.setting.cells`，但那是**稀疏差异记录**（只列被改过的单元格），不是全量表样。

### 2.1 ✅ 最省事的路子：拿到 `hot` 实例，直接调它的 API

比读 React props 更直接 —— **先把这个实例搞到手，后面所有读写都靠它**：

```js
const getHot = () => {
  const el = document.querySelector('.handsontable') || document.querySelector('.ht_master') || document.body;
  const key = Object.keys(el).find(k => k.startsWith('__reactFiber$'));
  let f = el[key], d = 0, hot = null;
  while (f && d < 200) {                 // 沿 fiber.return 往上找
    const sn = f.stateNode;              // ← 是 stateNode，不是 memoizedProps
    if (sn && typeof sn === 'object' && sn.hotInstance && typeof sn.hotInstance.getDataAtRow === 'function') {
      hot = sn.hotInstance; break;
    }
    f = f.return; d++;
  }
  return hot;
};
```

**实测确认过的几个"不是"**：

| 尝试 | 结果 |
|---|---|
| `window.hot` | 存在，但**不是** Handsontable 实例（没有 `getDataAtRow`） |
| `Handsontable.instances` | **空数组** |
| `element.hotInstance` | **undefined** |
| `props.hotInstance`（fiber 的 `memoizedProps`） | **找不到** |
| **`fiber.stateNode.hotInstance`** | ✅ **就是它**（`depth=1` 就能命中） |

拿到之后，常用的读写：

```js
hot.countCols(); hot.countRows();
hot.getDataAtRow(1);                 // 读第 2 行（表头行）的整行
hot.getSelected();                   // 当前选区，形如 [[r1,c1,r2,c2]]
hot.selectCell(row, col);            // 选中一个单元格
hot.selectColumns(col);              // 选中整列 ← 插列/删列前用它，别点列头
```

> ⚠️ **`hot` 的列索引与 DOM 会错位**：实测 DOM 列头显示 `销户时间 = V`，而
> `hot.getDataAtRow(1).indexOf('销户时间')` 是 **47**。**一律以 `hot` 的索引为准。**
> 另一个易错点：`hot.getDataAtRow(1)` 里**前面可能有一串空列**（预分配），
> 所以 **`trim()` 之前和之后的 `indexOf` 不是同一个数** —— 别混用。

## 3. ⚠️ 刷新之后，先看有没有弹窗，再动手

**刷新页面不会自动丢弃未保存改动**，它会弹：

> **检测到当前设计存在未保存的改动，是否应用这些改动？** 　[否] [是]

**不处理它的后果**（本篇作者因此乱了一整轮）：

- 弹窗**一直挡在页面上**；
- 之后任何**按坐标**发送的真实点击（CDP 也是按坐标）**会落在弹窗上** —— 等于随机点了「是」或「否」；
- 点到「是」→ **之前那些废弃的改动又被应用回来**，画面看起来像"自己变了"。

**纪律**：

1. **刷新后第一件事：确认弹窗**（截图，或读 `.wui-modal` 的文本）；
2. 明确选一次：**「否」** = 丢弃未保存改动、回到已保存定义；**「是」** = 应用改动；
3. **弹窗没清干净之前，不要做任何画布操作**。

```js
// 快速检查残留弹窗
[...document.querySelectorAll('.wui-modal')]
  .filter(m => m.getBoundingClientRect().width > 200 && getComputedStyle(m).display !== 'none')
  .map(m => m.innerText.trim().replace(/\s+/g, ' ').slice(0, 120));
```

## 4. 改坏了怎么回退

| 手段 | 实效 |
|---|---|
| 「编辑」→「撤销」 | **时灵时不灵**：连续点会突然 `no-item`；实测撤过 1~2 步后就再也撤不动 |
| 键盘 `Ctrl+Z` | **完全无效**（合成 keydown 无效，Handsontable 的 undo 未必启用） |
| **不保存 + 刷新 + 弹窗点「否」** | **✅ 可靠**——回到已保存定义；前提是**你没保存过** |

> 所以动手前先确认"**当前是编辑态还是已保存态**"：**只要没点过「保存」，刷新+「否」总能回到干净状态**。

## 5. 杂项（都实测过）

- **画布会横向溢出**（`wtHolder.scrollWidth` 远大于 `clientWidth`），**右侧列默认在视口外**；
- **右键菜单按"表格坐标"定位，不随滚动偏移** —— 目标列在右边时，菜单会出现在**视口外**，于是"点了没反应"。**先滚到目标列附近再右键**；
- **合成 `MouseEvent` 在"弹菜单"这一步是有效的**（右键菜单、顶部下拉都能弹出来）；
  但**"点菜单项"这一步不稳定**：有时生效、有时只关掉菜单什么也不做。
  **凡是"点完必须有结果"的菜单项，用 CDP 真实指针**（本机脚本 `real-click.mjs`，按元素中心点，不做 `scrollIntoView`）；
- **看结果优先用截图**：界面上"多出来的列""挂着的弹窗"，截图一眼可见，比在 DOM 里猜快得多。

## 6. ⭐ 往单元格里写字：**"能看见字"和"平台承认"是两件事**

**本篇最重要的一节。** 同样一句"把文字写进单元格"，有三条路，**成败完全不同**：

| 做法 | 平台是否承认 | 实测结果 |
|---|---|---|
| `browser_type` / `browser_setValue` / 合成 `keydown Enter` | ❌ **只在 DOM 打转** | 编辑器里**看着有字**（`ed.value` 读得到），但 **`hot.getDataAtRow()` 里没有**；Enter 提交不了，编辑器一直挂着 |
| `hot.setDataAtCell(row, col, v)` | ❌ **只改 Handsontable 内存** | **值立刻进得去**（`getDataAtRow` 马上能读到）、**看起来完全成功** —— 但 ① **保存不进去**（刷新即失）② **严重时把整块画布渲染成空白**（实测踩过：表头、数据区全部消失） |
| **「编辑」→「粘贴」**（剪贴板先放好字） | ✅ **走平台自己的编辑流程** | **能保存、能持久化**，刷新后仍在 ✅ |

### 6.1 正确姿势（实测跑通）

```powershell
# ① 先把要写的字放进【本机】剪贴板
#    从本机设，绕开浏览器"脚本不能写剪贴板/需要用户手势"的限制
Set-Clipboard -Value '是否直联行'
```

```js
// ② 用 API 选中目标单元格（不要靠坐标点）
hot.selectCell(2, 23);        // 第 3 行（数据区）= 字段绑定行；第 23 列
```

```text
// ③ 顶部菜单「编辑」→「粘贴」（真实指针点击）
//    node real-click.mjs <page片段> "#tmpPasteItem"
//    —— 打开「编辑」菜单后给「粘贴」项打个 id，再用脚本点它的中心
```

```text
// ④ 点右上角「保存」图标：i.ap-baocun-011（title="保存"）
//    若弹「当前设计已被对象引用，是否修改？」→ 必须点「修改」
```

```js
// ⑤ 验证是否真落库：刷新页面
//    - 没有「检测到未保存的改动」弹窗  且  数据还在  → ✅ 真存住了
//    - 弹出「未保存的改动」                          → ❌ 没存住
```

### 6.2 要点

- **剪贴板从本机设**（`Set-Clipboard`），比在页面里调 `navigator.clipboard.writeText()` 可靠 —— 后者常被"需要用户手势"拒绝；
- **粘贴前必须先用 API 选中目标格**（`hot.selectCell`），否则会粘到当前选区；
- **写完立刻保存**：「粘贴」虽被平台承认，但**不保存照样会丢**；
- **保存按钮是右上角的图标**（`i.ap-baocun-011`），**不是** `.wui-button-text-wrap` 里的文字按钮；
- **验证就看"刷新后有没有未保存弹窗"** —— 这是最干净的判定。

### 6.3 为什么 `setDataAtCell` 会把画布搞空

它绕过平台的数据流直接改 Handsontable 的内存，**平台的表样状态（单元格属性 / 字段绑定 / 扩展标记）没跟着更新**，
渲染时拿到的是一份自相矛盾的数据 —— 轻则值不落库，重则**整块画布渲染成空白**。

> **救命键**：只要**没保存过**，**刷新 → 弹窗点「否」→ 完全回到服务端定义**，一个字段都不会少。
> 所以**拿不准的时候，第一反应是"刷新 + 否"，而不是继续操作**。

## 7. 插一列的完整正确流程（实测跑通）

```js
// ① 定位目标列 —— 一律以 hot 的索引为准（DOM 列头字母会错位）
const txt = (c) => c == null ? '' : (typeof c === 'object' ? String(c.v ?? '') : String(c));
const row1 = (hot.getDataAtRow(1) || []).map(txt);   // 第 2 行 = 表头行
const target = row1.indexOf('数据日期');              // 想插在它左边
hot.selectColumns(target);                            // ② 用 API 选中【整列】
```

```text
③ 顶部「插入」→「列」 —— 直接插列；
   若弹出「插入」对话框（活动单元格右移/下移/整行/整列），必须选「整列」+ 列数 1 + 点「确定」
④ 验证：hot.getDataAtRow(1).filter(Boolean).length 是否 +1；
        「销户时间」与「数据日期」之间是否出现一个空表头
⑤ 写字：按 §6 的「编辑 → 粘贴」
⑥ 保存：i.ap-baocun-011
```

**这一步的三个坑**：

1. **不要点列头选列** —— DOM 的列头字母与 `hot` 的列索引**滚动后错位**（实测 DOM 显示 `销户时间=V`，`hot` 里却是 col 47）。**用 `hot.selectColumns(col)`**；
2. **不要 `holder.scrollLeft = 999999`** —— 会**滚过头**，目标列头跑出视口，点击落空、插列无效。**滚到"目标列刚好可见"**再操作；
3. **验证只看 `hot.getDataAtRow()`**，不要数 `.ht_clone_top th` / `td` —— 虚拟渲染下同一张表能数出 **24 / 36 / 37 / 50**。

> **本节的价值回顾**：这一轮"插一列 + 写表头 + 绑定字段"花掉的时间，**九成不是花在点上，而是花在误判结果**
> （以为插坏了 / 以为没插成 / 以为保存了）。**把测量方式换对（`hot` API + 截图 + 刷新验证），整件事就顺了。**

## 8. ⭐ 怎么可靠地"找到某一列"

单独立一节，因为**本轮最耗时的其实不是插列，是"找列"** —— 反反复复在"这一列到底对应哪个索引"上打转，
每换一种办法就发现"有偏差"，换到最后才确认**只有一种索引可信**。

### 8.1 只有一种索引是可信的

> **`hot.getDataAtRow(1).indexOf('列名')`** —— 第 2 行（表头行）的**数组下标就是列索引**。
> 其余一切"看起来像列索引"的东西，实测**全都不可信**：

| 看上去能用 | 实测为什么不行 |
|---|---|
| **DOM 列头字母**（`.ht_clone_top th` 里的 `A`、`B`…`AX`） | ① **虚拟渲染**：数量和位置**随滚动变化**（同一张 24 列的表，滚到最右会报出 `AX`，等于 50）；② **与 `hot` 的索引错位** —— 实测 DOM 显示 `销户时间 = V`，而 `hot` 里 `indexOf('销户时间') = 47` |
| **用 x 坐标把单元格与列头"对齐"** | **列头宽度 ≠ 数据列宽度**（实测有的 100px、有的 185px），对齐结果直接指向**隔壁列** |
| **数 `.ht_clone_top th` / `td` 个数** | 虚拟渲染：同一张表能数出 **24 / 36 / 37 / 50** |
| **`td.getAttribute('data-col')`** | 本平台**返回 null** |
| **`settings.data[1]` 的下标** | 与 `hot.getDataAtRow(1)` 一致，**但**前面可能有一串**预分配空列**，`trim()` 前后 `indexOf` **不是同一个数**（这里混用过一次：算出 col 49，实际是 23） |
| **右侧属性面板的"单元格 AW2"** | 那是它自己的列字母，**不能当 `hot` 的索引**用 |

### 8.2 正确做法

```js
const txt = (c) => c == null ? '' : (typeof c === 'object' ? String(c.v != null ? c.v : '') : String(c));

// ① 用 hot 读表头行 —— 这里的下标就是列索引
const row1 = (hot.getDataAtRow(1) || []).map(txt);
const col  = row1.indexOf('数据日期');     // ← 列索引的唯一来源

// ② 选中它
hot.selectColumns(col);                    // 插列 / 删列前：选整列
hot.selectCell(2, col);                    // 写单元格前：第 3 行 = 数据区

// ③ 立刻回读确认
hot.getSelected();                         // → [[r1, c1, r2, c2]]，c1/c2 即列索引
```

### 8.3 三条纪律

1. **不要在 `trim()` 之后的数组上取下标，再拿去操作原始矩阵** —— 两个下标不是一回事；
2. **每次操作前重新读一次 `row1`** —— 插列 / 删列**都会改变列索引**，上一轮算出的 `col` 下一秒就失效；
3. **拿不准就截图** —— 人眼一眼能看出"是不是这一列"，比任何 DOM 推算都快。

> **一句话**：**列索引只有一个来源 —— `hot.getDataAtRow(1).indexOf('列名')`。**
> **DOM 的列头字母、`th`/`td` 的数量、x 坐标的对齐结果，全都别用来推断列。**
