# 消化一份素材

四步，一步都不能跳。**每一步的产出都从工具拿，不要凭印象做。**

```
0  素材准备    PDF 先抽成带页标记的文本          没有文本后面全做不了
1  重叠门禁    digest_audit（不给 product）      值不值得做
2  摸底        digest_plan                       分几章、每章从哪行到哪行
3  写页面      按下面的规范写                    按体量分页
4  验收        digest_audit（给 product）        七项全过才算完
```

## 第零步：把 PDF 变成文本

`digest_plan` 与 `digest_audit` 的 `source` 参数要的是**抽取出来的文本**，不是 PDF 本身。这一步不属于消化，但没有它后面四步一步都走不了。

优先用 xparse（表格与版式还原更好）：

```
npx --yes xparse-cli parse "<file>.pdf" --api auto --output "<输出目录>"
```

它会写 `<basename>.md` 进输出目录。`--api auto` 先跑免费额度，额度不足会返回 `PAID_QUOTA_REQUIRED` 与重置时间——**这时不要自作主张切 `--api paid`**，先告知用户。（实测踩过：CLI 不在 PATH 上、当天额度为 0 页，两个坑都是当场才发现的。）

额度不可用时的降级路径是 PyMuPDF，抽出的文本必须带**物理页标记**：头部三行（`# 标题`、`# 原始文件:`、`# 页数:`），每页正文前一行 `## 第N页`。

**这个页标记格式就是配置项 `pageMarkPattern` 认的东西**——换了抽取器就要同步改配置，否则溯源密度会直接掉到 0。

## 第一步：值不值得做

先跑门禁，**不要先读文档**：

```
digest_audit(source="<源文档绝对路径>", vault="<vault id>")
```

不给 `product` 就是只跑门禁模式。看重叠率：

- **≤ 85%** → 有增量，继续
- **> 85%** → 大部分内容已在库里。**先问用户增量在哪**，别急着做

实测过一份红皮书与库里已有官方文档重叠 91.2%——不跑这一步就会花大力气生产 91% 重复的内容。

## 第二步：摸底

```
digest_plan(source="<源文档绝对路径>")
```

它给你：页数、字符数、章节骨架、**每章的 offset 与 limit**。

**把 offset/limit 直接交给 read 工具分段读，不要按页号自己算范围。**

> ⚠️ 这条是踩出来的：按页号切章，把 2.3 部署架构的尾巴（p15–16）划给了下一章，
> 而负责下一章的人按"只写这一章"处理，**那半节从知识库里消失了**，直到最后
> 核对才发现。章常常跨页，`digest_plan` 给的范围是按标题边界算的。

它还会提示：源文档没有一级标题（章是从 `3.1`/`3.2` 的前缀推出来的，**标题是生成的，引用时用范围不要照抄标题名**）、图可能只剩图题、章节格式认不出来（这时要改配置）。

## 第三步：写页面

**一篇文档 = 1 个 `wiki/sources/` 索引页 + N 个 `wiki/topics/` 主题页**。

**按体量分页，不要按章号硬套。**「一章一页」只是个起点。实测一份 129 页文档，第六章「开放接口说明」占了 56499 字符（全文 76%），照「一章一页」会产出一个 80 KB 的怪物页——读不动也改不动；这时按二级小节拆（6.1 / 6.2 / 6.3 / 6.4 各一页）。反过来，前五章加起来才 9000 字符，就不必各占一页。

拆分不影响验收：`digest_audit` 看的是「源文档的章节有没有进产物」，不数产物有几个文件。

### frontmatter 五个必填

```yaml
---
tags: [标签]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [raw/articles/<源文件名>]     # 必须指向 vault 内的路径
platform_version: "BIP V5"            # 必填
project: ""
last_verified: YYYY-MM-DD             # 必填
status: unverified                    # 从文档抽取、未经环境实测的一律 unverified
source_type: doc
---
```

`status` 别随手写 `verified`——那个值表示"在真实环境验证过"。从文档读来的知识是 `unverified`。

### 正文必须做到

| 要求 | 为什么 |
|---|---|
| **每节标页码**，格式 `（p23）` | 用 **PDF 物理页号**。原文正文的页眉印的页码比物理页小 1，两者不要混 |
| **覆盖本章全部小节**，一个不落 | 验收会算覆盖率 |
| **照录清单、表格、步骤** | 不要概括成一句话——摘要式糊弄会让覆盖率掉到 20% 以下 |
| **照录约束**："必须/禁止/不支持/注意"一条都别丢 | 这些最容易被摘要吃掉，又最不能丢——使用者会因此踩坑 |
| **标识符原样保留** | `UCF-MDD`、`cdatarule`、`getQuerySchemmaByCond`（原文拼写）都不改写、不规范化大小写 |
| **图缺失就标注** | 写"原图未随文本抽取，此处无法还原"。**绝不凭图题想象图的内容** |
| **代码残缺就照残缺记录** | 注明"原文此处可能为代码片段，抽取后残缺"。**绝不补全代码或配置** |
| **原文笔误照录并加注** | 比如原文把 OMG 写成「OMGz」——照录，然后注明应为 OMG |
| **编者注用 `>` 引用块** | 见下，这是契约不是风格 |

### 编者注必须用引用块

```markdown
> 原文此处把 OMG 写作「OMGz」，应为 OMG 的笔误，上面按正字记录。
```

**这不是排版偏好，是契约**：`digest_audit` 的保真率检查会跳过引用块。批注里常常故意提到源文档没有的词（"原文拼写 `MddRefServcie`，疑为 `MddRefService`"）——后半截是要给的建议，不是事实声明。写在正文里就会被当成幻觉。

### 结尾两节

```markdown
## 原文没有讲清的
这里列真正缺的东西：图缺失、代码残缺、原文自己前后矛盾之处。

## 相关页面
- [[另一个主题页]]
```

## 第四步：验收

```
digest_audit(source="<源文档>", product="<页面文件或目录>", vault="<vault id>")
```

> ⚠️ **`product` 只能给一个文件或一个目录，给不了"这一批文件"。** 产物和库里几千个既有页面同在 `wiki/topics/` 时，直接传那个目录会把**全部**页面算成产物——保真率会把别的文档的标识符统统报成幻觉。先把本次产物归集到一个临时目录再跑。

七项全过才算完：

| 项 | 阈值 | 不合格怎么办 |
|---|---|---|
| 结构完整 | frontmatter 五个必填 | 补字段 |
| 中文术语覆盖 | ≥ 85% | 有整节没写进去 |
| 二级章节覆盖 | ≥ 60% | 漏了小节 |
| 约束句覆盖 | ≥ 85% | 把限制条件略掉了 |
| 保真率 | ≥ 98%（两个口径取低） | **看逐条出处**——真幻觉要删，合法引用/批注要改成引用块 |
| 溯源密度 | ≥ 50% | 加页码标注 |
| 可寻址 | ≥ 70% | 产物太概括，源文档的术语进不去 |

**保真率报的"找不到"不等于幻觉**。报告会给出每条的出处，逐个判断：引用别处来源的（保留）、批注原文拼写的（移到引用块）、原文用文字描述层级而产物写成点号路径的（可保留），**真正编造的要删掉**。

## 回头看：库里这一批做得怎么样

上面四步是消化**一份**素材。要问「库里已有的消化质量如何」，用：

```
digest_sweep(vault="<vault id 或绝对路径>", under="wiki/topics")
```

它按产物 frontmatter 里的 `sources` 自动配对源文件，**按源分组合并验收**，把最差的排在最前。

**分组这一步不是可选的。** 一份源文档常被拆成多个主题页，逐页对着整本源文档比覆盖率必然不合格——实测一份 129 页文档拆 10 页，单拿一页去比只有 12%–43%，十页合起来才是 98.7%。第一版 `digest_sweep` 就是逐页比的，于是报告说「30 份全部不合格」，连刚验收合格的那批也在里面。

除了覆盖率与保真，它专门分出三桶**根本没法验收**的产物：

| 桶 | 含义 |
|---|---|
| 来源缺失 | `sources` 指向的文件不在库里——页面在、来源没了，不可复核 |
| 无 vault 内来源 | `sources` 指向库外的 PDF 名（如 `"iuap-xxx红皮书 (129页)"`）——无从核对 |
| 读不到 | 文件损坏 |

实测扫一个真实库的 `wiki/topics`（93 份）：

```
能验收           9 组   合格 1 / 不合格 8
无 vault 内来源  59 份   ← 63%
来源缺失          4 份
```

**「59 份无从复核」本身就是结论**：库里多数产物没有任何可回溯的依据，frontmatter 里写的是 PDF 名字，而那份 PDF 不在库里。

同一源下若混了多代产物（实测一个组里既有 9/28 那代的一页、又有另一批 9 页，指向同一个源却是两次独立消化），合并验收会把两代的差异一起算——报告里有提示，看的时候要对照页名判断是不是同一代。

**这个工具查出来的最险的一类，是覆盖率满分而保真率极低的产物**：实测 `raw/notes/2026-05-27-env-setup.md` 术语覆盖 100%、保真率只有 17%、可寻址 30%——术语都提到了，但绝大多数标识符在源文档里根本不存在。**只看覆盖率会把它当成好东西。**

## 它验证不了什么

**只能验证"覆盖"与"保真"，验证不了"正确"。** 产物忠实照录了原文的错误取值，照样判合格。涉及配置值、接口路径、参数名时，用前请对照真实环境验证。

**还有一处已知漏网**：纯英文单词形态的臆造（`DAO`、`Service` 这类不成标识符形态的词）逃过保真检查。

**更要紧的一处**：**编造如果全是中文通用词，保真率会给满分。** 保真率只看标识符（英文/数字形态），所以「消息队列」「生产者消费者模式」「点对点、发布订阅」「死信队列」这类纯中文的臆造，一个都抓不到。

实测例：一份 129 页的**消息平台**红皮书（讲模板、通道、待办、工作通知），被人写成"消息队列开发指南"，列了上面那六条 MQ 概念——**没有一条在原文里**，而保真率报 **100%**，因为它整页只抽出 1 个标识符。只有**术语覆盖 1.9%** 这一项反映了问题。

**所以中文编造只能靠覆盖率间接发现：看不到覆盖率，就看不到这种错。** 一份产物哪怕保真率满分，也要看覆盖率那一行。

**中文术语这一项会带进抽取噪声。** 术语是 n-gram 抽出来的，PDF 抽取把行切碎之后会产生像 `检查迪调用环境是`、`迪调用环境是否正` 这样的片段——它们不是真术语，永远不可能出现在产物里，却占着分母。实测一份 129 页文档，375 个术语里 5 个是这种噪声（覆盖率仍 98.7%，因为分母够大）。**文档越小，噪声占比越高，越会压低覆盖率**；这时看报告里「未覆盖的术语」那一行，是碎片就放过。

## 关于阈值

在 `~/.dsh/yon-panel/digest_config.json`，九组参数可改（阈值、章节模式、术语词表、页码格式等）。按素材类型调整——网页素材没有页码，`pageMarkPattern` 要换；章节编号形态不同的文档要改 `chapterPattern`。

**这些数是实测校准出来的起点，不是"正确的"数。** 85% 和 98% 能分开实测样本，换成你的素材类型可能需要调。

## 一份做完的样子

实测一份 133 页红皮书（6 章）：

```
sources/xxx.md     4.4 KB    文档级索引：是什么、六章导航、读它的提醒
topics/xxx-第1章.md  6.5 KB
topics/xxx-第2章.md 28.9 KB
...                        一章一页
```

验收结果：中文术语 98.0%、标识符 99.1%、二级章节 100%、约束句 88.9%、保真率 98.0%、溯源 191 处（100%）、可寻址 20/20。判定合格。

第二份实测是一份 129 页的接口手册（6 章，其中一章占全文 76%），拆成 9 个主题页 + 1 个索引页、共 134 KB。验收：中文术语 98.7%、标识符 100%、一级章节 6/6、二级章节 68.8%、保真率 98.6%、溯源 78 处（50.0%）、重叠 77.5%、可寻址 20/20。判定合格。

**同一份产物在修复前被判过不合格**——不是产物有问题，是 `digest_audit` 的章节识别与 `digest_plan` 漂移成了两套实现，把参数表里的「0 表示操作成功，和result 等同」当成了一个一级章节。现已合并为单一实现，并由 `tests/digest.spec.ts` 钉住那次漂移。**记在这里是因为它说明一件事：验收报不合格时，先怀疑检查器，再怀疑产物。**

**对比**：同一个检查器对一份 1.1 KB 的"摘要式"产物判不合格——术语 2.8%、可寻址 5.0%。那份摘要列的六章内容与文档真实的六章**没有一条对得上**，是照标题想象出来的，而它标着 `confidence: EXTRACTED`。
