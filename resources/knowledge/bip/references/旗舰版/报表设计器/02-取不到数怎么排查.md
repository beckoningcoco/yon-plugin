# 报表取不到数怎么排查（下拉空 / 报表 0 行）

> 实测：2026-10-10，金隅共享 `dev-fssc.bbmg.com.cn`，租户 `U8C3`，
> 对象：报表《账户直联情况统计表-管理口径》新增的「组织报表体系」筛选器。
> 关联：[[01-筛选器与参数绑定]]、[[00-设计器总览与操作纪律]]、[[../语义脚本编辑器/01-参数与固定值替换]]

## 0. 先分清「空」在哪一层 —— 三种空的成因完全不同

| 现象 | 出问题的层 | 去哪一节 |
|---|---|---|
| 筛选器下拉显示「暂时没有数据哦~」 | **筛选器自己的取数**（它有自己的数据源模型） | §3 |
| 报表表格空 / 合计空 | **报表主查询**（数据集 SQL） | §3.1、§3.2 |
| 「参数绑定」弹窗里参数下拉是空的 | **报表元数据缓存**（页面加载早于你改模型） | [[01-筛选器与参数绑定]] §5.0 |

**别混**：筛选器下拉空 ≠ 报表没数据；它们打的是不同接口、读不同配置。

## 1. 排查顺序（从便宜到贵，别一上来就改配置）

1. **找参照**：手边有没有一张**同类型且能用**的报表？
   → 把两者的筛选器配置逐项对比。**这是最快的一步**，本次就是靠它把范围缩到"来源模型"和"参数"。
2. **看请求**：抓取数接口 `/iuap-data-analytic/analysis/reference/data` 的 **body**
   → 拿到"平台实际用什么模型、带了什么参数"（§2.1、§2.2）。
3. **看响应**：抓同一请求的 **response**
   → 区分「控件坏」和「服务端 0 行」（§2.3）。
4. **库上实跑**：把 SQL 里的参数换成固定值，用 `datasource_query` 跑一遍
   → 有行 = SQL/模型都对，问题在**参数渲染**；没行 = SQL 或数据问题。
5. **逐参数对比**：两张报表的取数参数拉平成 `paramId → code → value` 再比（§2.4）。
6. **改一处、保存、预览**：一次只动一个变量，否则不知道是哪一步生效的。

## 2. 实测可用的代码片段

### 2.1 抓请求（含 body）

`fetch` 和 `XHR` 都要包（平台两种都用）：

```js
window.__reqs = [];
const of = window.fetch;
window.fetch = function (...args) {
  try {
    const url = typeof args[0] === 'string' ? args[0] : (args[0] && args[0].url);
    const opt = args[1] || {};
    if (/reference\/data/.test(url || '')) window.__reqs.push({ url: String(url), body: opt.body ? String(opt.body) : null });
  } catch (e) {}
  return of.apply(this, args);
};
const oOpen = XMLHttpRequest.prototype.open;
const oSend = XMLHttpRequest.prototype.send;
XMLHttpRequest.prototype.open = function (m, u, ...rest) { this.__u = u; return oOpen.call(this, m, u, ...rest); };
XMLHttpRequest.prototype.send = function (b) {
  try { if (/reference\/data/.test(this.__u || '')) window.__reqs.push({ url: String(this.__u), body: b ? String(b) : null }); } catch (e) {}
  return oSend.call(this, b);
};
```

> ⚠️ **别在 hook 里 `slice` 截断 body** —— 截断后 `JSON.parse` 必失败（踩过）。
> 装完 hook 要**重新触发一次**取数，且下拉数据可能被缓存 → 先点空白处关掉再打开。

### 2.2 解开 body：gzip + base64

body 形如 `{"Datas":"H4sIAAAA…"}`，`Datas` 是 **gzip 再 base64**；解开后可能是**多个 JSON 拼接**，
所以用括号配对取**第一个完整对象**，不要硬编码长度：

```js
const firstJson = (s) => {                    // 括号配对，忽略字符串内的括号
  let d = 0, str = false, esc = false;
  for (let i = 0; i < s.length; i++) {
    const c = s[i];
    if (str) { if (esc) esc = false; else if (c === '\\') esc = true; else if (c === '"') str = false; continue; }
    if (c === '"') { str = true; continue; }
    if (c === '{') d++;
    else if (c === '}') { d--; if (d === 0) return s.slice(0, i + 1); }
  }
  return null;
};
const bj = JSON.parse(last.body);
const bin = Uint8Array.from(atob(bj.Datas), c => c.charCodeAt(0));
const text = await new Response(new Blob([bin]).stream().pipeThrough(new DecompressionStream('gzip'))).text();
let obj = null;
try { obj = JSON.parse(text); } catch (e) { const js = firstJson(text); if (js) obj = JSON.parse(js); }
```

**解开后重点看三样**：

| 字段 | 含义 |
|---|---|
| `wideTableModel.name` / `.from` | **平台实际用的数据集与模型**（跟报表定义里的 `from` 对不上 = 引入错了） |
| `params[paramId][].code` / `.value` | **每个参数渲染前拿到的值**（`$$$` = 未选） |
| `iType` | 控件类型（`REFERENCE` / `REFERENCE_TREE` …） |

### 2.3 抓响应：区分「控件坏」还是「服务端 0 行」

```js
XMLHttpRequest.prototype.send = function (b) {
  const self = this;
  if (/reference\/data/.test(self.__u || '')) {
    self.addEventListener('load', function () {
      window.__resps.push({ status: self.status, text: String(self.responseText).slice(0, 1800) });
    });

```

判读：

- `datas: []` + `totalCount: 0` → **服务端查不出行**（去 §3）
- `fields: [ … ]` 齐全 → **字段配置没问题**（别再折腾字段了）
- `level > 0` / `errorStack` 非空 → 服务端报错，看 `traceId` 找后端

## 3. 高频根因（按本次命中顺序）

### 3.1 ★ 同名参数冲突（本次的根因，最隐蔽）

**机制**：不同数据集可以有**同名参数**（各自的 paramId）。但报表的参数是**按名字合并**的 ——
主数据集的参数拿到了值，**其他数据集的同名参数拿不到**，渲染进 SQL 就成空 → 条件恒不成立 → 0 行。

**判据**（两条都满足就高度怀疑）：

1. 该参数在报表定义里**只有一个 paramId**，但**多个数据集**的 SQL 都引用它；
2. 出问题的都是**同名**参数，而**独有**参数一直正常（本次 `orgCode` 是模型独有 → 一直是好的）。

**佐证方式**：在报表侧给这个参数**显式绑一个常量**（参数绑定 → 来源类型=常量）——
如果**仍然 0 行**，说明这条绑定喂的是主数据集那个参数，喂不到目标模型的，同名冲突坐实。

**解法（三选一）**：

| 方案 | 写法 | 适用 |
|---|---|---|
| **① 系统变量**（推荐） | `'${var('tenantId')}'` | 平台自动填当前租户，**不参与报表参数合并** |
| ② 固定值 | `'jd4ofb7k'` | 单环境够用；换租户要改 SQL |
| ③ 参数改名 | 改成 `ytenant_id_org` 之类 | 最"正统"，但模型 + 报表绑定都要动 |

### 3.2 ★ 改动没保存 / 保存被弹窗挡住

**两条铁律（本次都踩了）**：

| 在哪看 | 读到的是 |
|---|---|
| 语义模型页面点「**执行**」 | **编辑态** —— 不保存也能跑通 |
| **报表 / 筛选器取数** | **已保存的定义** —— 不保存，报表拿到的还是旧 SQL |

所以"模型页面执行成功、报表还是空"是**正常现象**：**改动要保存**。

而保存报表时若弹：

```text
当前语义模型 <名> 已被对象引用，是否修改？   [取消] [修改]
```

**必须点「修改」**，否则**等于没保存**（本次因此丢掉过整轮改动，页面重载后打回原形）。

### 3.3 `$$$` 是平台的「未选值」标记

参数值出现 `["$$$"]`，渲染进 SQL 就是空 → 条件不成立。
**常见触发**：筛选器绑定了这个参数，但筛选器**还没选值** → 把参数默认值刷成了空。
（`vOrCs` 字段里往往还留着原来的默认值，别被它误导 —— 平台用的是 `value`。）

### 3.4 引入模型选错了（副本）

「选择模型」面板里可能同时有 `xxx` 和 **`xxx-副本`**（编码形如 `total_org_systrem` / `total_org_systrem_copy1`），
中文名只差"‑副本"三个字。**认编码，别看中文名。**

**判据**：取数请求里的 `wideTableModel.name` 与报表定义里筛选器 `from` 指向的数据集**对不上**。

### 3.5 控件类型选错

模型**没有层级字段**（只有 id/code/name）时，配成「树形参照」取不到数
（面板里"子级字段/父级字段"下拉是空的，就是信号）。
**对照参照报表的 `iType`** —— 本次正确值是 `REFERENCE`，不是 `REFERENCE_TREE`。

## 4. 直接读报表定义（不想开一堆面板时）

```text
/iuap-data-analytic/report/design/<报表id>?isAjax=1&dirId=undefined&isAnalysisEdit=true
    &isCase=false&locale=zh_CN&systenant=<租户>&listType=DIRREPORT&serviceCode=<服务码>
```

（服务码见页面 URL：报表是 `report-51` 这一类的值，语义模型是 `report-28`。）

关键片段：

| 片段 | 内容 |
|---|---|
| `"filters":[...]` | 每个筛选器的 `from`(数据集) / `code` / `label` / `iType` / `paramsBindOut` |
| `wideTableModels` | 报表**引入**了哪些数据集（含它们的 `from` = 真实模型 id） |
| `"scope":"PARAMS","items":[{…}]` | **参数声明**（paramId + code + 默认值）← 判断同名冲突就看这里 |

> 语义模型的定义接口**不在** `/semantic/design|query|detail` 这些短路径上（试过，404）。
> ✅ **2026-10-11 补正**：可用的是**完整路径**
> `GET /iuap-data-common/semantic/model/get/<模型ID>?isAjax=1&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC&serviceCode=report-28`
> —— 返回 `data.model`：`tables[0].sql` 是 SQL 正文、`params` 是参数声明；
> 同结构里 `data.obj.tables[0].sql` 也能取到。**读模型 SQL 不必再点界面了。**
> （语义模型页面 URL 里的 `serviceCode` 是 `report-28`，报表是 `report-51` 这一类。）

## 5. 一句话总结

> **"下拉空"和"报表 0 行"先分层；找一张能用的报表做参照；
> 抓请求看平台实际用了哪个模型、每个参数拿到什么值；
> 库上把参数换固定值实跑一次，就能把问题钉死在"参数"还是"SQL"上。**

本次最终钉死在**参数**：模型对、字段对、SQL 库上能跑出 2 行，唯独**租户参数被同名参数抢走了值**。
