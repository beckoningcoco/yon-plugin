> 实测：2026-10-10，金隅共享 `dev-fssc.bbmg.com.cn`，

## 1. 为什么要把固定值抽成参数

以本例 SQL 为例，写死的值有两类（每个 `union all` 分支各出现一次）：

```sql
... where e0.dr = 0 and e0.ytenant_id = 'jd4ofb7k'
      and e0.org_epm_systems_id = '2570581176914280457'
```

| 写死的值 | 后果 |
|---|---|
| `ytenant_id = 'jd4ofb7k'` | 换租户/换环境就废，且散落在多处 |
| `org_epm_systems_id = '2570581176914280457'` | 换组织体系就废 |

抽成参数后，同一个语义模型能在不同租户/体系/期间下复用；报表侧再用「参数绑定」把筛选器的值传进来。

## 2. 定义参数：入口与字段（实测）

1. 打开语义脚本编辑器抽屉（点表清单里的表名）
2. 点顶部「**参数**」按钮（`fieldid=execute_param`，在「执行」右边）
3. 弹出「**参数设置**」弹窗（`.setparam-modal`），工具条只有两个：**新增参数** / **删除**

| 列 | 说明 | 实测可选项 |
|---|---|---|
| 勾选 | 配合「删除」用 | — |
| 序号 | — | — |
| **参数名称** | SQL 里引用时用的编码 | 文本输入 |
| **值类型** | 参数的数据类型 | **字符 / 整型 / 浮点 / 日期 / 时间 / 日期时间** |
| **是否必填** | 复选框 | — |
| **默认值类型** | 默认值从哪来 | **常量 / 系统变量 / 权限标签 / 表达式** |
| **默认值** | 随上一列变化 | 常量 → 文本输入；系统变量 → **可搜索下拉** |
| 操作 | — | — |

- 「新增参数」是**行内新增**（表格里直接多出一行），不是二级弹窗；行填完点弹窗底部「确认」。
- 新行自带的列值是 **字符 + 常量 + 默认值留空** —— 一般**只需填「参数名称」**，其余列不用动。
- 弹窗底部：取消 / 确认。

> **输入框行为差异（实测，容易踩）**：**参数设置弹窗里的输入框认"原型 setter + `input`/`change` 事件"**
> —— 可以脚本批量填（一次连加好几个参数）；而**报表设计器里筛选器的「名称」框不认**合成事件，
> 必须真实键盘输入。同一个平台、两处行为相反，结论别混用（见 [[../报表设计器/01-筛选器与参数绑定]] §7）。

### 「默认值类型 = 系统变量」给的是什么

实测是**相对当前日期的期间变量**下拉，选项形如：

```text
当前年2026 / 当前月10 / 当前年月2026-10 / 上年同月2025-10 / 上期年月2026-09
当前季Q4 / 当前年季2026-Q4
本年一季度第一天2026-01-01 / 本年一季度最后一天2026-03-31 / …（共 12+ 项）
```

即取值随运行时间走，适合"默认看本期"这类报表。

## 3. 在 SQL 里引用参数：写法与硬规则

> 下面这些是 [[../报表SQL/07-经验-语义模型报表开发]] §1.1–1.3 的**实测结论**，
> 不是推测；照抄能省一次报错。

### 3.1 三类可替换的值，先分清楚再用

| 值的性质 | 用什么 | 在哪定义/取 | SQL 里怎么写 |
|---|---|---|---|
| 由**使用者在报表上选** | **自定义参数** | 抽屉「参数」→ 参数设置弹窗 | `${param('编码')}` |
| 由**运行日期决定** | **系统变量** | 右侧「系统变量」折叠面板，如 `currentYearMonth`、`lastIssueMonth`、`currentYearSeason` | `${var('编码')}` |
| 由**登录者身份决定** | **权限标签** | 右侧「权限标签」折叠面板，如 `orgId`、`orgCode`、`deptId`、`roleId`、`staffCode`、`productLine` | `${var('编码')}` |

编码就是右侧面板里显示的那个**英文名**。分不清就用错工具：
把"本期"做成自定义参数，每个用户都得自己选；把"用户选的组织"做成权限标签，就只能看自己那一份。

### 3.2 写法规则

| 项 | 写法 |
|---|---|
| 自定义参数 | **`'${param('参数名称')}'` —— 外层单引号要自己包**（实测见 §3.3） |
| 系统变量 / 权限标签 | `${var('编码')}`（07 文档实测见过 `${var('tenantId')}` 这种写法） |
| 日期参数 | **不要**用 `TO_DATE` / `STR_TO_DATE` / `CAST` 去包 |
| 空值兜底 | `<#if param('x')?? && param('x') != ''>` —— 判断要**双重**；只写 `??` 时用户传空串仍然会过滤 |
| FreeMarker 位置 | 标签内部（`<#if …>`）写 `param('x')`；**SQL 正文**写 `${param('x')}`。写错会报 `You can't use ${...} (an interpolation) here as you are already in FreeMarker-expression-mode.` |
| 租户 | 以**该模型参数列表里实际存在的编码**为准：见过 `${var('tenantId')}`，也见过 `${param('ytenantid')}`，不要照抄别的环境 |

### 3.3 ⚠️ 单引号：语义模型里必须自己包（2026-10-10 实测）

在金隅 `账户直联情况统计_总览` 上实测（参数：`ytenant_id`、`org_epm_systems_id`，值类型字符、默认值常量）：

| 写法 | 结果 |
|---|---|
| `e0.ytenant_id=${param('ytenant_id')}` | 点「执行」→「确定」后**立刻报**：`错误提示(012-501-030155) 执行失败`（链路ID `8f4bd05b33a59320`） |
| `e0.ytenant_id='${param('ytenant_id')}'` | **执行成功**；保存也成功（"保存语义模型成功"） |

**结论：语义模型的 SQL 脚本里，参数替换不自带引号，单引号要自己写。**

> ⚠️ 这一条与 [[../报表SQL/07-经验-语义模型报表开发]] §1.1 原先的记录**相反**（那里写"不加单引号，平台自带引号"）。
> 本次是同一环境、同一编辑器的实测，**以本次为准**；07 那条已就地加更正说明。
> 报表侧的参数（如 `zhhz_org_id`）是否真的不同，目前**没有证据**，别急着把两边都改掉——遇到就以实测为准。

### 3.4 报错怎么抓（这次差点漏掉）

- 「执行」失败的提示是**瞬时 toast**，几秒后自己消失。用 `browser_*` 观察时**不能等结果再读**——
  必须点完「确定」后**高频轮询**（实测每 250ms 抓一次、抓 8~10 秒）才能捕到
  `错误提示(012-501-030155) … 执行失败 链路ID … 错误详情`。
- 报错里的「错误详情」可展开看后端细节；只有 `执行失败` 字样是不够定位的。

### 3.5 多选参数：逗号分隔 → IN 列表（实测）

平台的参数是**字符串**。报表侧多选（如组织树多选）传过来是 `id1,id2,id3`，
在 FreeMarker 里用 `?replace` 展开成 SQL 的 IN 列表：

```sql
<#if param('zlqk_orgid')?? && param('zlqk_orgid')!=''>
  and e.id in ('${param('zlqk_orgid')?replace(",", "','")}')
</#if>
```

- **外层单引号还是要有**（见 §3.3）；里面的 `?replace(",", "','")` 把逗号换成 `','`
- 渲染结果：`id1,id2` → `'id1','id2'` → `in ('id1','id2')`
- 参数为空时 `<#if>` 不成立 → **退化成不过滤**（显示全部）
- 判断用 `?? && !=''` 双重，比只写 `!=''` 稳（见 §3.2）

**实测（2026-10-10，语义模型「账户直联情况统计_总览」）：**

| 情形 | 结果 |
|---|---|
| 参数留空 | 执行成功；库上全量 **629 行**（不过滤） |
| `zlqk_orgid = 2570584535578705924,2570584535578705925` | 执行成功；库上验证**正好 2 行**（冀东水泥集团、混凝土集团） |

**过滤该加在哪一层**：像这种"一行一个组织、行上的数字已经是含下级的上卷汇总值"的报表，
过滤**只加在最外层 `where`**（作用在行上），**不要去动那个上卷子查询**——
一动就会变成"只统计所选组织本级"，与明细行口径对不上（这正是 [[../报表SQL/05-经验-组织树与子级数量统计]]
里记的那个坑：明细 76 / 合计 3）。

**参数值取哪个 ID**：取决于报表筛选器的**值字段**。
本例树形参照的值字段是模型的 `id`（= `org_epm_orginization_ext.id`，`2570…` 成员 ID），
所以过滤落在 `e.id` 上；同一体系里 `o.org_source_id` 是另一套（`2531…` 档案 ID），
两个空间**不重叠**，写错就是"一行都查不出来、还不报错"。

### 3.6 「一行汇总」型模型（合计）怎么写：过滤要作用在**组织集合**上

合计模型跟明细不是一回事：明细是**一行一个组织**，过滤作用在**行**上；
合计是**一行汇总**（本例 SQL 第一列就是 `'全部单位合计'`），没有行可过滤，
所以要过滤**它统计的那个组织集合**（本例是子查询 `m`）。

实测写法（2026-10-10，语义模型「账户直联情况统计_合计」）：

```sql
-- m 子查询：把组织集合限制为「所选组织 + 其全部下级」
from ( select o2.id as org_pk, o2.org_source_id as src_id
         from iuap_apdoc_basedoc.org_epm_orginization_ext e
         join iuap_apdoc_basedoc.org_epm_organizations o2 on o2.id = e.org_id
        where e.dr=0 and e.ytenant_id='…' and e.org_epm_systems_id='…' and o2.dr=0
        <#if param('zlqk_orgid_t')?? && param('zlqk_orgid_t')!=''>
        and e.id in (  -- 子树展开：8 段 union all，e0→e7 逐层往下
        )
        </#if> ) m
```

- **合计必须用「含下级」口径**，否则跟明细对不上：明细每行是"本单位＋全部下级"的上卷值，
  合计若只过滤本级，就变成"只统计所选组织自己"，两边数字天然不一致
  （[[../报表SQL/05-经验-组织树与子级数量统计]] 里记的明细 76 / 合计 3 就是这个坑）
- 子树展开与明细侧同一套路：**8 段 `union all`**（e0…e7 逐层向下），每段条件都要带租户与组织体系
- 改完合计模型的 SQL，**报表侧还要给合计单独绑一条参数**（参数名不同：本例 `zlqk_orgid_t`），
  否则报表上的合计行不会动（见 [[../报表设计器/01-筛选器与参数绑定]] §5.3）

**实测结果**：报表同时选 `1003 冀东集团,1005 地产集团` 时，
明细两行 2/1/1/0.50/1/0 与 1/1/0/1.00/0/0，**合计 3/2/1/0.67/1/0 = 两行逐项之和** ✅。

## 4. 把固定值换成参数：推荐步骤

1. 先在「参数设置」里**定义好参数**（名称、值类型、默认值），点「确认」
2. 回到 SQL，把这些字面量替换掉：

   ```sql
   -- 改前
   and e0.ytenant_id = 'jd4ofb7k'
   -- 改后（连同引号一起换掉，不要写成 '${param(...)}'）
   and e0.ytenant_id = ${param('ytenantid')}
   ```

   - 需要"没传值就不过滤"时，用 `<#if>` 包住**整个条件**，而不是只包值
3. 点「**执行**」验证（真的会跑 SQL，只读）
4. 「确认并返回」→ 主界面「**保存**」——**不保存不生效**
5. 报表侧再到「数据设置 → 参数绑定」把筛选器的值绑到这个参数上
   （见 [[../报表设计器/01-筛选器与参数绑定]] §5）

## 5. 坑

1. **先定义、后引用**：SQL 里写了 `${param('x')}` 但参数列表里没有 `x`，替换会失败或留空。
2. **写死的值往往不止一处**：本例 `ytenant_id` / `org_epm_systems_id` 在每个 `union all` 分支各一次，
   只替换一处就会让口径不一致（属 07 文档说的"口径覆盖不全"类**静默错误**——不报错，数字却不对）。
3. **改完不保存**：抽屉里只是编辑态；主界面「保存」之后才落库。
4. **别把报表侧的参数绑定当成这里的参数定义**：这里定义参数，报表侧只是**传值**。两处编码必须一致。
5. **模型的默认值 ≠ 报表取数会带上的值**：参数在「参数设置」里填了默认值，报表取数时仍可能拿到空
   （筛选器没选、绑定被刷空等）。凡"不选也必须出数"的关联/过滤，要在 SQL 里 `<#if>/<#else>` 兜底 —— 见 §6。
6. **日期区间要"左闭右闭"时，上界别用 `<=`**：时间列是 DATETIME，
   `<= to_date('2026-06-30','YYYY-MM-DD')` 等于 `<= 2026-06-30 00:00:00`，
   会把 6-30 当天带时间的记录**全部漏掉**。正确写法是"次日零点之前"：

   ```sql
   <#if param('开户日期起')?? && param('开户日期起')!=''>
     and a.accountOpenDate >= to_date('${param('开户日期起')}', 'YYYY-MM-DD')
   </#if>
   <#if param('开户日期止')?? && param('开户日期止')!=''>
     and a.accountOpenDate < to_date('${param('开户日期止')}', 'YYYY-MM-DD') + 1
   </#if>
   ```

## 6. 运行时的传值链路：**模型参数的默认值，报表取数时并不保证带上**

> 这一节回答原「待补」里的问题：参数被报表引用后，谁能覆盖默认值。

**实测（2026-10-10，两个模型都栽在它上面）**：

| 场景 | 参数设置里的默认值 | 报表取数时实际拿到的 | 后果 |
|---|---|---|---|
| 账户明细表「账户用途」 | `自定义档案账户用途id` = 常量 `2578799562497982468` | **空** | `cd8.custdocdefid = ''` → 关联不上 → **整列空**（同一 SQL 把值写死在库里跑，明明能查出 26 户） |
| 直联表组织过滤 | `org_epm_systems_id` = 常量 `2570581176914280457` | `$$$`（平台的"未选值"标记） | 条件恒不成立 → 查不出行 |

**结论**：**"参数在模型里有默认值" ≠ "报表取数会把它带上"**。
报表取数读的是**报表侧的参数值**；筛选器没选、或参数绑定把它刷空，模型里那个默认值就形同不存在。

**所以：凡"这一列必须有值"的关联/过滤，别指望参数，直接在 SQL 里兜底**：

```sql
-- 关联键兜底（本例：账户用途）
left join iuap_apdoc_basedoc.bd_cust_doc cd8
       on cd8.id = c.vcol8
      and cd8.custdocdefid = <#if param('自定义档案账户用途id')?? && param('自定义档案账户用途id')!=''>'${param('自定义档案账户用途id')}'<#else>'2578799562497982468'</#if>
```

- `<#if>` 的**标签内部**写 `param('x')`（不带 `${}`）；`<#else>` 里写字面量
- 判断标准：**不选参数时这一列还必须出数** → 必须兜底；"不选就不出数据"可接受 → 只包 `<#if>` 即可
- "同名参数被**别的数据集**抢走值"是**另一类**问题，见 [[../报表设计器/02-取不到数怎么排查]] §3.1

**这类问题的排查入口**：报表里某列全空、或数字明显不对时，走 [[../报表设计器/02-取不到数怎么排查]] 的分层排查 ——
**先在库里把参数写死跑一遍**：能出数就说明是**传值**问题，不是 SQL 问题。

- 「默认值类型 = 权限标签 / 表达式」分别要填什么
