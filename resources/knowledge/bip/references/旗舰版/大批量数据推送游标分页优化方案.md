# 大批量数据推送游标分页优化方案

## 一、背景

### 业务场景

用友 BIP 存货核算系统，将出入库流水和结存数据推送到外部系统中间表（`sdic_materials_*`），供下游消费。由 YMS 调度任务定时触发。

### 接口清单

| 接口 | 功能 | 目标表 |
|------|------|--------|
| `/inboundPush` | 入库数据推送 | `sdic_materials_in_storage_detail` |
| `/outboundPush` | 出库数据推送 | `sdic_materials_out_storage_detail` |
| `/balancePush` | 实时结存推送 | `sdic_materials_balance` |
| `/balancePushMonthly` | 月度结存推送 | `sdic_materials_month_balance` |

### 数据规模

| 指标 | 规模 |
|------|------|
| 单次推送数据量 | 30 万条 |
| 源表 JOIN 数量 | 6~9 表 |
| 分页大小 | 1000 条/页 |
| 数据库类型 | MySQL |

### 初始性能

- **入库推送**：30 万条耗时 **60+ 分钟**
- **出库推送**：同上

## 二、问题诊断

### 2.1 逐页 SQL 链路梳理

每页（1000 条）的执行链路：

```
Page Loop (300 页):
├─ ① 主查询 queryInboundData(offset)          → 1 SQL ★ 核心瓶颈
├─ ② checkNeedUpdateId(upsertRows, target)      → 1 SQL
├─ ③ batchDeleteInbound(dr=1)                   → N SQL
├─ ④ loadOtherFieldsForinbound:
│   ├─ queryChildRecords(purinrecords)           → 1 SQL
│   ├─ queryChildRecords(othinrecords)            → 1 SQL
│   ├─ queryFeatures(PURIN body+head)             → 2 平台API
│   ├─ queryFeatures(OTHIN body+head)             → 2 平台API
│   └─ translateData(7个特征字典)                 → 7 SQL/API
├─ ⑤ ensureIdsLoaded(10个字典懒加载)             → 10 SQL(冷)→0(热)
└─ ⑥ batchUpsertInbound                          → 10 SQL
```

**每页总计 ~30~45 次 SQL/API 调用，300 页 ≈ 9,000~13,500 次。**

### 2.2 核心瓶颈 #1：OFFSET 分页（占总耗时 ~85%）

```sql
-- 当前写法
SELECT ... (9表 JOIN)
FROM fieia.ia_ledger_b a
INNER JOIN fieia.ia_ledger_b_x_account b ...
LEFT JOIN ...
WHERE org.code IN (?) AND a.pubts >= ? AND a.pubts < ? ...
ORDER BY a.pubts
LIMIT 1000 OFFSET 299000   -- ← 问题在这里
```

MySQL 的 OFFSET 行为：**先扫描 OFFSET+LIMIT 行，再丢弃前 OFFSET 行**：

| 页码 | OFFSET | MySQL 扫描行数 |
|------|--------|---------------|
| 1 | 0 | ~1,000 |
| 100 | 99,000 | ~100,000 |
| 300 | 299,000 | ~300,000 |

**总扫描行数 = Σ(1000×page) ≈ 4,515 万行**（30万数据需要扫描4500万行）

### 2.3 核心瓶颈 #2：`pubts` 列缺少索引

```sql
-- 当前索引情况
SHOW INDEX FROM fieia.ia_ledger_b;

-- 关键发现：没有任何索引包含 pubts 列！
-- 现有索引：PRIMARY(id), i_ia_ledgers_tenant(ytenant_id), ...
```

`ytenant_id` 单列索引 Cardinality = 0（所有行同租户），过滤效果为零。MySQL 只能全表扫描 + filesort。

### 2.4 核心瓶颈 #3：每页重复查询

| 问题 | 影响 |
|------|------|
| `checkNeedUpdateId` 每页查一次目标表 | 300 次独立 SQL |
| `queryChildRecords` 每页查 2 次子表 | 600 次独立 SQL |
| `countInboundData` 预查总数 | 1 次全表扫描 |

## 三、优化方案

### 3.1 建索引（基础前提）

```sql
-- 覆盖 WHERE + ORDER BY，消除 filesort
ALTER TABLE fieia.ia_ledger_b 
  ADD INDEX idx_ytenant_pubts (ytenant_id, pubts, id);
```

**列顺序选择**：
- `ytenant_id` 第一：等值过滤，最左前缀
- `pubts` 第二：范围查询 AND 排序，索引直接有序
- `id` 第三：游标分页 tie-breaker（同秒数据不丢）

### 3.2 游标分页替代 OFFSET（最大收益）

**原理**：用上一页最后一条的 `(pubts, id)` 作为下一页起点，MySQL 每次只需扫描 1000 行。

**SQL 模板**：

```sql
-- 首页
SELECT ... FROM ... 
WHERE org.code IN ({org_in})
  AND a.pubts >= ? AND a.pubts < ?
  AND ...
ORDER BY a.pubts, a.id
LIMIT ?

-- 后续页（游标分页）
SELECT ... FROM ...
WHERE org.code IN ({org_in})
  AND (a.pubts > ? OR (a.pubts = ? AND a.id > ?))  -- ← 游标条件
  AND a.pubts < ?
  AND ...
ORDER BY a.pubts, a.id
LIMIT ?
```

**Java 循环改造**：

```java
// 改前：for + OFFSET
for (int page = 1; page <= totalPages; page++) {
    int offset = (page - 1) * pageSize;
    List<Map> rows = dao.queryInboundData(orgCodes, start, end, offset, pageSize);
    // ...
}

// 改后：while + 游标
List<Map> rows = dao.queryInboundDataCursorFirst(orgCodes, start, end, pageSize);
while (!rows.isEmpty()) {
    // 处理本页...
    
    // 取最后一条作为游标查下一页
    Map lastRow = rows.get(rows.size() - 1);
    Timestamp lastPubts = (Timestamp) lastRow.get("pubts");
    String lastId = lastRow.get("rkmx_id").toString();
    rows = dao.queryInboundDataCursorNext(orgCodes, lastPubts, lastId, end, pageSize);
}
```

**参数映射（后续页）**：

```java
SQLParameter param = new SQLParameter();
param.addParam(orgCode);      // org.code IN
param.addParam(lastPubts);    // a.pubts > ?
param.addParam(lastPubts);    // a.pubts = ? (OR clause)
param.addParam(lastId);       // a.id > ?
param.addParam(endPubts);     // a.pubts < ?
param.addParam(tenantId);     // a.ytenant_id
param.addParam(tenantId);     // b.ytenant_id
param.addParam(tenantId);     // bt.ytenant_id
param.addParam(limit);
```

### 3.3 合并 checkNeedUpdateId 到主查询

在主 SQL 中 LEFT JOIN 目标表，一次查出是否已存在：

```sql
-- SELECT 新增标记列
CASE WHEN tgt.rkmx_id IS NOT NULL THEN 1 ELSE 0 END AS _exists

-- FROM 新增 LEFT JOIN
LEFT JOIN c_scm_gterp_service_db.sdic_materials_in_storage_detail tgt 
  ON b.id = tgt.rkmx_id
```

```java
// 改前：每页单独查目标表
List<String> updateId = dao.checkNeedUpdateId(upsertRows, targetTable);

// 改后：直接从 row 读取
boolean exists = "1".equals(row.get("_exists").toString());
if (dr != 1 && exists) {
    deleteRkmxIds.add(rkmxId);  // 已存在 → 先删后插
}
```

### 3.4 子表字段并入主查询

子表字段（`sub_qty`、`inv_exch_rate` 等）通过 LEFT JOIN 带入主查询：

```sql
-- 新增 LEFT JOIN（按单据类型条件连接，避免 A08 行匹配 A15 子表）
LEFT JOIN ustock.st_purinrecords pr ON a.src_bill_row_id = pr.id AND bt.code = 'A15'
LEFT JOIN ustock.st_othinrecords oir ON a.src_bill_row_id = oir.id AND bt.code = 'A08'

-- SELECT 新增（COALESCE 跨表合并）
COALESCE(pr.subQty, oir.subQty, 0) AS sub_qty,
COALESCE(pr.invExchRate, oir.invExchRate, 0) AS inv_exch_rate,
COALESCE(pr.dInvalidDate, oir.dInvalidDate) AS d_invalid_date,
pr.tradeRouteLineno AS trade_route_line_no,
pr.tradeRouteID AS trade_route_id,
pr.applyDept AS apply_dept_code,
pr.applyDept AS apply_dept,
pr.applyOperator AS apply_operator_code,
pr.applyOperator AS apply_operator
```

对应去掉 Service 中的 `queryChildRecords` 和 `enrichFromChildRecords` 调用。

### 3.5 去掉 COUNT 预查询

游标分页不依赖总数，去掉 `countInboundData` 全表扫描。`totalRows` 改为循环结束后实际处理数累加。

## 四、实施过程中的踩坑

### 4.1 子表列名是驼峰不是下划线

数据库实际列名是驼峰（如 `subQty`、`invExchRate`），不是 Java 代码中 Map key 使用的下划线（`sub_qty`、`inv_exch_rate`）。

```sql
-- ❌ 错误
COALESCE(pr.sub_qty, oir.sub_qty, 0) AS sub_qty

-- ✅ 正确（先 SHOW COLUMNS 确认实际列名）
COALESCE(pr.subQty, oir.subQty, 0) AS sub_qty
```

**教训**：LEFT JOIN 前先用 `SHOW COLUMNS FROM table` 确认列名，不要根据 Java Map key 猜测。

### 4.2 不同子表列不完全一致

`st_purinrecords` 和 `st_othinrecords` 并非列对齐：
- `tradeRouteLineno`、`tradeRouteID`、`applyDept`、`applyOperator` **仅存在于** `st_purinrecords`
- COALESCE 跨表引用不存在的列会直接报 `SQLSyntaxErrorException: Unknown column`

```sql
-- ❌ 错误：oir.tradeRouteLineno 在 st_othinrecords 中不存在
COALESCE(pr.tradeRouteLineno, oir.tradeRouteLineno) AS trade_route_line_no

-- ✅ 正确：仅从存在的表中取值，A08 行自然为 NULL
pr.tradeRouteLineno AS trade_route_line_no
```

**教训**：实施子表 LEFT JOIN 前，**逐表 SHOW COLUMNS**，画出列对齐矩阵，确认哪些列共享、哪些表独有。

### 4.3 游标 SQL 参数计数要精确

游标分页的 NEXT SQL 比 FIRST SQL 多 1 个参数（`lastPubts` 用了两次），容易多传或少传。

**检查方法**：数 SQL 中的 `?` 个数，确保与 `param.addParam()` 次数一致。

## 六、通用模板

### 6.1 适用条件

- 数据量 > 1 万条的分页批处理
- SQL 使用了 `ORDER BY ... LIMIT ? OFFSET ?` 模式
- WHERE 条件中有等值过滤列 + 范围排序列
- 排序列有递增性质（时间戳/自增ID）

### 6.2 游标分页 SQL 模板

```sql
-- 首页
SELECT ..., 排序列1, 排序列2
FROM driving_table a
JOIN ...
WHERE 等值条件 AND 排序列1 >= start AND 排序列1 < end AND ...
ORDER BY 排序列1, 排序列2
LIMIT pageSize

-- 后续页
SELECT ..., 排序列1, 排序列2
FROM driving_table a
JOIN ...
WHERE 等值条件 
  AND (排序列1 > lastVal1 OR (排序列1 = lastVal1 AND 排序列2 > lastVal2))
  AND 排序列1 < end AND ...
ORDER BY 排序列1, 排序列2
LIMIT pageSize
```

### 6.3 索引模板

```sql
-- 覆盖：等值过滤 + 排序 + tie-breaker
ALTER TABLE driving_table 
  ADD INDEX idx_opt (等值列, 排序列, 主键列);
```

### 6.4 优化检查清单

| # | 检查项 | 工具 |
|---|--------|------|
| 1 | 主查询的 WHERE/ORDER BY 列上有没有索引？ | `SHOW INDEX FROM table` |
| 2 | 是否用了 OFFSET 分页？ | 搜索 `LIMIT ? OFFSET ?` |
| 3 | 每页有没有重复查询（查目标表、查子表）？ | 检查循环体内的 SQL 调用 |
| 4 | 是否有不必要的 COUNT 预查询？ | 游标分页不需要总数 |
| 5 | LEFT JOIN 新表前是否确认了列名？ | `SHOW COLUMNS FROM table` |
| 6 | 多表 COALESCE 前是否确认了所有列都存在？ | 逐表检查列清单 |
| 7 | SQL 参数个数是否与 `?` 数量一致？ | 人工计数 or 单元测试 |

## 七、附：结存推送优化（聚合查询 + 合并循环）

### 7.1 场景特征

结存类接口与出入库不同：**不需要分页**，数据是按维度（org + warehouse + material）聚合的 GROUP BY 查询。但存在 **逐月/逐组织循环查询** 的 N+1 问题。

### 7.2 问题模式

```java
// ❌ 反模式：循环体内逐月查数据库
for (String periodCode : validPeriods) {
    List<Map> monthRows = dao.querySettledBalance(orgId, periodCode); // N 次 SQL
    // accumulate + upsert...
}
```

假设 18 个月，就是 18 次 SQL，每次全表扫描（若缺索引）13 万行 → 共扫描 234 万行。

### 7.3 优化方案

**索引 + 合并查询 + 内存分组**：

```sql
-- 1. 建索引（覆盖 WHERE 全部列）
ALTER TABLE fieia.ia_period_balance_stock 
  ADD INDEX idx_ytenant_stockorg_period (ytenant_id, stock_org_id, period_code, dr);

-- 2. 一次查出所有月份数据
SELECT ..., period_code
FROM fieia.ia_period_balance_stock
WHERE stock_org_id IN (?) 
  AND period_code IN (?, ?, ...)  -- 所有月份
  AND dr = 0 AND ytenant_id = ?
ORDER BY period_code ASC;
```

```java
// 3. Java 内存按 period_code 分组，再逐月累加
List<Map> allRows = dao.querySettledBalanceMulti(orgId, validPeriods); // 1 次 SQL
Map<String, List<Map>> byPeriod = groupByPeriod(allRows);
for (String periodCode : validPeriods) {
    List<Map> monthRows = byPeriod.getOrDefault(periodCode, emptyList());
    // accumulate + upsert...（逻辑不变）
}
```

### 7.4 效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| monthly SQL 数 | N 次 | **1 次** |
| 扫描行数 | N × 13万 | **1 × 13万（索引）** |
| 预计耗时 | 30~60 秒 | **3~5 秒** |
