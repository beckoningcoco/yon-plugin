# 用脚本改一段语义模型 SQL 并保存

> 实测：2026-10-10，金隅共享 `dev-fssc.bbmg.com.cn`，语义模型「账户直联情况统计_总览 ZHZL_TJ」，
> 实做内容：把 SQL 里 **39 处** `'jd4ofb7k'` 与 **37 处** `'2570581176914280457'` 换成两个自定义参数，
> 执行通过并保存成功。
> 关联：[[00-界面总览]]、[[01-参数与固定值替换]]

---

## 0. 什么时候需要这套

要改的地方**多到手工点不现实**（本次 76 处，散在每个 `union all` 分支里），
或者要**机械地重复同一个替换**。手工点必然漏，漏了还不报错（口径不一致的静默错误）。

---

## 1. 进抽屉

抽屉是全屏的，**不在 DOM 里就说明没打开**（判断：`document.querySelector('.materialize-drawer-sql')`）。

**入口 ＝「悬停表格行 → 点『编辑』」**（2026-10-10 补上，原先这里是"未找到入口"）：

1. 鼠标移到主界面表清单的那一行上 —— 行尾会出现 **「编辑」/「删除」** 两个操作
2. 点「编辑」即打开语义脚本编辑器抽屉

> ⚠️ 表名单元格本身是**纯文本**（`<td>t_sk_zlzh_zl</td>`，没有 `a`/`span`/`button`），
> 直接对它发合成 `click` / `dblclick` **点不开**。正确做法，按这个顺序试：
> ① **`browser_hover`** 到那一行（指针停住，hover 态成立）→ 用 `browser_eval` 看「编辑」进没进 DOM → 再用 `browser_eval` 点它；
> ② 或 **`browser_click` 配 `hoverMs`**（例如 300）—— 移动指针后、按下之前先等一会儿，给 hover 渲染留时间；
> ③ 还不行再用 `mode="react"`（见 [[../报表设计器/08-操作手法与判据纪律]] §3）。
> **只发合成 DOM 事件、又不移动指针 → hover 态不成立 → 按钮根本不存在。**

## 2. 读 SQL：拿 CodeMirror 的 EditorView

```js
const view = document.querySelector('.cm-content').cmView.view;
const sql  = view.state.doc.toString();     // ← 全量读，一律用它
```

**别用 `innerText` 读 SQL —— 它会漏内容。** 同一份 SQL 实测对比：

| 读法 | 长度 | 搜同一个值得到的处数 |
|---|---|---|
| `.cm-content.innerText` | 7834 | 37（`ytenant_id`）/ 35（`org_epm_systems_id`） |
| `view.state.doc.toString()` | 9472 | **39 / 37**（真实值） |

计数和替换**一律以 `doc.toString()` 为准**，否则会"以为只剩几处没改"。

---

## 3. 改 SQL：整段 dispatch

```js
const before = view.state.doc.toString();
const after  = before
  .split("'老值'").join("'${param('参数名')}'");     // 想做几个替换就串几个
view.dispatch({ changes: { from: 0, to: before.length, insert: after } });
```

- 一次性替换全文，76 处秒改，不会漏。
- **不要**给 `.cm-content` 赋 `innerText`（CodeMirror 不认），也**不要**用 `execCommand`。
- 改完立刻再读一次 `doc` 校验：残留处数、替换后处数、以及有没有 `''${...}''` 这种重复引号。

---

## 4. 执行验证（这一步决定成败）

1. 点顶栏「**执行**」：`[...document.querySelectorAll('[fieldid="execute_button"]')].pop()`
2. 弹出「**执行数据模型**」对话框：自动列出这段 SQL 用到的参数，**并带上各自的默认值**
3. 点这个弹窗自己的确定按钮：`document.querySelector('.wui-modal-ok-button')`
   > ⚠️ 页面底部还有「取消 / 确认并返回 / **确定**」三个按钮，**别点到它们**（那是保存类操作）。
4. **报错是瞬时 toast，必须边点边抓** —— 点完「确定」后每 **250ms** 轮询 DOM 抓 message，连抓 8~10 秒：

   | 结果 | 抓到的文本 |
   |---|---|
   | 失败 | `错误提示(012-501-030155) 执行失败 链路ID：… 错误详情` |
   | 成功 | `执行成功` |

   **踩过的坑**：点完「确定」等了 11 秒才去读 DOM —— toast 早消失了，于是把"没读到"当成"没报错"，
   差点让一个失败的改动进入保存。**看报错不能等。**

---

## 5. 保存

1. 抽屉底部「**确认并返回**」→ 回到主界面
2. 主界面「**保存**」
3. 如果模型**已被对象引用**，会弹：

   ```text
   当前语义模型 <名> 已被对象引用，是否修改？   [取消] [修改]
   ```

   注意按钮是 **取消 / 修改**（**没有**"确定"），要点「**修改**」。
4. 成功提示：`保存语义模型成功`

---

## 6. 参数化改写的安全顺序（本次验证有效）

1. **先定义参数**，再动 SQL —— 反过来写 SQL 会因"参数不存在"而执行失败。
   - 参数默认值类型选**常量**，默认值**填原字面量**（如 `jd4ofb7k`）
2. 这样「执行」时按默认值渲染，**行为与改前完全一致** —— 于是"执行成功"就能证明
   参数替换被平台正确渲染了，而不只是"SQL 语法没错"。
3. 替换时**连引号一起处理**（写法与坑见 [[01-参数与固定值替换]] §3.3）。
4. **先执行、后保存**：执行通过再保存，避免把跑不通的脚本落库。

---

## 7. 参数设置弹窗的读写细节（实测）

| 项 | 事实 |
|---|---|
| 「新增参数」 | **行内新增**（表格里直接多一行），不是二级弹窗 |
| 连续点两次 | 实测**只加出 1 行** —— 点一次、填一次更稳 |
| 下拉（值类型 / 默认值类型）的选中值 | 在 `.wui-select-selection-item` 的 **`title`** 属性上；`innerText` 读出来是空字符串 |
| 文本框设值 | 用 `HTMLInputElement.prototype` 的 value setter + `input`/`change` 事件 |
| 弹窗按钮 | 底部「取消 / 确认」，确认后才落到模型上（真正落库还要主界面「保存」） |
