## 1. 什么时候读我

- 客开要**在销售订单提交/收回前后插手**，或者要判断"提交到底是走审批流还是直接保存"。
- 排查「提交后单据状态没变」「提交报错说找不到业务接口实现」「批量提交时部分单据走流程、部分没走」。
- 要理解**提交与保存在代码层是同一个引擎的两个入口**，以及**提交被翻译成 `SAVE` 或 `APPROVE` 的分叉点**。

## 4. 一个直觉错误：提交的 `actionName` 初始值是 **"SAVE"**

`SaleOrderBusiProcessWebServiceImpl#commit:210-230` 原文（只留关键行）：

```java
public SCMScriptResultDTO commit(SaleOrderVO[] vos) throws BusinessException {
    CloudPFlowContext context = new CloudPFlowContext();
    context.setBillType(SOBillType.Order.getCode());   // "30"
    context.setBillVos(vos);
    context.setActionName("SAVE");                     // ★★ 提交，但动作名是 SAVE
    SCMScriptResultDTO result = ((IBatchRunScriptService)NCLocator.lookup(IBatchRunScriptService.class))
                                    .runBacth(context, SaleOrderVO.class);
    if (ValueCheckUtil.isNullORZeroLength(result.getSucessVOs())) return result;
    String[] csaleorderids = VOEntityUtil.getPksFromAggVO(result.getSucessVOs());
    vos = ((ISaleOrderQueryAPI)NCLocator.lookup(ISaleOrderQueryAPI.class)).queryVOByIDs(csaleorderids);  // 回读
    result.setSucessVOs(vos);
    return result;
}
```
`uncommit:232-252` **逐字同构，只把 `"SAVE"` 换成 `"UNSAVE"`**。

**为什么"提交"用 `SAVE`**：NCC 里"提交"不是一个独立的动作语义，而**由"要不要走审批流"决定其真实动作**——
这个决定发生在下一层（第 5 节）。所以**在入口与服务层看到的 `SAVE` 不是"保存"，是"保存或审批"的待定值**。
排查"我点的是提交，日志里怎么是 SAVE"时，答案在这里。

> 对比：**收回**是 `"UNSAVE"`，语义直接，没有歧义。

**`actionnames` 数组**（:51 / :56，两处字面量相同）：

//                                    [0]      [1]       [2]      [3]

**这张表就是"提交"的真实语义**：

| 调用的方法 | 传入 actionName | 有没有审批流 | 最终 actionName | 实际行为 |
| --- | --- | --- | --- | --- |
| `commit` | `"SAVE"` | **没有**（`!hasApproveflowDef && !hasApproveflowExcute`） | **`"APPROVE"`** | 提交 = 直接审批通过 |
| `commit` | `"SAVE"` | **有** | `"SAVE"` | 提交 = 存下并送审 |
| `uncommit` | `"UNSAVE"` | 流程没在执行（`!hasApproveflowExcute`） | **`"UNAPPROVE"`** | 收回 = 撤销审批态 |
| `uncommit` | `"UNSAVE"` | 流程在执行 | `"UNSAVE"` | 收回 = 撤回送审 |

**两个 `hasFlow` 判定不是一件事**：

| 方法 | 实现 | 查什么 | 签名要点 |
| --- | --- | --- | --- |
| `hasApproveflowDef:253` | `IWorkflowDefine#hasValidProcessDef(groupId, trantype, pkorg, billMaker, emendEnum, WorkflowTypeEnum.Approveflow)` | **有没有"流程定义"**（配置层面） | 用 `fbi.getPkorg()` / `fbi.getBillMaker()` / `fbi.getEmendEnum()` |
| `hasApproveflowExcute:259` | `IPFWorkflowQry#isApproveFlowStartup2(fbi.getBillId(), context.getBillType())` | **该单据的流程有没有"正在执行"**（实例层面） | 用 `fbi.getBillId()` |

> 保存路径在 `NCCloudScriptPFlowServiceImpl#procFlow:92-99` 里用的是**第三个**判定
> `PfUtilTools.isHasStartFlow(trantype, aggvo, pk_group, WorkflowTypeEnum.Approveflow/Workflow)`。
> **三处判定、两套接口，别以为是一回事**——排查"明明配了流程却没走"要分清是哪个判定没过。

另外 `IFlowBizItf` 是**按元数据拿实现**（`PfMetadataTools.getBizItfImpl`），拿不到直接抛错：
> `4001004_0 / 04001004-0086`（"找不到业务接口实现"）——报这个错不是流程问题，是**该单据的 `IFlowBizItf` 实现没注册**。

## 7. 入口基类：`AbstractGridAction`（列表动作的通用模板）

`SaleOrderCommitAction extends AbstractGridAction<SaleOrderVO>`（`nccloud.web.so.pub.action.AbstractGridAction`，111 行）：

```java
public abstract class AbstractGridAction<E extends AbstractBill> implements ICommonAction {
    public Object doAction(IRequest request) { ... }          // :29 模板方法
    protected void checkVO(E[] vos, int len) { ... }         // :46
    protected String getPermissioncode() { return null; }    // :52 子类覆写
    protected String getActioncode()     { return null; }    // :56
    protected String getBillCodeField()  { return null; }    // :60
    protected void checkPermission(IBill[] bills) {          // :64
        DataPermissionUtil.checkPermission(bills, getPermissioncode(), getActioncode(), getBillCodeField());
    }
    protected abstract E[] queryVos(String[] var1);          // :104 子类实现
    protected abstract Object action(E[] var1);              // :106 子类实现
    protected String getBtnCode() { ... }                    // :108
}
```
**模板方法把"列表动作"固定成三步**：取单据（`queryVos`）→ 权限（`checkPermission`）→ 干活（`action`）。
`SaleOrderCommitAction` 只实现了后两个抽象方法和三个权限元数据。

> **这是"列表动作"与"卡片动作"的分界**：卡片动作（如保存）`implements ICommonAction` 自己写 `doAction`；
> 列表动作继承 `AbstractGridAction`，**权限检查是白送的**。
> ⚠️ `AbstractGridAction` 有 **7 个同名类**（`bc`/`credit`/`ct`/`dm`/`price`/`scmpub`/`so` 各一个），
> 全都叫 `nccloud.web.*.pub.action.AbstractGridAction`——**必须按 jar / 包名分辨**（与 `IRule`、`IBeforeRule` 同一个坑）。
