# NCC 集团报表数据中心取数（epm / datacenter）

> 适用：NCC（NC Cloud）「集团报表报送管理 → 数据中心 → 报表数据查询」这条链路的取数，
> 以及任何要把报表网格转成结构化数据的场景。
> 实测版本：**NCC 1909**。结论来自反编译 + 真机样本验证。

## 一、结论先行

**不要把 `queryDataCenter` 返回的 JSON 当数据格式去解析**——它是**前端网格（Handsontable）的序列化快照**，
服务于渲染，不是数据交换格式。正确做法是用**平台的报表对象模型 `CellsModel`**。

```java
// 取数：得到 CellsModel（而不是 JSONObject）
DataCenter dataCenter = new DataCenter(pkTask, pkSheet, null, paramMap, dataType);
CellsModel model = dataCenter.getCellsModel();     // pageInfo 传 null 是允许的
```

> 注意 `getCellsModel()` 与 `getJsonModel()` 对 `pageInfo` 的要求不同：
> 后者为 null 会抛业务异常，前者不要求。

## 二、那份 JSON 的结构，以及四个坑

```json
{
  "RowHeader": {"44": 22, "1": 0, ...},      // 坑1：这是行高像素，不是行标题！0=隐藏行
  "ColHeader": {"11": 135, "0": 81, ...},     // 坑1：这是列宽像素，不是列标题！
  "Base": {"rowNum": 58, "colNum": 15, "width": 1775, "height": 1122},
  "TableSetting": {"canEdit":"true","isSubmit":"true",
                   "freezeInfo":{"pk_task":"...","pk_sheet":"..."}},   // 唯一能反推"哪张表"的地方
  "DynamicModel": {
    "cells": [[{"r":12,"c":3,"v":"199698.2","tv":"199,698.20","f":11,
                "extend":{"uniqkey":"2.c.4...","TB_DIMLEV_CURR_00000":"1002Z..."}}]],
    "formats": [...],        // 纯渲染（字体/边框/对齐）
    "combineAreas": [...],   // 合并区
    "modelArea": {...}, "vardefs": {}, "extendAttri": {"DynAreas": []}
  },
  "ts": 1792053030102
}
```

| # | 坑 | 说明 |
|---|---|---|
| 1 | **`RowHeader`/`ColHeader` 名不副实** | 它们是**行高/列宽**，不是表头。真正的表头模型在 `CellsModel.getRowHeaderModel()/getColumnHeaderModel()` 里，序列化时只剩了尺寸 |
| 2 | **`v` 与 `tv` 不同** | `v` 是**原始值**（`199698.2`），`tv` 是**显示值**（`199,698.20`，带千分位）。取数要用 `v` |
| 3 | **`$ref` 引用复用** | 相同属性用 `{"$ref": "$.DynamicModel.cells[6][2].extend"}`，解析方还得自己解引用 |
| 4 | **隐藏行里有有效内容** | 行高 0 的行（本例 1-5、7、8）里，第 7 行是**度量维行**。想"跳过隐藏行"就把表头丢了 |

另外：`Base.colNum`（15）可能与 `cells` 实际列数（14）不一致，**以模型的实际列数为准**。

## 三、平台里能复用的东西

| 需要 | API | 位置 |
|---|---|---|
| 拿报表模型 | `new DataCenter(pkTask, pkSheet, null, paramMap, dataType).getCellsModel()` | `nc.bs.epm.data.grid.query.DataCenter` |
| 也走工厂 | `new DefaultDataCenterFactory().createGetCellsModel(dataType, paramMap)` → `IGetCellsModel` | `nc.bs.epm.data.grid.query` / `...grid.itf` |
| 单元格原始值 | `CellsModel.getCellValue(r,c)` / `Cell.getValue()` | `com.ufsoft.table`（jar：`modules/bqrt/lib/pubbqrt_cellLevel-1.jar`） |
| **拆包装** | `if (v instanceof ICellValue) v = ((ICellValue) v).getCellValue();` | `com.ufsoft.table.ICellValue` |
| 单元格业务属性 | `Cell.getExtNames()` / `Cell.getExtFmt(key)` | `com.ufsoft.table.Cell` |
| 去隐藏行 | `new ExcelExportUtil().creatCellModelRemoveHide(model)` | `nc.bs.bcs.data.excel.ExcelExportUtil` |
| 行数 / 列数 | `model.getRowNum()` / `model.getColumnHeaderModel().getHeaders().length` | |

`ICellValue` 拆包这条是从平台导出实现里学来的（`ExcelExportUtil#covertCell`），
**不拆的话取到的是包装壳而不是值**。

## 四、版本（orig / gb / gbAdjDg）怎么取

靠 **`BM_TRAIL`** 区分。平台导出 `nc.bs.epm.data.export.ExportExcel#transformTask` 里的硬编码就是官方口径：

| dataType | BM_TRAIL |
|---|---|
| `orig`（初始个别报表数） | `1001Z4D00000000WH022` |
| `gb`（个别报表数） | `1001Z4D000000000WH02` |
| `adjafter` / `adjdg` | `1001Z4D0000000002IC7` |
| **`gbAdjDg`（调整分摊底稿）及其他** | **不传**，用当前任务（`getCurrTask()`） |

机制：`AbsGetViewJson#getNewTaskPk` 在 paramMap 带 `BM_TRAIL` 时，会经
`new TaskInfo(pkTask).getTaskByAuditPK(trail).getPk_obj()` **反查出该版本对应的任务实例**——
所以 orig 与 gb 即使传同一个 `pk_task`，也能各自取到正确的数。

`tb_cube_SCCWBB` 是纯维度表（无 pk_task 列），orig 与 gb 的数据就是靠 `PK_BM_TRAIL` 分开的。

## 五、把网格转成业务结构（平台没有现成的）

平台对 `CellsModel` 只有输出方向：→ JSON（渲染）、→ Excel / HTML / PDF（导出）、← XML / Excel（导入）。
**没有 `CellsModel → 指标/维度/值`**——因为平台自己不需要。
`IArea` / `IAreaAtt` 只有坐标范围，**没有"这块是数据区"的语义标签**。

所以这一步要自己写。**关键是不要硬编码行号**，否则表样一调就静默出错。动态识别四步：

1. **列头行** = 第一个出现「指标」字样的行（集团报表每行对应一个 cube 指标，编码形如 `TB.global.SCZCFZ003`）；
2. **栏** = 列头行上每一处「指标」是一栏的起点（资产负债表左栏 c=1、右栏 c=7 → 两栏）；
   末栏取到列头行**最后一个非空列**（否则会把尾部的空列带进来）；
3. **度量维** = 出现「度量维」的行，用它的值给每个数值列配编码
   （`global.QM` 期末数 / `global.NC` 年初数 / `global.BDE` 变动额 / `global.BZ` 备注）；
   该行上写「度量维」的那格是标签，要置空；
4. **数据行** = 列头行之后、在该栏列范围内**有值**的行（空行跳过即可，
   左右栏各自的列范围不同，天然不会互相串行）。

产出建议（自描述，对接方不用数坐标）：

```json
{
  "layout": "two-block", "headerRow": 10, "rowNum": 58, "colNum": 14,
  "blocks": [
    { "name": "左栏",
      "columns": ["指标","项目","期末数","年初数","变动额","备注"],
      "metrics": ["","","global.QM","global.NC","global.BDE","global.BZ"],
      "rows": [["TB.global.SCZCFZ003","货币资金","199698.2","199744.31","-46.11",""]] },
    { "name": "右栏", "columns": [...], "metrics": [...], "rows": [...] }
  ]
}
```

报表名 / 单位 / 期间**不必进 JSON**——它们能从任务上下文（`tb_md_task` + `org_orgs`）拿到。

## 六、实测样本（NCC1909 · 安徽淮创 · 2024-01）

- 网格：58 行 × 14 列；`headerRow=10`、`metricRow=7`、栏起点 `[1, 7]`、末非空列 `12`
- 真相：资产负债表是**左右两栏**，左栏 c=1..6、右栏 c=7..12，各 6 列 46 行数据
- 指标名在单元格里带排版缩进（`"      货币资金"`），取用时建议 `trim()`
- 数值列示例：货币资金 期末 `199698.2` / 年初 `199744.31` / 变动 `-46.11`

## 七、还没验过的

- **利润表 / 现金流量表**是单栏布局，同一算法应适用，但**无样本实跑**过
- `Base.colNum` 与 `cells` 列数不一致的原因未深究（疑与列宽 1px 的近似隐藏列有关）
- `ICellValue.getCellValue()` 的返回类型是否有更细的分支（金额/日期）未逐一验证
