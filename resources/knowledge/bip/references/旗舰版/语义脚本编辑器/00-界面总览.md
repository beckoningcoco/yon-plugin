## 1. 它是什么、从哪进

**语义脚本编辑器 = 语义模型编辑页里的 SQL 脚本抽屉**，不是一个独立页面。

```text
https://<host>/iuap-data-common/ucf-wh/intelliv/index.html#/semantic/query/edit/<语义模型ID>?serviceCode=report-28&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC
```

和报表设计器是**同一个前端**（`intelliv`），靠 `listType` 区分：`DIRSEMANTIC`＝语义模型，
`DIRREPORT`＝报表（`serviceCode` 也随之不同）。别把两者的页面结构记混。

| 折叠项 | 内容（实测） | 用途 |
|---|---|---|
| **参数** | 本模型已定义的参数列表（本例为空）；带搜索框 | 与顶部「参数」按钮同源 |
| **系统变量** | 期间类变量，**中文名 + 英文编码**：当前年2026 `currentYear`、当前月10 `currentMonth`、当前年月2026-10 `currentYearMonth`、上年同月2025-10 `lastYearMonth`、上期年月2026-09 `lastIssueMonth`、当前季Q4 `currentSeason`、当前年季2026-Q4 `currentYearSeason`、各季度第一天/最后一天… | 随运行日期走的值 |

## 4. 操作纪律

1. **改动要保存才生效**：抽屉底部「确认并返回」→ 主界面「保存」。只是看的时候**不要点这两个**。
2. **「执行」会真的跑 SQL**（只读查询），别在没确认过的脚本上随手点。
3. **用 `browser_*` 时**：抽屉不在 DOM 里就说明还没打开；SQL **既能读也能程序化改** ——
   `document.querySelector('.cm-content').cmView.view` 就是 CodeMirror 的 EditorView，
   读用 `state.doc.toString()`、改用 `dispatch({changes})`。
   ⚠️ **别用 `innerText` 读 SQL，它会漏内容**（实测同一份 SQL：`innerText` 7834 字符 vs `doc` 9472 字符，
   同一个值数出 37 处 vs 真实 39 处）。批量改 + 执行 + 保存的完整套路见 [[02-用脚本改SQL并保存]]。
4. 主界面步骤条右侧也有一个「参数」，**本文未核实**它是否与抽屉里的是同一个入口；
   抽屉里那个（`execute_param`）已核实，见 [[01-参数与固定值替换]]。
