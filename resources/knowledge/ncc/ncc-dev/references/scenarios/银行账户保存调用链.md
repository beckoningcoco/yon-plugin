# 银行账户（单位银行账户）保存调用链 — NCC2505

> 采集口径见 [_call-chain-collection-standard.md](./_call-chain-collection-standard.md)。
> 证据等级：**反编译**（本机无 NCC2505 数据库连接，字段未做实测；SPR 单列一轮）。
> 环境：Home = `E:/NCProject/NCC2505/HOME_BYZY_BIP`，元数据索引 6603 实体 / 258833 字段。

## 1. 什么时候读我

- 客开要**在单位银行账户保存前后插手**：校验账号/户名唯一性、开户单位与核算归属组织的对应关系、账户停用/销户联动、子户（子账户）批量维护。
- 排查「账户编码取号冲突」「联行号（IBAN）被清空格导致重复」「删账户后客户档案下的银行账户还在」这类问题。
- 想知道**银行账户走的是哪条持久化通道**——它和客户、供应商、物料同属基础档案（BD）族，但落的是 `BDSingleBaseService` 模板，且**自己重写了 insert/update/delete**，不是纯用父类。

> 银行账户 ≠ 银行档案（`bd_bankdoc`）。银行档案是"哪个银行"，银行账户是"本单位在某个银行开的户"。两者是不同的实体、不同的 action XML、不同的服务类。见 [_call-chain-archive-plan.md](./_call-chain-archive-plan.md)。

## 4. 入口 action 的四个分支

`BankAccCardSaveAction#doAction` 只有两个维度：**主键有没有** × **saveFlag 是不是 "specil"**。

| 条件 | 行为 | 行 |
|---|---|---|
| `pk_bankaccbas` 空 **或** `saveFlag == "specil"` | 先查一次：specil 且已存在同主键 → 抛 `BusinessException("该单据已经生成银行账户！")`；否则 `setStatus(2)` → **`insertBankAccBaseInfo`** | :63-69 |
| 否则（有主键且不是 specil） | **`updateBankAccBaseInfo`** | :71 |
| 结果为空 | 直接 `return null`（无报文） | :73 |
| 正常 | `bill.setBodys(bankaccVO.getBankaccsub())`、`bankaccVO.setBankaccsub(null)`、`bco.toCard(bill)` | :76-79 |

收尾把 `accnum` 的 value 复制到 display（:84，**第 84 行是空指针风险点**——`bc.getHead()` 为空时直接 NPE）。

**子户预处理（:44-59，容易漏）**：
- `status != 3` **或** `pk_bankaccbas` 非空 → 保留进 `bankaccvoList`；
- `istrade == null` → 强制 `UFBoolean.FALSE`；
- 当**主表有主键且 saveFlag 非 specil**（即修改场景）时 → `fronzenstate = 0`、`pk_bankaccbas = 主表主键`、`status = 2`。**注意这里给所有子户无条件重置为正常状态**，是修改路径上的一个潜在坑。

## 7. 写路径一：修改（`updateBankAccBaseInfo:307`）

1. `retrieveVO(primaryKey)` 拿 `oldVO`（:311，**后面 :322 又拿了一次**，两次重复查询）。
2. `updateBankacc:318`：
   - `handlePk_elecbill(vo)`（同新增）；
   - `BDPKLockUtil.lockSuperVO({vo})`（:320，**先 PK 锁**）；
   - `BDVersionValidationUtil.validateSuperVO({vo})`（:321，乐观锁版本校验）；
   - `retrieveVO` 拿 `oldVO`；
   - `deleteAccnumBlank4IBAN`（IBAN 去空格）；
   - `updateValidateVO(oldVO, vo)`（:324）；

   - `setUpdateAuditInfo(vo)`；
   - `fireBeforeUpdateEvent(oldVO, vo)` → `dealAccsubVOsBeforeUpdate(vo, oldVO):460`（**返回 `Map<String, List<String>>`，键是 `insert` / `update` / `delete`**）→ `dbUpdateVO(vo)`；
   - `notifyVersionChangeWhenDataUpdated(vo)`；按 map 里的键分别 `CacheProxy.fireDataInserted/Updated/Deleted`（:369-379）；
   - `retrieveVO` 回读 → `fireAfterUpdateEvent(oldVO, vo)` → `dealAccsubVOsAfterUpdate(vo, oldVO, map):395`。
3. 业务日志用**父子比对**：`BDBusiLogUtilHasJudeged(mdId).writeModefyBusiLog("edit", newVO, oldVO)`（:313-314）。

> `updateBankacc` **没有 `updatelockOperate`**——只有 `BDPKLockUtil`，没有 `BizlockDataUtil`。与新增路径（只有 `BizlockDataUtil`）正好互补，两边都缺一半。这一点在排查「两处并发改同一个账户」时很关键。

## 8. 写路径二：删除（`deleteBankAccbas:560` / `deleteVO:575`）

- `deleteBankAccbas:560`：先看 `isinneracc` 与 `accclass`，`deleteVO(vo)` 之后，**非内部账户且 `accclass == 2`（公司）才归还取号** `returnBillCodeOnDelete("bankaccount", pk_group, pk_org, code, vo)`。
- `deleteVO:575` 自写六步：`deletelockOperate(vo)` → `BDVersionValidationUtil.validateSuperVO` → `deleteValidateVO(vo):592`（父类 + 对 `getBankaccsub()` 跑 `getDeleteValidator`）→ `retrieveVO` → `fireBeforeDeleteEvent:623` → `notifyVersionChangeWhenDataDeleted:599` → `dbDeleteVO:634` → `fireAfterDeleteEvent:612` → `writeBusiLog("delete", ...)`。
- `dbDeleteVO:634` 在父类之后追加 **`delCustbankaccInfo(vo):639`**：用 `ICustBankaccQueryService#queryCustBankBySubPk` 按子户主键查客商侧银行账户，有则 `baseDAO.deleteByClause(CustbankVO.class, " pk_bankaccbas = '...' ")` —— **直接拼 SQL 删客户档案下的银行账户**，用 `NCESAPI.sqlEncode` 转义，并 `CacheProxy.fireDataDeletedBatch` 清缓存。

**预置码模式**：`BillCodeContext.isPrecode()` 为真时入口**不取号**，界面上直接给一个可编辑编码（handler `setDefaultValue:593` 分支），保存时才由 `commitPreBillCode` 落定；非预置码模式则在 `insertBankAccBaseInfo` 内直接取号。`precode` 变量的作用域只在新增方法内，所以**预置码提交失败不会回滚已插入的数据**（:161 在 insert 之后）。

## 10. 事务与锁

- **事务**：整条链**没有任何显式事务注解或手工 begin/commit**（已 grep `RequiresNew` / `TransactionAttribute` / `startTransaction` / `commitTransaction`，仅命中取号方法的 `_RequiresNew` 后缀）。事务边界由容器/EJB 层提供，反编译层看不到——**这是本条链最大的 ⬜**。
- **锁（三类，各用在不同的地方）**：
  1. 新增：`BizlockDataUtil.lockDataByBizlock(provider, {vo})`，`provider = BankaccBizlockDataProvider`（本类内部类）；
  2. 修改 / 销户 / 升级 / 启停：`BDPKLockUtil.lockSuperVO({vo})`；
  3. 子户冻结/解冻：`BDPKLockUtil.lockString({pk_bankaccbas, pk_bankaccsub})`（子户粒度）；合并账户：`lockString({pk_src, pk_dest})`（双主键）。
- **乐观锁**：修改与删除都在动作前跑 `BDVersionValidationUtil.validateSuperVO`（依赖 `modifiedtime` 之类版本列，不是显式 version 字段）。
- **锁失败报文**：入口 catch 段把 `UndeclaredThrowableException` 剥开，`LockFailedException` → 走资源包 `nccriauapbd0` 提示（与供应商档案同一套）。
- **`_RequiresNew` 的取号方法自带新事务**（见 `IBillcodeManage`），所以取号失败/归还**不受主流程回滚影响**——这也是为什么必须显式 `AbandonBillCode_RequiresNew`。
