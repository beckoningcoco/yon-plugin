# 调度任务与线程池使用规范

## 一、调度任务执行时长限制

| 任务类型 | 超时限制 | 能否修改 | 适用场景 |
|---------|---------|---------|---------|
| 普通后端脚本 | 60s | ❌ 框架硬限制 | 轻量数据同步、简单批处理 |
| 后端脚本（长任务） | 1h | 配置选择 | 大批量处理 |
| REST接口调用 | 2s（默认） | ❌ | 所有 HTTP 调用 |

### 超时后果

- 普通脚本超过 60s → 自动结束，任务标记失败
- REST 调用超过 2s → 记录失败

### 应对策略

1. **短任务**：选普通脚本，同步执行，返回结果
2. **长任务**：选长任务脚本，或改成异步模式

## 二、YMS 线程池（ymExecutor）行为说明

> **重要**：`YmsExecutors.getYmsExecutor()` 对长任务**只告警不杀死**。

| 行为 | 说明 |
|------|------|
| 60s 警告 | 任务执行超过 60s 时，日志中打印 `Yms线程池执行中的任务超时检测` 警告 |
| 是否杀死线程 | ❌ **不会**强行终止任务，线程继续执行直到完成 |
| 环境差异 | 本地 YDS 无此警告；部署到环境后由 YMS 框架监控产生 |

**结论**：异步长任务优先使用 `ymsExecutor`，警告可以忽略，任务不会被杀。不需要为此单独建自定义线程池。

### 调度的 60s 硬限制

注意区分：调度任务接口本身的 2s/60s 超时是**独立于 ymsExecutor 的**，指的是调度框架等待 REST 接口返回的时间。异步模式下接口立即返回 `asynchronized`，不触发此限制。

## 三、异步模式（推荐）

REST 接口收到调度任务调用后，立即返回 `asynchronized`，后台继续执行：

```java
@PostMapping("/sync")
public Object sync(HttpServletRequest request, @RequestBody Map<String, Object> param) {
    String logId = request.getHeader("logId");
    ymsExecutor.execute(() -> {
        int status = 1;
        String content = "";
        try {
            content = service.doWork(param);
        } catch (Exception e) {
            status = 0;
            content = e.getMessage();
        }
        // 回调通知调度任务
        yonBipUtil.callbackPlatform(logId, status, content);
    });
    return Map.of("asynchronized", true, "status", 1);
}
```

回调接口：`POST ${domain.iuap-apcom-scheduler}/warning/warning/async/updateTaskLog`

回调参数：`{ "status": "1", "title": "...", "content": "...", "id": logId }`

## 三、线程池选择

| 线程池 | 来源 | 上下文 | 监控 | 适用 |
|--------|------|--------|------|------|
| `YmsExecutors.getYmsExecutor()` | 平台 | ✅ 继承租户/用户 | ⚠️ 60s 监控 | DB 操作、文件解析等需框架身份的任务 |
| 自定义 `ThreadPoolExecutor` | 自建 | ❌ 无上下文 | ❌ 无监控 | 纯文件下载等不需要框架身份的任务 |

### 注意事项

- **自定义线程池中调用 `IYmsJdbcApi` 等注入服务会报错**（缺少租户上下文）
- **下载大文件**用自定义线程池，避免被 YMS 60s 监控误杀
- **下载+处理分离**：下载用自定义池 → 处理切回 YMS 池

### 两段式异步模式（解决大文件超时）

```
Controller 下载接口:
  自定义线程池 → downloadFromSftp()  ← 无超时限制
  完成后 → ymsExecutor.execute()     ← 切回 YMS 池
    → syncFiles()                     ← 有框架上下文
```

### 并行处理（解决单文件大超时）

YMS 线程池中并行处理多个 ZIP 文件无效——`syncFile` 内部依赖 `IYmsJdbcApi`，只能用 YMS 池线程。改为拆分子任务：每个 ZIP 文件一个独立 YMS 任务，各自享受完整超时额度。
