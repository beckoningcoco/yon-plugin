# 财务核算账簿保存调用链 — NCC2505

> 采集口径见 [_call-chain-collection-standard.md](./_call-chain-collection-standard.md)。
> 证据等级：**反编译**（本机无 NCC2505 数据库连接，字段未做实测；SPR 单列一轮）。
> 环境：Home = `E:/NCProject/NCC2505/HOME_BYZY_BIP`。

## 1. 什么时候读我

- 客开要在**建账 / 改账套 / 启用账簿**前后插手：总账、资产、存货、成本、税务各自的启用状态与期间方案。
- 排查「账簿保存报"XX 模块未启用"」「切换主账簿没生效」「账簿保存了但 `org_accbook` 没数据」。
- 需要知道**账簿的启用位有哪些、各自的事件码是什么**——这是一份 16 位启用状态的清单（第 7 节）。
- 与 [_会计科目保存调用链.md](./会计科目保存调用链.md) 配套看：**账簿定科目表（`pk_curraccchart`）**，科目定辅助核算。

> 「财务核算账簿」在 NCC 里是 `org_accountingbook`（**不是** `bd_accbook`，也没有 `version`/`latest` 列）。
> 模块归属是 `org`（`riaorg`），但 action 名字前缀仍是 `uapbd.accountingbook.*`——**模块与 action 前缀不一致**，别按前缀找 jar。

## 2. 怎么拿到这条链

**入口 XML**：
```
<HOME>/hotwebs/nccloud/WEB-INF/extend/yyconfig/modules/org/accountingbook/config/action/accountingbook.xml
```
其中保存那一项：
```xml
<action>
    <name>uapbd.accountingbook.save</name>
    <label>财务核算账簿保存</label>
    <clazz>nccloud.web.org.accountingbook.action.AccountingBookSaveOneAction</clazz>
</action>
```
同 XML 的邻居（都是同一族）：`uapbd.accountingbook.add`（新增）/`edit`（修改）/`delete`（删除）/
`enable`（启用禁用）/`batchsave`（批量新增）/`deletepre`（**删除权限前置**）/`enablepre`（**停启用权限前置**）/
`editparaccount`（**修改时校验平行记账**）/`changeBook`（切换账簿）/`print` / 三个 query。

**三步定位**（本次实际路径，可复用）：
1. `query-action.js` / XML → action 类名；
2. `ncc_class_search('AccountingBookSaveOneAction')` → `external/lib/uiriaorg_nccloud.jar`；
3. `ServiceLocator.find(IAccountingBookManageService.class)` → 实现类要看 **UPM 或类索引**：
   `ncc_class_search('AccountingBookManageServiceImpl')` → `nc.impl.org.AccountingBookManageServiceImpl`
   （`modules/riaorg/META-INF/lib/riaorg_org.jar`）。

> 反编译时发现的**大小写坑**：账簿相关 jar 在同一模块下有两个——
> `modules/riaorg/META-INF/lib/riaorg_nccloud.jar`（pubimpl 层）与 `modules/riaorg/lib/pubriaorg_org_rt.jar`（VO 层）、
> `modules/riaorg/META-INF/lib/riaorg_org.jar`（实现层）。VO 不在 `riaorg_org.jar` 里，在 `pubriaorg_org_rt.jar`。

## 4. 入口 action 的分支

`AccountingBookSaveOneAction#execute` 只有两个维度：**`pk_accountingbook` 有没有** × **`formStatus` 是不是 `edit`**。

| 条件 | 行为 | 行 |
|---|---|---|
| `formStatus == "edit"` | 先 `isNullPeriodOnEdit(vo)`；返回非空串 → **不保存**，返回 `{status:"1", msg:...}` | :42-50 |
| `pk_accountingbook` 空 | `pk_group`/`pk_org` 都为空时补成会话集团 → `insertVO(vo)` | :53-59 |
| 否则 | `updateVO(vo)` | :61 |
| 成功 | `new FormConvertor().toForm("accountingbookcard", updateVO)`、`setPageid("10100ACB_accountingbook")`、套模板算公式、翻译 → `{status:"0", returnForm:...}` | :63-74 |
| `BusinessException` | `ExceptionUtils.wrapException` | :76-78 |

**`isNullPeriodOnEdit:82-98` 是入口层的"想启用就必须给期间"校验**，逐项检查（注意只看**启用位是 2 或 3**的）：

| 检查 | 条件 | 资源 |
|---|---|---|
| 总账 | `accountenablestate` ∈ {2,3} 时 `pk_accountperiod` 与 `pk_curraccchart` 不能都空 | `AccountingBookSaveAction-nc-000000` |
| 资产 | `assetenablestate` ∈ {2,3} 时 `pk_assetperiod` 必填 | `-nc-000001` |
| 存货 | `materialenablestate` ∈ {2,3} 时 `pk_materialperiod` 必填 | `-nc-000002` |
| 税务 | `taxenablestate` ∈ {2,3} 时 `pk_taxperiod` 必填 | `-nc-000003` |
| 项目成本 | `itemcostenablestate` ∈ {2,3} 时 `pk_itemcostperiod` 必填 | `-nc-000005` |
| 产品成本 | `productcostenablestate` ∈ {2,3} 时 `pk_productcostperiod` 必填 | `-nc-000004` |

> 只有 `formStatus == "edit"` 才跑这套；**新增不跑**。所以"新增时漏填期间"要被后面的服务层校验器兜住。

## 5. 新增路径：`MultiManageTypeBaseService#insertVO:220` 十步

```java
if (vos == null || vos.length == 0) return vos;        // :221-223 空入参直接返回
this.insertlockOperate(vos);                            // :224 → 本类重写：lockPkOrg
this.insertValidateVOs(vos);                            // :225 → getInsertValidator() 7 个
this.setInsertAuditInfo(vos);                           // :226 → AuditInfoUtil.addData
this.fireBeforeInsertEvent(vos);                        // :227 → BDCommonEventUtil(mdId)
String[] pks = this.dbInsertVOs(vos);                   // :228 → 本类重写（见下）
this.notifyVersionChangeWhenDataInserted(vos);          // :229 → CacheProxy.fireDataInserted(tableName)
vos = this.retrieveVOs(pks);                            // :230 回读
this.fireAfterInsertEvent(vos);                         // :231
this.writeInsertBusiLog(vos);                           // :232 → writeBusiLog("add", null, vos)
```

**被账簿覆写的三处**：

1. **锁（`insertlockOperate:208` → `lockPkOrg:212`）**：把各 VO 的 `pk_relorg` 收成 Set，交给
   `PKLock.getInstance().addBatchDynamicLock(pks)`；**抢不到锁就抛**
   `NCLangResOnserver("org","AccountingBookManageServiceImpl-000000")`。
   —— 注意这里用的是 **`PKLock`（组织维度动态锁）**，不是 `BizlockDataUtil`，也不是 `BDPKLockUtil`。
   **同一关联组织下并发建账会被挡住**。

2. **`dbInsertVOs:318`（插主表 + 插组织 + 挂科目表）**：
   ```java
   for (vo : vos) vo.setStatus(2);
   String[] accBookPks = getMDService().saveBill(vos);              // ① 写 org_accountingbook
   for (i...) {
       OrgVO orgvo = OrgVOAdapterFactoryBasic.getInstance().createOrgVO(vos[i]);
       orgvo.setOrgtype47(UFBoolean.TRUE);                          // ② 标记为"核算账簿"型组织
       ((IOrgUnitManageBasicService)NCLocator.lookup(IOrgUnitManageBasicService.class)).insertVO(orgvo);
       CacheProxy.fireDataInserted(orgvo.getTableName(), null);      //    写组织主数据
   }
   String pk_accchart = vos[0].getPk_curraccchart();
   this.getAccChartService().setAccountingBookForAccchart(accBookPks, pk_accchart, false);  // ③ 科目表挂账簿
   return accBookPks;
   ```
   > **一处要看仔细**：`pk_accchart` 只取 `vos[0]` 的，**批量新增时所有账簿都挂第 0 条的科目表**。客开做批量建账要留意。

3. **`insertVO(vo)` 单条版（:278）**：`setPk_org(pk_group)` → `super.insertVO` → `syncToAccBookVO(insertVO)`。

**`syncToAccBookVO:285`（写第二张表）**：`TransToAccBookUtil.batchToAccbookVO(vos, false)` 生成
`AccbookVO[]` → `new BaseDAO().insertVOArrayWithPK(...)` → `CacheProxy.fireDataUpdated(AccbookVO.getDefaultTableName())`。
失败时抛「将财务核算账簿数据往 org_accbook 表中同步时发生了错误」。
—— **账簿一次保存写两张表**：`org_accountingbook`（主）与 `org_accbook`（同步表）。后者是给其他模块读的扁平视图。

## 7. 修改路径：`AccountingBookManageServiceImpl#updateVO:334`

```java
vo.setPk_org(vo.getPk_group());                                            // :335
AccountingBookVO returnvo = ((AccountingBookVO[])super.updateVO({vo}))[0]; // :336 → MultiManageTypeBaseService#updateVO:156
this.syncUpdateToAccBookVO(returnvo);                                      // :337 → 同步 org_accbook
return returnvo;
```
`super.updateVO` 的顺序（`MultiManageTypeBaseService:156-172`）：`updatelockOperate` → `updateValidateVOs` →
`setUpdateAuditInfo` → `fireBeforeUpdateEvent` → `dbUpdateVOs` → `notifyVersionChangeWhenDataUpdated` →
`fireAfterUpdateEvent` → `writeUpdatedBusiLog`。

**账簿自己的两处覆写**：

1. **`updatelockOperate:223`**：先 `super.updatelockOperate(vos)`（父类 = `BDPKLockUtil.lockSuperVO`），
   **再 `addBusiLock:228`** —— 锁键是 **`getTableName() + pk_relorg + pk_setofbook`** 拼出来的动态串，
   仍走 `PKLock.getInstance().addBatchDynamicLock`。抢不到抛同一句 `-000000`。
   > 新增锁的是 `pk_relorg`，修改锁的是 `表名+pk_relorg+pk_setofbook`，**两次锁的键不一样**。

2. **`updateValidateVOs:245`**：先父类校验，**再 `setAccchartByOldAndNewVOs:250`** ——
   **科目表变了就调 `IAccChartService`**：
   - 旧空新非空 → `setAccountingBookForAccchart({pk}, 新科目表, false)`
   - 旧非空新空 → `cancelAccountingBookForAccchart({pk})`
   - 两边都非空且不同 → 先 `cancel` 再 `set`
   > **"改账簿的科目表"不是一句 update**，它会去改科目表侧的归属。

**平行记账校验单独走一个 action**：`uapbd.accountingbook.editparaccount` →
`AccountingBookEditParaccountAction`，最终落到 `AccountingBookServiceImpl#ValidateEditParaccount:80`
（只用 `BDReferenceChecker` 校验，`ValidationException` 时返回 `true` 表示"需要拦截"）。
