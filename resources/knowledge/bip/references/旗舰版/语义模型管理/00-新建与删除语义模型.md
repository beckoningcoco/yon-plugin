# BIP 旗舰版 · 语义模型的新建与删除（全流程实测）

> 实测：2026-10-12，国投集团 `erpbip.sdic.com.cn`，旗舰版，租户 `U8C3`，账号 `yhtmanager`，数据源 `TP查询仓-采购云`（MYSQL8）。
> 关联：[[../报表SQL/07-经验-语义模型报表开发]]（模型里的 SQL 口径与参数）、[[../报表设计器/08-操作手法与判据纪律]]（浏览器驱动纪律）。

**一句话**
- **建模型**：选目录 →「新增」填表 → **勾选行** →「语义模型设计」（另开页签）→「添加SQL脚本」写 SQL →「执行」验证 →「保存并返回」→ 向导「保存」。
- **删模型**：**勾选行** →「更多」→「批量删除」。
- **删目录**：左侧点「**全部**」→ **悬停目录行** →「更多 ˅」→「删除」。
- ⭐ 到处都有一个共同点：**操作入口不在你第一眼找的地方**（不是点名称，而是"勾选行"或"悬停行"）。

## 1. 进页面 & 怎么判断"真的进来了"

- 首页顶部「我的收藏 / 最近使用 / 常用应用」里点 **语义模型**。
- ⚠️ **点击后是门户内的 tab，`location.href` 仍然是 `https://<host>/#/` 不变。**
  **不要用 URL 判断有没有进去**——本会话就因此误判成"点击失败"，白绕了很久。
  判断只能看内容区：出现左侧目录树 `ul.mk-dir-tree-left` + 右侧列表 + 工具栏 `新建文件夹 / 新增 / 导入 / 高级搜索`。
- 语义模型的设计器（模型定义）是**另开一个浏览器页签**，地址形态：
  ```text
  https://<host>/iuap-data-common/ucf-wh/intelliv/index.html#/semantic/query/edit/<模型ID>?&serviceCode=intellivworkbenchplatform-28&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC
  ```
  ⚠️ `serviceCode` 是 **`intellivworkbenchplatform-28`**（从门户点进来带的是这个）。纯 intelliv 独立页用 `report-28`。
- 租户号：URL 的 `systenant`，或 `localStorage.diworkContext` 里的 `ytenantId`。

## 2. 列表页的两副面孔（先搞清楚在看哪张）

| 左侧树选中 | 右侧列表张什么样 |
|---|---|
| **「全部」** | 所有**目录行 + 模型行混排**在同一张 `wui-table` 里 |
| 某个具体目录（如「自建」） | 该目录下的**模型行** |

- 左侧树的 `li` 是**嵌套**的：「全部」那个 `li` 的高度**包含它所有子节点**（实测 672px）。
  ⚠️ 拿 li 的中心点去点，会落到子节点上 → **要点标题 `span.wui-tree-title`**。
- 目录行的 checkbox 是 **`disabled`**（勾不上），所以目录**走不了"批量删除"**，只能走行内「更多」。

## 3. 新建目录

1. 左侧树选中父目录（「全部」或某个目录）。
2. 点工具栏「新建文件夹」。
3. 第 1 行**立即多出一行**，但它处于**就地重命名编辑态**：名称单元格里是一个**可见的输入框**
   （`input[inputid="name"]`，默认值 `新建文件夹N`，已自动聚焦），同时 `div.file-name` 是**空的**、
   这一行的 `data-row-key` **也是空的**。
4. ⚠️ **必须提交这个编辑态，目录才真正存在** —— 直接按 **Enter** 用默认名，或改好名字再回车。
   **不提交就离开的话它只是一行草稿**：实测早先一次点完只发出了
   `GET /iuap-data-common/obj/getDefaultName?...&pid=<父目录ID>&type=DIRSEMANTIC`，树和列表里都没有它。
5. 提交后列表会重排，该行拿到真正的 `data-row-key`，创建者/时间也出现了。

> 💡 **重命名有两个入口，都是就地编辑**：
> ① **新建后那一步**（上面第 3–4 步）就是改名的机会；
> ② 改**已有**目录：**悬停该行 → 点「重命名」→ 行内变成输入框 → 改好 Enter**（见 §3.1）。
> 之前写"找不到重命名入口"是错的 —— 它就长在那组 hover 按钮里，和「删除」同样的出场方式。

> ⚠️ **悬停不生效时，先看指针原来在哪儿**：`browser_hover` 只在指针**真的"进入"元素**时才触发 hover
> 渲染。如果指针**本来就已经停在这一行上**（比如刚在某行的输入框里按过回车），它的两次移动都发生在
> 元素**内部** —— **一个 `mouseenter` 都不会产生**，行会带着 `-hover` 类却什么都不渲染。
> 处理办法：**先把指针移到别处再悬停**（工具已按这个修好：现在每次都先到中性角 `(1,1)` 再进入目标）。
> 实测连续 hover 同一个目标三次：修复前第 2 次起就没反应，修复后三次都正常。

### 3.1 重命名一个已有目录（实测）

1. 左侧点「**全部**」（或它所在的父目录），让右侧列出目录行。
2. **悬停到该行** → 行尾出现 `重命名 / 复制到 / 移动到 / 更多` —— 和删除是**同一组按钮**。
3. 点「**重命名**」→ **行内变成输入框**（`input[inputid="name"]`，值 = 当前名字，已自动聚焦）。
4. 改好名字（`browser_set_value` 可直写）→ **Enter 提交**。
5. 验证时看这四处：**`data-row-key` 不变**（同一个对象改名，不是新建）、序号可能因重排而变、
   **修改时间**更新、**左侧树同步改名**。

> 实测把 `新建文件夹18` 改成 `客开-重命名验证`：rowKey 仍是 `980544c6…`，树里也变成新名字；
> 随后删除时确认框写的就是「**确定要删除客开-重命名验证**」—— 说明改名**真的落到了服务端**。

## 4. 新建语义模型

1. 左侧树选中目标目录（本会话用的「自建」）。
2. 点工具栏「**新增**」（红色主按钮）→ 弹窗「新建语义模型」。
3. 四个字段（表单 id）：`#objCode` 编码、`#name` 名称、`#dataSource` 数据源、`#description` 描述。
   - 编码规则：**字母开头，字母/数字/下划线，≤40 字符**。
4. ⚠️ **数据源下拉是虚拟列表**，选中项要**完整事件序列**才生效：
   `mouseenter → mouseover → mousedown → mouseup → click`。
   只发一次 `browser_click` 会出现"点了、但界面仍显示『请选择数据源』"的假成功。
5. 点「确定」→ 模型创建成功，**不会自动进设计器**，回到列表。
6. **进设计器**：**勾选该行 checkbox** → 工具栏出现「**语义模型设计**」→ 点它 → **另开页签**打开向导。
   （点模型名只是选中/无反应，不是打开。）

## 5. 向导五步 + 写查询 SQL

向导步骤：`1、选择表 → 2、设置连接条件 → 3、选择字段 → 4、描述器 → 5、选项`
工具栏：`预览数据 / 预览模型 / 参数` ＋ `添加业务对象 / 添加数据库表 / 添加SQL脚本 / 添加聚合表 / 添加语义模型 / 添加存储过程 / 删除表`

### 5.1 写 SQL（"查询 SQL 测试"的入口就是「添加SQL脚本」）

1. 点「**添加SQL脚本**」→ 打开**语义脚本编辑器**：表名、表显示名、Monaco SQL 编辑器、字段列表；
   顶上是 `标准SQL / 代码优化 / 执行参数`，并显示 `当前数据源 / 数据库类型`（本例 `TP查询仓-采购云` / `MYSQL8`）。
2. 表名要求：**字母、数字、下划线组成、需以字母开头**。
3. SQL 可以直接用 Monaco API 写入：
   ```js
   window.monaco.editor.getModels()[0].setValue("select 1 as id, 'A客开' as name")
   ```
4. 点「**执行**」→ 底部出现 `字段列表 / 查看数据` 两个页签，「查看数据」里出结果
   （本例 `select 1 as id, 'A客开' as name` 返回一行 `id=1 / name=A客开`）。
5. 点「**保存并返回**」→ 回到向导，表列表多一行：`表类型 = SQL脚本`、`表名 = 你填的表名`、`表显示名`。
6. 向导底部「**保存**」→ 保存整个语义模型。

### 5.2 权威核对（别只看界面）

```text
GET /iuap-data-common/semantic/model/get/<模型ID>?isAjax=1&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC&serviceCode=intellivworkbenchplatform-28
```
返回 `data.model.tables[0]`：
```json
{ "name": "A客开测试", "alias": "akekaitest", "type": "Script",
  "sql": "#0c2VsZWN0IDEgYXMgaWQsICdB5a6i5byAJyBhcyBuYW1l" }
```
`sql` = **`#0` + base64**，解出来就是 SQL 正文。

## 6. 删除语义模型

1. 左侧树选中它所在的目录 → **勾选模型行**（checkbox）→ 工具栏出现 `语义模型设计 | 更多`。
2. 点工具栏「**更多**」（`.wui-button.wui-dropdown-trigger.ml10`）→ 菜单 `批量删除 / 批量移动`。
3. 点「**批量删除**」→ 确认框：「**确定要删除吗 / 同步删除物化设置的物理表**」→ 确定。
4. 列表行消失。

> ⚠️ **删完 `model/get` 仍然返回完整定义**（加 `_t=<时间戳>` 绕浏览器缓存也一样）。
> 可能是模型定义缓存或逻辑删除，**本会话没有该环境的数据库连接可查 `iuap_dp_data.wb_ta_sqlmodel`，这条没坐实**。

## 7. 删除目录（本会话最费劲的一步）

**正确路径**：

1. 左侧点「**全部**」——**点标题 span，不要点 li**（见 §2）。
2. 右侧列出**所有目录行**。
3. **把鼠标悬停到目标目录行上** → 行尾出现**四个按钮**：

   | 按钮 | 说明 |
   |---|---|
   | 重命名 | |
   | 复制到 | |
   | 移动到 | |
   | **更多 ˅** | 下拉：`设置对象权限 / 删除 / 属性` |

   实测位置：第 13 行那组按钮落在 `y≈702`、`x≈2281…2528`（`更多` 是 `button.wui-button.wui-dropdown-trigger.ml10`，59×22）。
4. 点「**更多 ˅**」→ 点「**删除**」。
5. 确认框会**带目录名**：「**确定要删除新建文件夹18**」→ 删除 → **树和列表里同时消失**。

### 7.1 ⭐ 驱动这条路的坑（给自动化用）

- **那四个按钮只在"真实悬停"时渲染进 DOM**，鼠标一离开就没了。
  不悬停时用 JS 扫 `重命名 / 复制到 / 移动到 / 更多 / 删除` 这些文本 —— **0 命中**。
- **正确做法**：`browser_hover` 到那一行，再用 `browser_eval` 读出按钮。
  ⚠️ hover 之后**指针就留在那儿了**：**不能再 `browser_click`、也不能再 hover 一次**，
  一移动指针按钮就消失（连 `data-z` 这类临时标记也随 DOM 重渲染一起没）。
  使用者自己动一下鼠标、或者切页签，同样会结束这次悬停。
- 如果按钮**已经知道在哪、只是点不到**（点击时它还没渲染出来），用 `browser_click` 配 **`hoverMs`**
  （移动指针后、按下之前先等 200–500ms），相当于替它留出"移过去 → 看到按钮 → 再点"的时间。
- 用**按钮的 y 坐标确认它是哪一行的**（行高 50：实测第 13 行 y 687–737，按钮落在 y≈702）。
  删除确认框会**写目录名**（「确定要删除新建文件夹18」），点之前对一眼——这一行有别人的目录，别删错。
- 打开「更多」下拉、点「删除」这两步，如果不想动指针，也可以全程 `browser_eval`：
  调按钮的 React props 打开菜单，再对菜单项派发事件。
  （**实测**：wui 这套组件对合成 DOM 事件不响应，但对 React props 直调响应 ——
  这也正是 `browser_click` 的 `mode="react"` 走的路。）
  ```js
  const b = /* 行内「更多」按钮 */;
  const k = Object.keys(b).find(x => x.startsWith('__reactEventHandlers$'));
  b[k].onMouseEnter({ stopPropagation(){}, preventDefault(){}, target: b, currentTarget: b, nativeEvent: {} });
  // 内部会走 o.delaySetPopupVisible(true, delay, e)
  // 然后对 .wui-dropdown-menu-item 里文本为「删除」的那一项派发 mousedown/mouseup/click，
  // 确认框的「删除」按钮同样派发一次。
  ```
- ⚠️ **别追错浮动层**：悬停时会有一个名字很像的文库组件浮动层
  `src-libraryTile-common-list-index__library_List_right / library_List_more`
  （fiber props 带 `fileListIds / handlerJumpToFile`）——它是**文库**的行操作，**不是**语义模型的，本会话追了好几轮。

## 8. 接口

| 用途 | 接口 | 备注 |
