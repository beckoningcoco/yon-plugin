# 蓝票开具特有逻辑

## 概述

本文档定义蓝票开具场景的特有逻辑，仅描述与公共逻辑的差异部分。

## 前置条件

1. 发票方向为蓝票（invDirection = 2）
2. 发票未同步至税务系统
3. 发票已审核通过

## 特有差异

### 1. 金额处理

所有金额字段必须为正值（abs）：

| 字段 | 处理 | 代码 |
|------|------|------|
| qty | 绝对值 | qty.abs() |
| oriMoney | 绝对值 | oriMoney.abs() |
| oriTax | 绝对值 | oriTax.abs() |
| oriSum | 绝对值 | oriSum.abs() |

### 2. 发票类型映射

| BIP类型 | 目标类型 |
|--------|----------|
| 10 (数电专票) | 31 |
| 11 (数电普票) | 32 |

### 3. 特有字段

| 字段 | 数据来源 |
|------|---------|
| invType | 发票类型转换 |
| orderNo | BIP.code |
| orderDate | BIP.vouchdate（YYYYMMDD） |
| drawer | 特征组-开票人 |

### 4. 折扣处理

蓝票独有的折扣字段（红票不传递）：

| 字段 | 说明 |
|------|------|
| lineDiscountMoney | 折扣含税金额 |
| discountType | 折扣类型：1明折/2暗折 |

## 红冲特有差异点

与红冲（即reference/07_red_only.md）的差异：

| 项目 | 蓝票 | 红冲 |
|------|------|------|
| 金额符号 | 正值abs() | 负值negate() |
| 原票信息 | 无需 | 必填 |
| 冲红原因 | 无需 | 必填 |
| 折扣字段 | 传递 | 不传递 |

## 完整流程

```
1. 接收 invoiceId
2. 调用 iuap-c-openapi-integration 查询BIP数据
3. 字段映射转换（金额abs）      ← 蓝票特有
4. 特征字段翻译
5. 发票类型转换（10→31/11→32）  ← 蓝票特有
6. 调用三方接口
7. 响应解析
8. 回写结果
```

## 注意事项

- 所有金额必须为正值
- 发票类型必须进行转换
- 蓝票特有字段参考：reference/02_field_mapping.md
