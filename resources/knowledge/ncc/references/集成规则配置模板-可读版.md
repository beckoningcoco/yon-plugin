## 五、配置决策速查

写新接口时，每个字段按此流程决策：

```
接口文档的字段
  │
  ├─ 字段类型是"参照"或"编码"？
  │   └─ 是 → 归入 §2.1（ref），查 VFIELDTYPE
  │        → 查《常见参照 VFIELDTYPE 速查》→ 没找到 → 查 md_class
  │        → 确定 scope（group/org/global）
  │        → 确定 onNotFound（必填→error，可选→ignore）
  │
  ├─ 字段类型是"字符/日期/数字"，外部传入？
  │   └─ 是 → 归入 §2.2（direct），值照搬
  │
  ├─ 文档标注"固定"或"NCC自动生成"？
  │   └─ 是 → 归入 §2.3（fixed）
  │        → ⚠️ 额外检查：值是不是编码？
  │           ├─ 是编码 → 升级为 ref！（如 jsfs=3）
  │           └─ 是主键/枚举 → 保持 fixed
  │
  └─ 字段不在请求参数中（仅用于回写/查询）？
      └─ 是 → 归入 §四，注明排除原因
```

## 六、常见陷阱 ⚠️

1. **固定值 ≠ 不翻译**：`jsfs=3` 中的 `3` 是编码不是主键，必须 type=ref
2. **表体字段要加前缀**：VFIELD 格式为 `{prefix}.{field}`，前缀从 bmf 文件取
3. **vfieldtype 区分版本**：`deptid` 用 `DeptVO`（b26fa3cb），`deptid_v` 用 `DeptVersionVO`（66ed0cf6）
4. **scope 不能默认全填 org**：大多数档案是 group 级别，只有少数按业务单元隔离的才填 org
5. **jobid 不是会计科目项目**：是项目管理项目（`ProjectHeadVO`），查错 fullclassname 会漏掉
