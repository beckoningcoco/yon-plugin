# 新建自由报表：端到端回归测试用例

> 目的：把「从零建一张自由报表」变成**可反复执行**的测试。
> 输入：需求（确认单）+ 表样（xls/md，列头与列数）+ 字段说明（md，每列取数口径）
> 输出：一张能预览出数、筛选器生效、全部落库的自由报表，且每一步都有可断言的判据。
>
> 配套：流程与踩坑见 [[09-从零建一张报表-端到端流程与踩坑]]；SQL/参数写法见
> [[../报表SQL/07-经验-语义模型报表开发]]；筛选器细节见 [[01-筛选器与参数绑定]]。

---

## 0. 为什么要有它

报表开发流程里有大量「点了没反应」的静默失败（见 09 的 12 个坑）。
**光看页面像是成功了，实际刷新就丢**。所以测试用例的判据必须是**接口字段 + 刷新后状态**，
不能用"按钮变成灰色了""弹窗关了"这类界面现象。

---

## 1. 测试输入（三件套）

| 输入 | 形式 | 用它确认什么 |
|---|---|---|
| 需求描述 | 一句话 + 业务口径 | 报表名、行列粒度 |
| 表样 | `.xls` / `.xlsx` / 截图 | **列数、列顺序、列中文名**（多数设计器粘贴要按列对齐） |
| 字段说明 | `.md` | 每列取哪张表哪个字段、关联/枚举规则 |

> 三件套进需求条目 `user/`；确认单（字段映射+待确认项）进 `generated/`，见 [[../报表SQL/08-接单产出物-报表开发确认单]]。

---

## 2. 前置条件（测试开始前逐条确认）

| # | 条件 | 怎么确认 |
|---|---|---|
| P1 | 环境可达且已登录 | `browser_targets` 能找到该环境的页签 |
| P2 | 测试目录已建（语义模型侧 + 报表侧各一个） | 列表页能看到该文件夹 |
| P3 | 数据源确认方言 | 语义模型新建时选的 TP 仓是 **MySQL8**（不是达梦）；裸表名会 Table not found |
| P4 | SQL 已在目标仓验证过 | 设计器「执行」能出数（或在业务库用 `datasource_query` 验过，注意两库数据可能不同） |
| P5 | 参数名清单已定 | 4 个以内建议 `xxx1`…，避免与平台保留名冲突 |
| P6 | **枚举列的取数口径已核实** | 有枚举列（`bd_*_enum` 之类）时，先在抽屉「执行」一条 `SELECT COUNT(*) FROM <字典表> WHERE <定义ID>`。返回 0 **不要自己先硬编码**，先回去找使用者核实字段说明是不是指错了表/键（见 09 §2.1） |
| P7 | **SQL 带稳定排序** | 分页报表必须 `ORDER BY <唯一键>`（如客户编码），否则几十万行翻页会行重复/漏行且不报错（见 09 §2.3） |

## 3. 基线（每次测试前先确认，作为后续断言基准）

> ⚠️ **业务库行数 ≠ TP 查询仓行数**。报表跑在 TP 仓，断言必须以 TP 仓实际返回为准。
> 实测（2026-10-18 二次实证）：客户档案在业务库 323,504 行，在 TP查询仓-公共 也是 **323,504 行 / 6471 页**。
> （更早一版记的「60,002 行」经复核是错的，已作废。）

| 断言点 | 期望（金隅实测） | 取法 |
|---|---|---|
| 模型参数数 | 4 | `model.params.length` |
| 模型字段数 | 15 | `model.tables[0].columns.length` |
| 报表筛选器数 | 4 | `analysisModel.filterModel.filters.length` |
| 每个筛选器绑定数 | 1 | `filters[i].paramsBindOut.length` |
| 预览总行数 | 323,504 | 预览页脚「共 N 条」 |
| SQL 是否带排序 | 含 `ORDER BY <唯一键>` | `model.tables[0].sql` 里检索；**首版例外已留档，新报表必须带** |
| 客户分类取值 | 内部 / 外部 | 预览列 |
| 是否供应商取值 | 是 / 否 | 预览列 |
| 账号类型取值 | 对公账号 / 对私账号 | 预览列 |

## 4. 执行步骤与断言

> 每步两句：**操作**（怎么点，含选择器/DOM 事实）+ **断言**（看到什么才算过）。
> 所有「断言」都优先用接口读，其次刷新后读画布。

### S1 建语义模型
- 操作：列表 → 新增 → 填编码/名称（**名称用真实键入**）→ 数据源选树里的子节点 → 确定
- 断言：列表出现该模型，`GET semantic/model/get/<id>` 返回 `status=1`

### S2 建 SQL 脚本表
- 操作：添加SQL脚本 → 表名/显示名 → CodeMirror 粘贴 SQL → 执行 → 确认并返回
- 断言：执行返回 `status=1`；「查看数据」有行；表出现在表清单里
- ⚠️ 两个坑：①「执行」的数据预览**恒截断 100 条**，别用它断言行数（见 09 §1.2）；② SQL 末尾必须带 `ORDER BY <唯一键>`（见 09 §2.3）

### S3 选字段
- 操作：下一步 ×3 → 选择字段 → 下一步到「5、选项」
- 断言：字段数 = 表样列数（本用例 15）

### S4 声明参数
- 操作：表名行「编辑」→ 顶部「参数」→ **填一个增一行** → 确认 → 确认并返回
- 断言：`model.params.length` = 期望参数数；逐个核对 `code` 与 `defaultValue`（**注意 defaultValue 可能被前端回写旧值，只作为提示不作为判据**）

### S5 保存模型
- 操作：主界面「保存」
- 断言：`GET model/get` 里 `tables[0].sql` 非空、`tables[0].columns.length` = 期望

### S6 建报表并先落库
- 操作：报表列表 → 新增 → 点「空白报表」卡片 → 进入设计器 → **先点保存图标**（`i.ap-baocun-011`）
- 断言：URL 从 `#/report/REPORT/new/...` 变为 `#/report/query/edit/<报表ID>`

### S7 挂数据集
- 操作：字段区「添加模型」→ 切「语义模型」页签 → **左侧目录树点测试目录** → 点模型行 → 全选 → 确定
- 断言：左侧字段树出现全部字段（数量 = S3 的字段数）

### S8 写表头
- 操作：Clipboard API 写 `text/html` 表格 → `hot.selectCell(1,0)` → 编辑 → 粘贴
- 断言：`hot.getDataAtRow(1).slice(0,列数)` 等于表样列头；**刷新后仍在**

### S9 绑定字段行
- 操作：`hot.selectCell(2,0)` → 插入 → 绑定字段 → 逐个点字段行右侧 `i.ap-tianjia` 加入右侧 → 绑定
- 断言：`hot.getDataAtRow(2)` 前 N 列为字段名；刷新后仍在

### S10 加筛选器 × N
- 操作：插入 → 自定义筛选器 → 点类型下拉的 **input**（`#rc_select_*`）选类型 →
  名称真实键入 → 拖值字段（`drag-node.mjs`）→ 参数绑定（参数 / 筛选器字段 / 筛选器自身）→ 确定
- 下拉类额外一步：**「下拉设置 → 来源」改成「数据模型」** 才会出现「拖入字段」
- 断言：`analysisModel.filterModel.filters.length` = N；每个 `paramsBindOut.length` = 1

### S11 保存
- 操作：点保存；若弹「是否应用这些改动」，**点否 → 立即再保存一次**
- 断言：`GET report/design/<报表ID>` 的 `filterModel.filters` 与 S10 一致

### S12 预览验证
- 操作：点预览（`i.ap-yulan-01`）→ 等待加载
- 断言：出现数据行；页脚「共 N 条」与 §3 基线一致；抽样列值形态正确

### S13 筛选器生效验证
- 操作：**在设计态（「筛选」tab）画布上方的筛选器里填值** → 点预览
- 断言：预览弹窗顶部出现 `已选条件: <筛选器名>:<值>`，且行数与库上同条件一致；清空后恢复全量
- ⚠️ 预览弹窗**不渲染筛选器控件本身**（只有「已选条件」一行文字），别把它当成"筛选器没配上"

## 5. 断言脚本（可直接 `browser_eval` 执行）

### 5.1 验证语义模型
```js
(async () => {
  const id = '<模型ID>';
  const r = await fetch('/iuap-data-common/semantic/model/get/' + id + '?isAjax=1&serviceCode=report-28&locale=zh_CN&systenant=<租户>', {credentials:'include'});
  const j = await r.json();
  const m = (j.data && j.data.model) || {};
  return {
    ok: j.status === 1,
    params: (m.params || []).map(p => p.code),
    columns: ((m.tables || [])[0] || {}).columns ? m.tables[0].columns.length : 0,
    hasSql: !!((m.tables || [])[0] || {}).sql
  };
})()
```

### 5.2 验证报表与筛选器
```js
(async () => {
  const id = '<报表ID>';
  const r = await fetch('/iuap-data-analytic/report/design/' + id + '?isAjax=1&serviceCode=report-51&locale=zh_CN&systenant=<租户>&_t=' + Date.now(), {credentials:'include'});
  const j = await r.json();
  const am = (j.data || {}).analysisModel || {};
  const fs = (am.filterModel || {}).filters || [];
  return {
    ok: j.status === 1,
    filters: fs.map(f => ({ label: f.label, type: f.iType, binds: (f.paramsBindOut || []).length }))
  };
})()
```

> 判据：`filters.length` 等于期望个数，且每项 `binds >= 1`。
> **不要查 `filterDatas`**，那是另一个字段，常常是 `{}`（见 09 §5.2）。

### 5.3 验证画布（表头 + 字段行）
```js
(() => {
  const el = document.querySelector('.handsontable');
  const fk = Object.keys(el).find(k => k.startsWith('__reactFiber'));
  let fiber = el[fk], hot = null, guard = 0;
  while (fiber && guard++ < 30) { if (fiber.stateNode && fiber.stateNode.hotInstance) { hot = fiber.stateNode.hotInstance; break; } fiber = fiber.return; }
  return {
    headers: hot.getDataAtRow(1).slice(0, <列数>).map(c => (c && c.v !== undefined ? c.v : c)),
    fields: hot.getDataAtRow(2).slice(0, <列数>).map(c => (c && c.v !== undefined ? c.v : c))
  };
})()
```

## 6. 已知失败模式（出现即判 FAIL，并对照 09 的对应坑）

| 现象 | 判 FAIL 的判据 | 对照 |
|---|---|---|
| 表头/字段行刷新后消失 | 刷新后 `getDataAtRow(1/2)` 为空 | 09 坑 5（只走了内存 API） |
| 表头挤在 A2 一个格 | `row1[0]` 是含 `\t` 的长字符串 | 09 坑 4（纯文本剪贴板） |
| 参数绑定下拉缺参数 | 下拉选项数 < 模型参数数 | 09 §5.1（没在「分析参数」确定） |
| 筛选器查得到但 `filterDatas` 为空 | 只看 `filterDatas` 会误判 | 09 §5.2（查错字段） |
| 预览 0 行 | 页脚「共 0 条」 | 09 §3.14（参数空值/`$$$`） |
| 保存后弹「是否应用改动」点「是」无反应 | 弹窗不消失 | 09 坑 12（点否再保存） |
