# 保存规则链更新特征字段超时

## 问题描述

在单据保存后，根据单据信息更新特征组某个字段。实现方式是配置规则链在保存动作，调用后端 Java 规则类。

代码部署到目标环境后，点击保存会报超时。把更新特征字段的处理改成异步的就能正常保存。

同样是调用批量更新特征的方法，同步调用几万毫秒，异步调用几十毫秒。

## 原因

在单据的保存规则链保存后调用 API 接口更新特征项，此时标品单据保存更新 SQL 事务还未提交，单据的特征表还有锁，因此接口无法更新对应特征表字段，造成 SQL 事务间锁等待。

## 解决方案（三选一）

1. **推荐**：在保存规则链，标品单据保存规则**前**把特征数据组装到标准单据数据里（可保持数据与事务一致性）。
2. 规则链里单据保存后做异步处理。
3. 在单据保存事务提交后，在单据前端调用更新特征处理（会造成多次刷新）。
