# 保存、校验与业务流的新增/删除

> **接单入口**：刚接到业务流任务，先读 `06-接单流程-从任务到确认单.md`；本文是配置阶段的参考。

## 一、保存业务流

**保存按钮在设计器右上角**：`.design-header` 里 `innerText === '保存'` 的 `span`
（**没有 fieldid 也没有 class**，要先用 `browser_eval` 按文字找到它再加临时属性定位）。
旁边是「属性设置」。

保存成功后页面会弹提示，用 `browser_messages` 读：实测返回 **「✓ 成功」「✓ 更新成功」**。

### 校验：核心单据的交易类型不能为空

**这是保存失败最常见的原因**。页面弹「**核心单据的交易类型不能为空**」。

排查过程（记录下来，省得下次再绕）：
- `knowledge_search` 查这句文案 → **平台参考库里没有**。
- 到前端 JS 里找：`performance.getEntriesByType('resource')` 能列出
  `.../businessflow/static/js/app.983532.js` 等；在里面搜到 i18n key
  `UID:P_BIZFLOW-FE_17C72704042000E5` = 这句文案，变量名 `billType`。
- **但 `billType` 在整个 app.js 里只出现一次（只有定义、没有引用）** → 说明这条校验**在后端**，
  前端只是负责把后端返回的消息弹出来。

**结论：交易类型只能在「规则」里设置**：
- 「属性设置」面板**没有**交易类型字段；
- 节点属性面板的交易类型下拉**永远是 `disabled` + placeholder「请到规则中设置交易类型」**。

**解法**：打开**以核心单据为某一端的那条规则** → 基本信息 → 设置**来源交易类型**或**目标交易类型**。

操作步骤：

1. 点画布连线名 `#designer div.rule-name` 选中那条边 → 右侧 `.relation-item` 出现规则卡片
   （此时会显示 `引用规则编码 : <code>`）。
2. 点「编辑」`[fieldid="businessFlowFe_designEdge_handleItem1"]`。
3. 在基本信息页点开交易类型下拉：`[fieldid="businessFlowFe_designBaseInfo_se2"]`（来源）或
   `..._se3`（目标），它是 `div.el-select.bill-theme-setting.el-select--small`。
4. 选好之后点「确定」`[fieldid="businessFlowFe_designRuleIndex_btn2-saveHandle"]` 保存规则。
5. 再点右上「保存」保存业务流。

> ⚠️ **判断"有没有选上"的坑**：`el-select` 选定后 **`input.value` 仍然是空字符串**，
> **只有容器 `innerText` 才反映已选值**。
> ```js
> document.querySelector('[fieldid="businessFlowFe_designBaseInfo_se2"]').innerText  // ✅ 反映已选值
> document.querySelector('[fieldid="businessFlowFe_designBaseInfo_se2"] input').value // ❌ 恒为空
> ```
> 用 `input.value` 判断会误判成"没选上"，然后反复重选。

**交易类型设在"哪一侧"没有固定规矩**：预置流设在来源侧、实测的自定义流设在目标侧，
两种都能通过校验。**把核心单据那一端的交易类型填上就行**。

## 二、新增业务流

### 前提：必须在「其他」分类下

左侧云分类里，每个云下都有「预置」和「其他」两个叶子。

- 选**「预置」**时，「新增」按钮 `button.businessflow-list-table-addbtn`
  （fieldid `businessFlowFe_businessFlowList_list_add`）是 **`disabled=true`**；
- 切到**「其他」**（点 `.menu-tree` 里文本为「其他」的 `A.wui-tree-node-content-wrapper`）后按钮可用。

### 新增弹窗

点「新增」后出现 `.wui-modal-content`，标题「新增」，表单是 `form#businessflowlistaddform`：

| 字段 | 选择器 | 说明 |
|---|---|---|
| **名称** | `input[fieldid="businessFlowFe_businessFlowList_list_add_name_requireNoAutoComplete"]` | 必填，maxlength=200，placeholder「请输入名称」 |
| **编码** | `input#code` | 必填，placeholder「仅支持/字母/数字/下划线，不能以下划线开头」 |
| 启用业务泳道 | `.wui-switch` | 默认 off。**开着会让「触发设置」的前 5 个时机可选**（见 `02` 第四节） |
| 按钮 | `.wui-modal-footer button` | 「取消」`wui-button-secondary` / 「确定」`wui-button-primary` |

> ⚠️ 名称输入框的 **`id` 是 `businessflowlistaddform`（和 form 同 id）**，
> 用 `#id` 定位不可靠，**用 `fieldid` 属性选择器**。

### 建完之后

- 列表首行出现新流，格式如：`TEST_XS_PSFH / 测试-普通销售（有发货） / -- / 已启用 / V1.0 / <当前用户> / <时间>`。
- **交易类型列显示 `--`**（因为还没配规则）。
- **新建流在设计器 URL 里用的是数据库主键（雪花 ID，如 `2651467514339393538`）；
  而预置流的 id 就是它自己的 GUID 编码**（如 `7c59f9e0-7db8-45a6-b432-fe189dcf9bbb`）。
  所以从列表点「设计」拿到的 `id` 参数，两种形态都可能出现。

## 三、删除业务流

> **硬规则（2026-10-18 血泪）：删除前必须先停用。**
> 直接删除启用中的流，平台可能不拦，但会留下 `DR=1 / STATUS=1` 的脏数据：
> 列表看不到，唯一性校验却仍把它算作占用（校验 SQL 只看 `STATUS=1`，不看 `DR`）。
> 实测两条测试流这样删掉后，一直占着「发出商品」，导致后续启用报 `000-533-020003`。

1. **先停用**：行悬停右侧「停用」→ 确认，确认 `status=false`。
2. 在列表里**点该行 `td:nth-child(2)`（名称列）**选中该行 → 底部工具栏出现
   新增/设计/停用/复制/编辑/日志/删除。
3. 点「删除」`[fieldid="businessFlowFe_businessFlowList_list_btn_delete0"]`。
4. 确认弹窗文案：「**是否删除？ 您确定要删除该流程，删除之后将不可恢复，是否确定？**」，
   按钮 `businessFlowFe_businessFlowList_list_delete_modal_modal_footer_cancel` /
   `..._modal_footer_ok`。
5. 点「确定」→ 列表刷新，该行消失。

**删除是不可恢复的**，确认前核对好是哪一条（尤其别在「预置」分类下误删 —— 虽然预置流本来就不给删）。

> 如果已经误删出 `DR=1 / STATUS=1` 的脏数据：这条流不会出现在列表，只能改库
> `UPDATE ... SET STATUS=0 WHERE ID=... AND DR=1`，或物理删除；改库前先 `SELECT` 确认。

## 四、列表上的其他操作

工具栏按钮：**新增**；**行悬停右侧**出现 设计 / 启用 / 停用 / 复制 / 编辑 / 日志；
选中行后的底部工具栏还有 删除 / 加入迁移清单。**复制入口在悬停行右侧，不要先点行再找底部工具栏。**

- **设计**：`window.open` **新开页签**进设计器。
- **复制**：以现有流为模板建一条新的（适合"照着某条流改一条"）。
- **停用**：`status` 置 false，业务流不再生效但配置保留。
- **日志**：流程日志。
- **加入迁移清单**：业务流支持跨环境迁移；平台提示（i18n）：迁移会涉及来源/目标单据、交易类型、
  特征/特征组、过滤/转换公式、工作流、消息模板等；**预置规则也支持迁移**；
  **以编码（code）作为业务唯一校验字段，相同 code 的视为同一个流程**。

## 五、版本与启用

业务流主体上有 `version`（如 `V1.0`）、`isVerSupport`、`isCurrentVersion` 字段。

**平台机制（使用者确认，2026-10-18）**：
- **没有独立「发布」动作**；
- **开启版本控制（`isVerSupport=true`）的流**：保存后变为未启用；**重新启用时会更新版本号**；
- **未开启版本控制的流**：保存后保持原启用状态（`_06` 实测仍 `status=true`），`version` 不变；
- 保存本身是否递增 `version`：实测 `_01` / `_03` / `_06` / `_07` 保存前后都是 `V1.0`，**未观察到保存时递增**——
  「更新版本号」发生在**重新启用**时。

**实测**：
- 「启用 / 停用」已验证：`status` 双向切换，`version` 不变（启用不是保存）；按钮是同一个，文字随状态变。
- 设计器头部只有「属性设置」「保存」；属性设置只有流程名称/创建人/时间——没有发布/生成新版本按钮。
- 列表「编辑」的版本控制开关是 `disabled`，不能补开。
- `_06`（收款复制流，`isVerSupport=false`）保存后仍 `status=true`、`version=V1.0`；
  `_07`（普通销售复制流，`isVerSupport=true`）保存后变 `status=false`、`version=V1.0`，
  但启用被交易类型校验拦住，未测到重新启用后的版本号。

详见 `08-启用与发布-实测.md`。
