## 1. 十条主干流程（按顺序做）

### 1.1 建语义模型
1. 数据工场 → 智能分析 → 语义模型（DIRSEMANTIC）
2. 「新建文件夹」建测试目录（如 `测试目录`）：**先选中父目录** → 点按钮 → 出现 `#multiInputName` 输入框 → **真实键入**名称 → Enter
   - 建完**不一定**立刻出现在树上：它挂在你当时选中的那个父目录下，**展开父节点**才看得到。
   - 别用"刷新页面"去确认（会退回工作台首页）；用「列表里有没有」或展开父节点判断。
3. 进目录 → 「新增」→ 填编码/名称/**数据源** → 确定

**数据源选择**：下拉是**树形**，默认只显示根节点「系统数据源」。
必须点根节点左侧的展开箭头（`.wui-select-tree-switcher`）展开，再点子数据源（如 `TP查询仓-公共`）。

> ⚠️ **坑 1：点「确定」没反应、不发任何请求。**
> 根因：`语义模型名称` 是多语言输入组件，用原型 setter（`browser_set_value`/`fill`）只改 DOM、
> 不进组件 state，`onOk` 里 `valueList[locale]` 为空 → 提示"请输入语义模型名称"并 return。
> **解法：名称必须用真实键盘输入（`browser_type`），不要用 set_value。**

**哪些框认 setter、哪些不认**（照这张表判断，不用每次试）：

| 控件 | 原型 setter | 正确做法 |
|---|---|---|
| 普通编码 / 数值 / 文本 input | ✅ 认 | `Object.getOwnPropertyDescriptor(proto,'value').set` + `input`/`change` 事件 |
| **多语言名称组件**（模型名、文件夹名、报表模板名、列表页重命名） | ❌ 静默不进 state | `focus()` → `select()` → **`browser_type`** |
| 筛选器「基本属性 → 名称」 | ❌ | 同上，`browser_type` |
| 树形下拉 / 目录树选节点 | ❌（`el.click()` 只高亮） | **真实点击** title（`browser_click`） |

> 规律：**凡是"名称"类（背后是多语言 `valueList[locale]`）一律真实键入；凡是"树/下拉"里选值一律真实点击。**
> 用错的表现统一是"看着填进去了、提交时打回原形或干脆没反应"，且**不报错**。

### 1.2 写 SQL 脚本表
1. 设计器里「添加SQL脚本」→ 打开「语义脚本编辑器」抽屉
2. 填表名（`t_xxx`）、表显示名
3. CodeMirror（`.cm-content`）里填 SQL：先 `focus()` + `Range.selectNodeContents` 选中全部，再 `browser_type` 覆盖
4. 点「执行」→ 弹「执行数据模型」参数框 → 留空点确定 → 看「查看数据」
5. **失败要抓响应**：`execSQL` 返回 `status:1` 只代表解析成功；数据为空要再排查（见 §3.14）
6. 点「确认并返回」回主界面（**不是「确定」**，「确定」不关抽屉）

> ⚠️ **坑 1b：「执行」出来的数据预览只截断 100 条** —— 页脚永远写着「共100条」，
> 不管是全量查询还是 32 万行，都显示 100。**不要拿它断言行数**，会直接得出"只有 100 行"的错误结论。
> 断行数只能靠：① 在抽屉里跑一条 `SELECT COUNT(*)`；② 报表预览页脚的「共 N 条」。

### 1.3 选字段
主界面「下一步」×3（选择表 → 连接条件 → 选择字段），字段会自动列出；
点「下一步」到「5、选项」再点「保存」。

> 字段保存在 **`tables[0].columns`**（表级），不是 `model.columns`（模型级）。查接口时别看错位置。

### 1.4 声明参数（关键坑密集区）
入口：**先点一下表名单元格**（`.editable-cell`）→ 行尾才渲染出「编辑 / 删除」→ 点「编辑」→
语义脚本编辑器 → 顶部「**参数**」（`fieldid=execute_param`）

> `.editIcon`（铅笔）是 `display:none`，**不是入口**；点字段文本、双击、hover 都不会出「编辑」按钮。
> 主界面工具栏那个「参数」按钮打开的是同一个「参数设置」弹窗，找不到行入口时可以用它兜底。

- 弹窗「参数设置」→ 「新增参数」（行内新增）
- **⭐ 填一个增一行**：必须先填当前行的「参数名称」，再点「新增参数」；
  **空行会阻塞新增**，表现就是"新增按钮点了没反应"
- 全部填完后点「确认」——**有空行时确认不关闭也不报错**
- 回到主界面必须点「**保存**」才落库

> ⚠️ **坑 1c：参数表格里第一个 `input` 是「勾选框」，不是参数名。**
> 每行 `querySelectorAll('input')` 的顺序是：
> `[0] 行勾选框  [1] 参数名称  [2] 值类型  [3] 必填  [4] 默认值类型  [5] 默认值`。
> 把值写进 `[0]`（我踩过）→ React state 里名称仍为空 → 再点「新增参数」**不加行**，
> 表面看就是"新增按钮坏了"。正确写法：取 `input.wui-input-md` 那个（第 1 个匹配），
> 且参数名称要用 `browser_type` 真实键入。

**参数默认值要核对**：弹窗里输入框按行排列，一次输入多个容易串位
（实测 `khbm` 的默认值被写成 `khmc`）。保存后用接口核对一遍：

```bash
GET /iuap-data-common/semantic/model/get/<模型ID>  →  data.model.params[].defaultValue
```

### 1.5 建报表（先落库再改名）
1. 数据工场 → 智能分析 → 报表设计（DIRREPORT）→ 进目录 → 「新增」
2. 抽屉里填名称 + 点「空白报表」卡片 → **进入报表设计器（默认名「报表x」）**
3. **⭐ 先点右上角保存图标**（`i.ap-baocun-011`，title=「保存」）—— 不保存这个报表"不存在"
4. 保存后 URL 从 `#/report/REPORT/new/...` 变成 `#/report/query/edit/<报表ID>`
5. 需要改名再去列表页「重命名」

> ⚠️ **坑 2：点「空白报表」后列表里没有新报表。**
> 不是没建成，而是进了设计器且**未保存**；到设计器里点保存就落库了。

> ⚠️ **坑 2b：抽屉里那个输入框（placeholder「请输入模板名称」）填的**不是**报表名。**
> 填「客户情况统计表」也没用，报表建出来照样叫「报表1」、页面标题也是「报表1」——它是**模板名称**。
> 报表名只能事后到列表页「重命名」。

> ⚠️ **坑 2c：列表页「重命名」弹窗里没有「确定」按钮。** 填完名直接按 `Enter` 提交
> （实测 Enter 生效、列表立刻刷新成新名字），别在弹窗里找按钮。

### 1.6 挂数据集
1. 左侧字段区「添加模型」→ 弹「选择模型」
2. 顶部页签切「语义模型」
3. **⭐ 左侧是目录树**：默认只显示某个分类；**点「测试目录」**，右侧才出现该目录下的模型
4. 点模型行（`.list-metas`）→ 右侧出现字段清单 → 勾「全选」→ 点「确定」

> ⚠️ **坑 3：对话框里找不到自己刚建的模型** —— 90% 是没切左侧目录，不是模型没建好。

### 1.7 写表头（必须走 HTML 剪贴板）
用 Clipboard API 写入 `text/html` 表格，再走设计器的「编辑 → 粘贴」：

```js
const headers = ['列1','列2', ...];
const html = '<table><tr>' + headers.map(h => '<td>' + h + '</td>').join('') + '</tr></table>';
await navigator.clipboard.write([new ClipboardItem({
  'text/html':  new Blob([html], {type:'text/html'}),
  'text/plain': new Blob([headers.join('\t')], {type:'text/plain'})
})]);
```

然后：选中 A2（`hot.selectCell(1,0)`）→ 点顶部「编辑」→ 点「粘贴」→ 保存。

> ⚠️ **坑 4：粘贴后 15 个表头挤在 A2 一个格子。**
> 根因：纯文本剪贴板（`Set-Clipboard` / `text/plain`）进来就是一段字符串；
> **必须给 `text/html` 表格**，设计器才按表格分列。
>
> ⚠️ **坑 5：`hot.setDataAtCell` / `populateFromArray` 写进去的内容保存不下来。**
> 只在内存生效、刷新即丢。**只有设计器自己的「编辑→粘贴」通道才会落库。**
>
> ⚠️ **坑 6：`navigator.clipboard.write` 报 `Document is not focused`。**
> 先把页面切到前台（`browser_activate`），再写剪贴板。

### 1.8 绑定字段行
1. 选中目标起始格（如 A3，`hot.selectCell(2,0)`）
2. 「插入」→「绑定字段」→ 弹「批量字段绑定」
3. **⭐ 点左侧字段行右侧的「+」图标**（`i.ap-tianjia`，y 坐标在字段区内），字段才进右侧「已选」
4. 右侧 `排列方式` 默认「从左到右」，保持即可
5. 点「绑定」

> ⚠️ **坑 7：点字段名/双击/点节点行都不进右侧** —— 必须点行尾的「+」。
>
> ⚠️ **坑 8：加号点完不消失。** 循环点"第一个 +"会把同一个字段加 N 遍；
> **必须按字段索引点**：第 i 次点当前可见 `i.ap-tianjia` 列表里的第 i 个。
>
> ⚠️ **坑 9：绑定起点是"当前选中单元格"**。选 B3 绑 15 个字段，就铺到 B3:P3，
> A3 保留原值、整体错位。**先选对起始格再绑定。**
>
> ⚠️ **坑 10：清空错行** —— `hot.clearContent()` 不生效；**选中区域后按 `Delete` 键**才清。

### 1.9 加筛选器
1. 「插入」→「自定义筛选器」→ 右侧出现「<类型> 设置」面板
2. **改类型**：筛选器类型下拉 —— **点它的 `input`（`#rc_select_*`），不是点容器/箭头**；
   展开后是 9 种：树形下拉/下拉/树形参照/日期/左树右表/参照/平铺/输入框/系统参照

   > ⚠️ `#rc_select_N` 的**序号每插一个筛选器就变**（实测用过 `rc_select_10` / `_17` / `_31`），
   > **不能缓存 id**，每次都要按"当前面板里值等于『下拉』/『输入框』的那个 input"重新定位。
3. **改名称**：基本属性 →「名称」输入框 —— 合成事件不认，**必须 `browser_type` 真实键入**
4. **填值字段**：输入框类筛选器显示「值字段：拖入维度或度量」，只认**真实 HTML5 拖拽**：

```bash
node ~/.dsh/yon-panel/scripts/drag-node.mjs "<页签片段>" "#源字段" "#拖放区"
# 成功输出：DROP_DONE, target now: <字段名>
```

5. **参数绑定**：数据设置 →「参数绑定」→ 弹窗 →「添加」→ 三列：
   - 参数：选模型参数编码（如 `khbm`）
   - 来源类型：`筛选器字段`
   - 值：`默认`
   → 「确定」

> ⚠️ **坑 11：参数绑定弹窗里的下拉点开却是"筛选器类型"的 9 个选项。**
> 根因：`y` 坐标相同的多个 `.wui-select` 撞在一起，按坐标匹配会命中画布上的下拉。
> **解法：在弹窗容器内取 `.wui-select` 再按下标定位**，不要跨全页按坐标找。

6. **筛选器落在哪**：插入后的控件是**画布上方的浮层**，不在 Handsontable 网格里（`hot.getDataAtRow(0)` 是空的，
   别以为插入失败）。切到「筛选」tab 就能看到控件排在画布顶部。判"配没配上"以接口为准：
   `GET /iuap-data-analytic/report/design/<报表ID>` → `analysisModel.filterModel.filters[i]`，
   `iType` = `TEXT`（输入框）/ `DROPDOWN`（下拉），`paramsBindOut.length` = 1 才算绑上。

## 2. 数据源方言与取数约束（最容易整段白写）

报表挂在「TP查询仓-*」上时，它是 **MySQL8**，与达梦业务库不同：

| 差异 | 达梦（业务库） | TP 查询仓（MySQL8） |
|---|---|---|
| 表引用 | `iuap_apdoc_coredoc.merchant` | **同样要写 schema 前缀**，裸表名 `Table not found` |
| 类型转换 | `TO_CHAR(x)` | `CAST(x AS CHAR)` |
| 中文别名 | 直接写 | **必须反引号** `` `客户编码` `` |
| 校验 | `datasource_query` 连的是业务库 | 只能用设计器「执行」验证 |

> 先用「添加SQL脚本 → 执行」跑一条 `SELECT COUNT(*)` 确认表在前缀下存在，再写整段 SQL。

### 2.1 枚举列整列取空：**先怀疑字段说明写错了，去问人**

> 🔴 **这不是"TP 仓字典表残缺"的机制性规律，别照上一版理解**（2026-10-18 使用者纠正）：
> 枚举缺失属于**数据/口径问题**，很可能是**需求文档给的字段说明本身错**（指错了表、指错了关联键）。
> 遇到就**去找使用者核实这个字段该从哪取** —— 不要自己猜一套 CASE 硬编码糊上去当结论。

典型**现象**（本次实例，不是规律）：

```text
业务库：iuap_apdoc_basedoc.bd_cust_enum  → 证件类型枚举全在（custenumdefid='2080195409054531634' 有 11 条）
TP 仓：同一张表只有 142 行，且**没有这条枚举定义** → 表在、字段在、JOIN 却不报错、结果恒为空
```

现象：枚举列（证照类型、账号类型、各种 `bd_*_enum`）**整列为空，SQL 不报错、执行 status 正常**。

**判据**：某一列全空，而业务库里这列明明有值 → 先在抽屉里「执行」一条
`SELECT COUNT(*) FROM <枚举表> WHERE <定义ID>`。返回 0 = 这张表/这个定义ID 在报表用的仓里取不到。

**但取不到的原因有三种，别默认是第三种**：

| 原因 | 特征 | 处理 |
|---|---|---|
| ① 字段说明指错了表 | 确认单/字段说明给的表、关联键与元数据对不上 | **找使用者核实口径**（首选） |
| ② 关联键类型/格式不符 | 表里其实有数据，是 `id` 与 `code` 混用、大小写或补零差异 | 打印两侧样本值比对 |
| ③ 该仓确实没同步这张表 | 同一条查询在业务库与目标仓结果不同 | 也先回去问口径，再谈同步 |

**临时兜底**（只有在①核实完毕、业务方认可"先这么出"时才用）：
1. 可以退化成 `CASE` 硬编码，但**必须把值域从库里打出来**（`datasource_query`），不要凭记忆写；
2. 要在交付说明里注明"此处为临时映射，未经字典联动、字典变更需同步改 SQL"；
3. 别把它写成通用规律 —— 换个字段，①往往才是真因。

> 本次实例留档：证件类型在业务库 `bd_cust_enum`（`custenumdefid='2080195409054531634'`）有 11 条，
> 同名查询在 TP 查询仓返回 0 条、该表整表只有 142 行。**按使用者判断，这是数据/口径问题（很可能字段说明指错），
> 不是平台设计** —— 所以最终做法（CASE 硬编码）只是本单的临时处置，不是标准姿势。

> 同批实证：TP 仓 `merchant` 是 **323,504 行**（与业务库一致）。
> 上一版文档写的「TP 仓 60,002 行」是错的，已作废 —— 断言行数前一定自己跑一次 `COUNT(*)`。

### 2.2 「执行」用的是哪个库？怎么自证

抽屉里点「执行」跑的是**模型配置的那个数据源**（本模型 = `TP查询仓-公共`），**不是** `datasource_query` 连的业务库。
两者结论不一致时，先确认这一点，否则会把"库不同"当成"SQL 写错"。

**硬证据法（推荐）**：找一条**两个库必然不同**的查询分别跑一遍，看结果是否分叉。

> 本次实例：`SELECT COUNT(*) FROM iuap_apdoc_basedoc.bd_cust_enum WHERE custenumdefid='2080195409054531634'`
> —— 业务库 `datasource_query` 返回 **11**，抽屉「执行」返回 **0**。两个数字不一致，就证明「执行」没走业务库。

`SELECT DATABASE()` 之类**直接自证**的办法：**尚未验证**（方言与仓类型不统一，别依赖），
所以先用上面的"差值法"兜底。

### 2.3 ⭐ 开发规范：**分页报表必须带稳定排序**（2026-10-18 定）

报表按页翻的时候，SQL 里**没有 `ORDER BY` 就不保证行序稳定** —— MySQL 不承诺返回顺序，
几十万行翻到后面可能出现**行重复或漏行**，使用方按页核对会对不上，而且**不会报错**。

**写法**：`ORDER BY <唯一且基本非空的键>`，一般用编码（如 `ORDER BY m.cCode`）。
不要按名称、时间、金额这类可能重复或为空的列排 —— 那不是稳定排序。

```sql
-- 放在 WHERE 参数块之前
ORDER BY m.cCode
```

> 例外留档：本次「客户情况统计表」首版**未加排序**，按使用者要求不回头改；
> **之后新开发的报表一律加**。所以本文件其余示例里没写 `ORDER BY` 的，都要自己补上。

## 5. 报表侧几个"隐蔽但必须"的配置（2026-10-18 实证补充）

### 5.1 报表参数必须先引入「分析参数」，否则参数绑定下拉里选不到

> ⚠️ **这条的因果未完全验证**（2026-10-18）：本次 4 个筛选器做完、参数绑定弹窗里**第一次打开就已经有全部 4 个参数**，
> 也就是说没做「分析参数」这一步它也是全的。所以「分析参数」更可能是**给报表加"可选参数"入口**，
> 而不是"参数绑定下拉能选到参数"的前提。**照做无害**（点一次「数据 → 参数 → 分析参数 → 确定」成本很低），
> 但不要把它当成"缺参数"的唯一解释 —— 真缺参数时先查 §5.2 的 `paramsBindOut` 和模型 `params`。

现象（上一轮实证）：模型有 4 个参数，报表「参数绑定」下拉只显示 3 个，缺的那个怎么都刷不出来
（「更新模型」做了、整页刷新也做了，都没用）。

正确入口：**顶部「数据」→「参数」→ 面板切到「分析参数」页签 → 点「确定」应用**。
应用之后，参数绑定下拉里 4 个参数就全了。

> 「模型参数绑定」页签里能看到 4 条（`客户情况统计 / 等于 / khbm …`）不代表报表已把它们变成可选参数；
> 真正让筛选器能选到的是「分析参数」页签被确定过。

### 5.2 筛选器的落库位置是 `analysisModel.filterModel.filters`，不是 `filterDatas`

查落库状态时别查错字段（我为此误判过两次"筛选器没保存"）：

```text
GET /iuap-data-analytic/report/design/<报表ID>
  data.analysisModel.filterModel.filters   ← 真正的筛选器数组
  data.filterDatas                         ← 常常是 {}，不代表没保存
  data.filterSchemas                       ← 同上
```

每个筛选器的关键字段：

| 字段 | 含义 |
|---|---|
| `label` | 显示名（页面上看到的名称） |
| `code` | 筛选器编码（拖的字段名；改名不会同步改它） |
| `iType` | `TEXT` = 输入框、`SELECT` = 下拉… |
| `paramsBindOut` | 参数绑定：[{paramId, value, valueType:"FIELD"}]，`paramId` 是**报表侧参数 id**（不是模型 uid） |
| `from` | 数据集 id |

> 判断"筛选器是否生效"看 `paramsBindOut` 长度，不是看 `label` 或 `code`。

### 5.3 参数绑定三列的实际取值

| 列 | 取值 | 说明 |
|---|---|---|
| 参数 | `khbm` / `khmc` / … | 模型参数编码 |
| 来源类型 | `筛选器字段` | 另有 系统变量 / 权限标签 / 常量 |
| 值 | 该筛选器自己的名称（如「客户编码」） | 选了「筛选器字段」后，值列列出的是**当前报表的筛选器**，选自己 |

### 5.4 实验证过的完整链路（金隅客户情况统计表）

- 模型 `KHQKTJ` + 4 参数 → 报表挂数据集 → 15 列表头 + 15 字段绑定 → 2 个输入框筛选器

- **预览成功，返回 323,504 条 / 6471 页，字段值正确**（客户类型=通用客户、客户分类=内部/外部、账号类型=对公账号）
  —— 注：上一版这里记的「60002 条 / 1201 页」经复核是错的，已作废。

**下拉类筛选器已验证通过**（2026-10-18 第二次实证，接续上文）：
「下拉设置」区块里那个**没有标签、值显示为「自定义」的下拉就是「来源」**（DOM：`.filter-settings-panel .wui-select`，
`input[value="自定义"]`）。点它 → 选项只有三项 **数据模型 / 自定义 / 接口** → 选「数据模型」后，

## 9. 判据速查：**"看不到"≠"没成功"**

这是本次开工最大的时间黑洞 —— 几乎每个"没生效"最后都只是**看错了地方**。
判断"成没成"，**只认这四种证据**：

1. `GET` 接口回来的定义（模型 `params` / `columns` / `sql`；报表 `filterModel.filters[].paramsBindOut`）
2. **刷新后内容还在**
3. 页脚行数与库上 `SELECT COUNT(*)` 对得上
4. 列表里出现了这一条

**界面上的"没出现"一律不算证据。** 对应速查：

| 界面现象 | 大概率不是失败，而是 | 正确判据 |
|---|---|---|
| 新建文件夹后树上没有 | 父节点没展开 / 树没刷新 | 展开父节点再看；刷新列表（**不要靠刷新页面确认，会退回首页**） |
| 表名行找不到「编辑」 | 还没点单元格 | 先点 `.editable-cell`，行尾才渲染「编辑 / 删除」 |
| 「新增参数」点了不加行 | 名称写进了勾选框（行内第 1 个 `input`），React state 仍是空 | 写 `input.wui-input-md` 那个 + 真实键入，见 §1.4 坑 1c |
| 树形下拉点节点没选中 | DOM `click()` 只高亮 | 真实点击 title（`browser_click`），不要 `el.click()` |
| 「执行」页脚「共100条」 | 预览**恒截断 100 条** | 抽屉里跑 `SELECT COUNT(*)`，或看报表预览页脚，见 §1.2 坑 1b |
| 预览里没有筛选器控件 | 预览弹窗**不画控件**，只显示「已选条件」 | 设计态填值 → 预览看「已选条件: xxx:值」+ 行数，见 §6 |
| 报表名不是自己填的 | 抽屉里填的是**模板名称** | 列表页「重命名」，见 §1.5 坑 2b |
| 刷新后回到工作台首页 | 子应用页刷新就是退栈 | 不是环境问题，重新从首页进，见 §0 |
| 打开页面纯白、无报错 | `serviceCode` 拼错 | 从「最近使用」进，抄地址栏里的真实值，见 §0 |
| 预览白屏 / 一直转圈 | 32 万行要 13～15 秒 | 等页脚出现「共 N 条」，见 §1.10 坑 12c |
