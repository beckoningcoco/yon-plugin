> 实测：2026-10 ~ 2026-10-11，金隅共享 `dev-fssc.bbmg.com.cn`，旗舰版 `U8C3`。
> 关联：[[00-设计器总览与操作纪律]]（§4 是本文的早期版本）、[[06-超链接跳转与跨表传参]]、[[03-表样结构操作与结果验证]]

## 1. ⭐ 判据纪律：只读权威源

### 1.1 本会话犯的 4 次误判（同一个病）

| 我看到的 | 我据此判断 | 真相 |
|---|---|---|
| 填了日期，汇总表「账户总数」还是 287 | 源表筛选器不生效 | **没点「查询」** —— 平铺模式不自动重查 |
| `analysisModel.links` 是 `[]` | 超链接没保存 | **路径错了**，真身在 `sheets[0].areas[0].setting.links` |
| hook 里没有 `report/save` 记录 | 保存失败 | hook 写漏了一行，请求被**原样放行**；界面弹的"保存成功"是真的 |
| 点「修改」后没抓到请求 | 保存失败 | 同上 —— **拿 hook 当判据本身就是错的** |

四次都是同一类：**拿间接信号当结论**。

### 1.2 规则的表述

> **间接信号一律不算证据。**
> DOM 变没变、hook 记没记到、界面弹没弹提示、元素可不可见 —— 都不能单独推出结论。

**只读权威源**：

| 问题 | 权威源 |
|---|---|
| 配置改了没 | 服务端定义：`GET /iuap-data-analytic/report/design/<报表ID>`、`GET /iuap-data-common/semantic/model/get/<模型ID>` |
| 数据对不对 | **直接查库**（`datasource_query`），别信界面上的数 |
| 页面渲染出多少条 | **数它渲染出来的数据行**（`table tbody tr` 里文本非空的行数），别数 DOM 节点总数 |
| 参数进没进报表 | `analysisModel.params` 里搜参数名 |

### 1.3 界面提示也要打折

- **"保存成功"是真的、而你的 hook 没记到** —— 本会话两次栽在这。
- **"失败"也可能是假的**：报「当前文件被其他人锁定编辑」时，内容其实已经在服务端了（乐观锁冲突）。
- 所以：**提示只当作线索，最终一律回权威源核对**。

## 2. 定位元素

| 手法 | 说明 |
|---|---|
| **打临时标记** | 用 `browser_eval` 给目标加 `data-z="x"`，再点 `[data-z="x"]` —— 避免同一选择器命中多个、或点错同行的另一个控件（本会话在一行 6 个控件里点错过好几回） |
| **按文字找，不按坐标** | 视口 2552px，坐标随滚动/布局变；用 `textContent.trim() === '确定'` 这类精确匹配 |
| **多个候选取"最后一个可见的"** | `.wui-select-dropdown` 会残留旧的；过滤可见后取 `[length-1]` |
| ⭐ **判"可见"不能只看 `offsetParent`** | 关闭的菜单/弹层只是被挪到 **`(-9998, -9998)`**，`offsetParent` **仍然非空**。要连矩形一起看：<br>`const b = e.getBoundingClientRect(); b.width > 0 && b.height > 0 && b.left > -1000 && b.top > -1000`<br>（本会话就在这儿先写错了一版，`ui-probe` 对着数据显示 `MENUS(1)` 才发现） |
| **画布单元格** | `.ht_master tbody tr` 第 N 行 → 该行 `td` 第 M 个。表样 `[5][3]` = `trs[5].querySelectorAll('td')[3]` |
| **别用 `document.querySelectorAll('tr')` 找画布** | 画布内容不在普通 `tr` 里，会一无所获；用 `.ht_master` 收窄 |
| **`innerText` vs `textContent`** | 对 `offsetParent === null` 的元素 `innerText` 常为空；收集选项/文字用 `textContent` |

## 3. 点击：点不动时按顺序换手段

⭐ **这四种手段已经内置进 `browser_click` 的 `mode` 参数**（`real` / `dom` / `seq` / `react`），
不必再手写页面脚本，也不必再跑 `ui-click.mjs`：

| 现象 | 手段 | `mode` | 备注 |
|---|---|---|---|
| 默认 | **CDP 真实指针** | `real`（默认） | 绝大多数控件要的就是它 |
| 点了没反应 | **`el.click()`** | `dom` | 原生 DOM 点击，React 的 root 委托能收到。本会话「参数」「保存」按钮都是这样点开的 |
| `el.click()` 也不行 | **完整事件序列** `mouseenter → mouseover → mousedown → mouseup → click` | `seq` | 只发 mousedown/click 常常没反应；补上 mouseenter/mouseover 才通（实测「值」下拉） |
| 还不行 | **React props 直调 `onClick`** | `react` | 沿祖先最多找 8 层 `__reactProps$`。实测用友 wui **对合成 DOM 事件不响应、对这条路响应**的场景（语义模型的行操作菜单） |
| 状态敏感的元素 | **真实指针 + 不做 scrollIntoView** | — | 画布、右键菜单；仍要 `real-click.mjs`（工具版的 `real` 会先 scrollIntoView） |

⚠️ **不要"四种一起试"** —— 这些点击基本不幂等，全试一遍等于把一次操作做成三次。按上表**从上往下**换。

### 3.1 hover 才展开的子菜单 / hover 才出现的按钮

用友这套 UI 里有大量**只在悬停时才渲染**的东西：

- 菜单里右侧带小三角的项是**子菜单触发器** —— **点击只会把整个菜单关掉**，必须真的把鼠标移上去停住；
- 语义模型列表的行操作（`重命名 / 复制到 / 移动到 / 更多`）也只在行被悬停时进 DOM，指针一走就消失。

用 **`browser_hover`**：两段式 `mouseMoved`（先落到目标左侧 30px → 停 120ms → 落到中心 → 默认停 900ms），
做的事和 `hover.mjs` 一样，但在工具层。

⚠️ **悬停后指针就留在那儿了**：

- 要读 DOM 只能用 `browser_eval`（它不移动指针）；
- **不能再 `browser_click`、也不能再 `browser_hover`** —— 一移动指针，悬停渲染出来的元素立刻消失
  （连 `data-z` 这类临时标记也会随 DOM 重渲染一起没）；
- 悬停是**共享指针**的状态：使用者自己动一下鼠标、或者切页签，同样会结束它；
- ⚠️ **"连续 hover 同一个目标"不算一次进入**：hover 渲染靠的是元素上的 `mouseenter`，而它只在指针
  **离开过又进来**时才发生。指针**本来就已经停在目标上**（最容易发生在"刚在某行的输入框里按过回车"
  之后），两次移动都落在元素**内部** —— 一个 `mouseenter` 都不会产生，元素会带着 `:hover` / `-hover`
  类却**什么都不渲染**，看 DOM 会误判成"这个控件没有操作按钮"。
  **修法**：先把指针移到**别处**再悬停（`browser_hover` 已按此改：每次都先到中性角 `(1,1)` 再进入目标；
  实测连续 hover 同一行三次，改前第 2 次起失效、改后三次都正常）。
  所以"新建完一行之后悬停没反应"**不是新行的问题**——是因为指针正停在那一行里，先让指针离开再回来；
- 返回的 `hitTag/hitText` 是**指针底下真实是谁**，用来发现"以为悬停在 A、其实落在 B"
  （浮层、固定列、滚动后失效的坐标都会造成这个）。

> 另一半问题——"按钮要悬停才渲染，于是点击时它还不存在"——用 `browser_click` 的 **`hoverMs`** 解决：
> 移动指针后、按下之前先等 N 毫秒（200–500 通常够），模拟真人"移过去 → 看到按钮 → 再点"。

### 3.2 拖拽：`browser_drag`，两档不可互换

```text
browser_drag  page=<页面> from=<源> to=<落点> [mode=html5|mouse] [steps=12] [stepMs=60]
```

- **`mode:"html5"`（默认）** —— `draggable="true"` 的源，报表设计器把字段拖进画布 / 拖进「值字段」就是这一档。
  走：`Input.setInterceptDrags(true)` → `mousePressed` → 12 步 `mouseMoved` → 等
  **`Input.dragIntercepted`** 拿到它携带的数据 → `dispatchDragEvent` 依次 `dragEnter`/`dragOver`/`drop`。
- **`mode:"mouse"`** —— 滑块、表格拖拽排序、画布平移这类监听 `mousedown`/`mousemove`/`mouseup` 的拖拽。
- ⚠️ **选错时页面不报错，只是什么都没发生**。所以返回值里有 `intercepted`：
  `html5` 模式下它必须是 `true` 才说明真的搬运了数据；拿到 `false`（或工具直接抛错）就改用 `"mouse"`。
- ⚠️ **两端必须同时在视口里**。CDP 的指针坐标是视口坐标，看不见的地方拖不到。工具会先滚到**源**，
  再一次性量两端；若落点因此落到视口外，它会**明确拒绝并说明**，而不是默默拖空。
- ⚠️ 在页面里合成 `DragEvent`（`dispatchEvent`）**没有用**：`isTrusted=false`，设计器的落点不认它。

**实测判据**（自造一个 `dragstart` 写入 `dataTransfer`、`drop` 再读出来的页面即可复跑）：
`dragstart`/`dragover`/`drop` 三个事件都触发，且 `drop` 时能取回 `'HELLO-DRAG'` 这类原样写入的数据。

### 3.2 打开菜单 + 点菜单项要在**同一次** `browser_eval` 里做完

菜单失焦即收起，分两次调用必失败。写法：先给菜单项派发 `mouseenter/mouseover` 开菜单，
再在同一个表达式里 `.click()` 那一项。

## 4. 下拉与选择器

| 场景 | 做法 |
|---|---|
| 普通 select | 点 `.wui-select-selector` 即可展开 |
| 自定义下拉（如「参数赋值」的「值」列） | 它是 `div.wui-dropdown-trigger` 包一个 **`readonly`** `<input>`；用**完整事件序列**才能展开 |

## 5. 弹窗与模态

- **`offsetParent === null` 不代表不能操作。** 本会话「选择模型字段」「参数设置」「链接设置」都判定为"不可见"，
  可里面的按钮**照样能用 `.click()` 点**。按"不可见所以用不了"去判断会白绕一大圈。
- 判断"弹窗开着"用 `document.querySelectorAll('.wui-modal').length`，**不要**用可见性。
- 弹窗按钮用文字精确匹配：`确定` / `修改` / `取消` / `关闭`。
- ⚠️ **「当前对象已被引用，是否修改？」→ 必须点「修改」才真的保存**；点「取消」等于没保存。
  这个弹窗常在点保存后 1~2 秒才出现，**别急着下"没反应"的结论**。

## 6. 发送 / 拦截请求

### 6.1 铁律：不要自己拼 HTTP 请求

Content-Type、CSRF 令牌、版本号任一处不对，就会报
`Cannot invoke … getYtenantId() because … getObj() is null` 或「当前文件被其他人锁定编辑」。
本会话按抓到的格式**原样回放**都失败过。

### 6.2 正确姿势：搭平台自己的车

```text
1. hook：open 里把 url 记到 this.__u；setRequestHeader 里把 (k,v) 记到 this.__h；
        send 里检测目标接口，拦下请求体。
2. 在界面上做一次真实操作触发该接口 → 拦下来：解压 body → 改内容 → 重新压缩
3. 用**同一次的 url + headers + token** 新开一个 XHR 发出去。
```

**两个反复踩的坑**：

1. **重装 hook 时若新的 `open` 忘了写 `this.__u`**，拦截条件永远不成立、请求被**原样放行** ——
   而界面上的"保存成功"是**真的**，极易误判成"我的改动生效了"。
2. **拦截后平台的"未保存"标记会被清掉**，再点保存就不发请求了；要重发就用记下来的 url/headers 自己发 ——
   **发之前先把 hook 关掉**，否则连自己发的请求也被拦。

### 6.3 两个保存接口的 body 是同一套

```text
POST /iuap-data-analytic/report/save?…        报表定义
POST /iuap-data-common/semantic/model/save?…  语义模型
body: {"Datas": "<base64(gzip(JSON + xsrfToken))>"}
```

解压出来就是**整份定义的 JSON**；**尾部拼着** `xsrfIntellivSplitFIX_<token>!<数字>`，改内容时**必须原样保留尾部**。
具体路径与例子见 [[06-超链接跳转与跨表传参]] §7.4。

## 7. 脚本清单：哪些动作已经不用再手写了

这些脚本在 **`~/.dsh/yon-panel/scripts/`**（跨会话固定位置），**写一次、以后直接用**。
公共连接代码在 **`cdp.mjs`**（新脚本 import 它，别再抄第六遍）。

| 脚本 | 用途 |
|---|---|
| `activate-tab.mjs <片段>` | ⚠️ **已内置为 `browser_activate`**（`Target.activateTarget`，必须走浏览器级连接）。**只在"要动手改"的页面切，纯读不切**（见 `~/.dsh/AGENTS.md`） |
| `ui-probe.mjs <片段> [关键字]` | ⭐ 侦察：弹窗（分 visible/hidden）、已开下拉+可见选项、按钮、菜单、画布链接数。**动手前先看一眼** |
| `ui-click.mjs <片段> <选择器> [dom\|seq\|react\|real]` | ⚠️ **已内置为 `browser_click` 的 `mode`**，优先用工具；脚本留作调试 |
| `ui-pick.mjs <片段> <选项文字>` | ⭐ 在已打开的下拉里选中一项，**自动滚虚拟列表** |
| `real-click.mjs <片段> <选择器>` | 真实左键、**不做 scrollIntoView** —— 画布这类"坐标敏感"元素（工具版的 `real` 会先 scrollIntoView） |
| `right-click.mjs <片段> <选择器>` | ⚠️ **已内置为 `browser_click` 的 `button:"right"`**（实测页面收到 `isTrusted=true` 的 contextmenu，合成事件给不出这个） |
| `hover.mjs <片段> <选择器> [停留ms]` | ⚠️ **已内置为 `browser_hover`**，优先用工具；脚本留作调试 |
| `drag-node.mjs <片段> <源> <目标>` | ⚠️ **已内置为 `browser_drag`**（`mode:"html5"` / `"mouse"` 两档）；脚本留作调试 |
| `insert-column.mjs` / `probe-insert.mjs` | 插列专用（见 [[03-表样结构操作与结果验证]]） |
| `navigate.mjs` | 打开/跳转页面 |

**怎么选工具、脚本还是 `browser_eval`**：

- **动作类**（点击、悬停、选下拉、切页签）→ **先用工具**：点击 `browser_click`（可配 `mode` / `hoverMs` / `button`），
  悬停 `browser_hover`，切页签 `browser_activate`。工具在插件里，**不依赖 shell**。
- **只剩"故意不滚动"这一件事要脚本**：`real-click.mjs`（工具版的 `real` 一定会先 `scrollIntoView`）。
  其余动作都已经进工具层，**不依赖 shell** —— 这也是这套文档里反复出现的教训：脚本能做的事，只要
  它是 CDP 命令，就都该搬进工具层。
- **读/探查类** → `browser_eval` 更省事（内容每次都不同）。
- **业务片段**（比如"在参数赋值弹窗里填 4 行"）→ 仍然每次现拼，但**把里面的公共动作换成工具**，
  自己只写"填哪一行、填什么值"。

## 9. 待补

- **工具层现在只剩"不滚动的点击"没搬**：`real-click.mjs` 故意不 `scrollIntoView`。要不要收进
  `browser_click`（例如加个 `noScroll`），等真遇到坐标敏感的场景再说 —— **别因为"清单里还剩它"就提前做**；
- `browser_click` 的 `real` 会先 `scrollIntoView`（工具设计如此），画布这类"坐标敏感"的元素仍要用
  `real-click.mjs`（它故意不滚动）；另外 `real` 现在会在按下之前校验按点：元素被 CSS 平移出视口、
  或被浮层/固定栏挡住时报 `not-hit`，不再报"已点击"（`dom` / `react` 在页面内触发，不受视口限制）；
- 弹出框模式 / 顶部平铺模式切换（走 CDP hover，见 [[01-筛选器与参数绑定]] §13）；
- `ui-probe.mjs` 目前不列"表格里的可点单元格"，画布仍要自己按 `.ht_master tr/td` 索引找；
- 语义模型编辑器（`report-28`）的向导步骤（下一步/上一步）没有稳定入口记录。
