# 报表参数设置：默认值、常量，以及"写死一个值"的坑

> 实测：2026-10-11，金隅共享 `dev-fssc.bbmg.com.cn`，旗舰版，租户 `U8C3`，
> 报表《账户余额分析表》（`edbd891f-7bf3-4610-98e6-b313eb8e09c2`，`report-51`）。
> 关联：[[00-设计器总览与操作纪律]]、[[02-取不到数怎么排查]]、[[05-排查方法论-配置还是缓存]]、
> [[../报表SQL/07-经验-语义模型报表开发]]

## 0. ⭐ 一句话

**报表的参数默认值可以是一个"常量"，而常量默认值 = 每次执行都强塞给模型的一个固定值。**
语义模型 SQL 里只要有 `<#if param('x')?? && param('x') != ''> … </#if>`，
这个参数就会**恒成立**，过滤条件永远生效 —— 报表查出来的行数因此**比语义模型预览少**，
而 SQL、模型、字段全都"没问题"。

> **典型症状**：语义模型预览 N 行，报表预览 M 行（M < N），两边都没报错。
> **第一嫌疑**：报表侧有一个参数的默认值被设成了**常量**。

## 1. 这个配置在哪（界面路径）

```text
报表设计器（设计态）
  → 顶部「数据」菜单
      → 「参数」
          → 弹窗「参数设置」
              → 选中某个参数行 → 「默认值」列 / 齿轮图标
                  → 弹出「设置默认值」
                      ● 权限标签   ○ 系统变量   ● 常量
                      值：[________________________________]  [添加]
```

要点：

| 项 | 实测 |
|---|---|
| 入口 | 顶部 **「数据」→「参数」**（不是「筛选」；筛选面板里看不到它） |
| 弹窗 | 标题「参数设置」，两个页签：**模型参数绑定** / **分析参数** —— ⚠️ **两者不是一回事**：「更新模型」只写前者；而筛选器、超链接里"能选到什么参数"读的是**后者**，新参数必须手动加进「分析参数」才选得到，详见 [[01-筛选器与参数绑定]] **§10.5** |
| 表格列 | 序号 / 参数名称 / 参数类型 / … / **默认值**（并排还有「模型参数绑定」那一页） |
| 二级弹窗 | **「设置默认值」**，三选一：**权限标签 / 系统变量 / 常量** |
| 默认值形态 | 选「系统变量」→ 如 `var$(当前日期)`；选「常量」→ 一个**写死的字符串** |

⚠️ **默认值藏在二级弹窗里**，主表格那一行只显示参数名和类型。
这就是"使用者说我把能绑的都去掉了、报表却还在按某个值过滤"的常见原因 —— **那一步没被看到**。

## 2. 机制的配置证据（前端定义里长什么样）

一份"orgId 被写死"的真实定义（`analysisModel.params` 里的一项）：

```jsonc
{
  "id": "2fc17399-240b-41c6-8680-90db2b1b86eb",
  "scope": "PARAMS",
  "items": [{
    "code": "orgId",
    "dataType": "STRING",
    "defaultValues": ["2531236811194761226"],   // ← 「设置默认值」写进去的常量
    "value":         ["2531236811194761226"],   // ← 运行时真正被取用的值
    "vOrCs":         ["2531236811194761226"],
    "defaultParseVals": ["2531236811194761226"],
    "vt": "CONST",          // 常量（`var$(当前日期)` 时这里是 SYSTEM）
    "defaultVt": "CONST",
    "baseParam": { "name": "orgId", "value": "2531236811194761226", "dataType": "STRING" }
  }]
}
```

再往前一步：这个参数被**数据集**以 `paramRelations` 声明往下传 ——

```jsonc
// wideTableModels[].conditions.paramRelations[]
{ "label": "orgId", "target": "2fc17399-…", "valueOrCode": "2fc17399-…", "valueType": "PARAM", "compareType": "EQ" }
```

两端对上，就是"报表执行时会把 orgId 的这个常量值传给语义模型"。

## 3. 为什么结果是"少了一部分行"而不是 0 行（或报错）

模型的 SQL 决定了后果。对照三种写法：

| 模型 SQL 里参数的用法 | 传进来一个常量时 | 传进来空时 |
|---|---|---|
| `and a.account_org_id = ${param('orgId')}` 裸写 | 过滤生效，行数变少 | **报错或恒空**（`= ` 后面没值） |
| `<#if param('orgId')?? && param('orgId') != ''> and a.account_org_id = ${param('orgId')} </#if>` | 过滤生效，行数变少 | **整段不生效 → 全量** |
| `and a.org = '${param('orgId')}'` 当字符串拼 | 过滤生效 | `= ''` → 通常 0 行 |

本次就是第二种：**模型预览时参数为空 → 441 行；报表侧塞了常量 → 26 行**。
`<#if>` 写得越"讲究"，这个坑越安静 —— 它让"参数没传"和"参数传了个固定值"表现出**完全不同的两种结果**，
而不是报错。

> 所以排查时要问的不是"SQL 里有没有这个条件"，而是 **"这次执行，这个参数拿到的是什么值"**。

## 4. 怎么改

**目标：让默认值回到"不选即不过滤"。**

1. 回到 `数据 → 参数 → 参数设置`，选中那个参数行 → 打开「设置默认值」。
2. **把常量删掉**（删掉那条值 / 清空输入框），不要只是想当然地改。
3. 「设置默认值」→ **确定** → 「参数设置」→ **确定**。
4. **保存报表** → **刷新页面**再验（设计态内存里那份配置不可信，见 [[05-排查方法论-配置还是缓存]]）。

如果这个参数**根本不该存在**（连接键配错、平台自动生成的），更干净的是**删掉参数本身**：
在「参数设置」里把它删掉，同时确认 `模型参数绑定` 那一页不再引用它。

### ⚠️ 改完必须回头核对这四处（本次实测的坑）

清默认值**未必**把运行值一起清掉。实测出现过：

| 字段 | 清默认值之后 |
|---|---|
| `defaultValues` | `[]` ✅ 清掉了 |
| `value` / `vOrCs` / `defaultParseVals` / `baseParam.value` | **仍然是旧值** ❌ |

判据：平台**取数用的是 `value`**（`vOrCs` 只是留底，别被它误导，与 [[02-取不到数怎么排查]] §3.3 一致）。
所以清完**刷新页面**，再读一次这四个字段 —— **任何一处还留着旧值，就还会继续按它过滤**。

---

## 5. 一句话验收

改完保存 + 刷新后：

- 报表预览行数 = 语义模型预览行数；
- 或抓一次取数请求，看该参数渲染进去的值是空 / `$$$`（未选），而不是那个常量。

---

## 6. 关联的坑（顺手记）

- **别把"参数默认值"和"筛选器"混为一谈**：筛选器是给人选的控件（[[01-筛选器与参数绑定]]）；
  参数默认值是**无人值守时平台自己填的值**。要"按组织过滤但别写死"，正解是**加筛选器 + 参数绑定**，
  而不是给参数配一个常量默认值。
- **同一个"设置默认值"弹窗里，`权限标签` / `系统变量` 也都在干同一件事** ——
  往参数里放一个"每次执行都成立的值"。`var$(当前日期)` 用在日期参数上是正常的；
  但一个**业务维度**（组织、账套、单位）被设成常量，几乎总是错的。
- 界面里 `参数设置` 的**「值」列只显示参数自身的名字**（如 `orgId`），不显示它被设成了什么，
  所以"界面上看着没绑定"≠"没传值"。
