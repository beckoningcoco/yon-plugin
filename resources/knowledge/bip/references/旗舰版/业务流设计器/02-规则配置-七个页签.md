# 规则配置：七个页签逐项参数

> 「规则」是业务流配置的主体工作量所在。点边上的「编辑」或「+ 新建规则」会打开 `.design-rule-dialog`
> 弹窗，左侧 7 个页签。本文逐个说明**每个参数的业务含义**与**它在数据里落到哪个字段**。
> 实测环境：金隅共享 BIP 旗舰版，对照的流是 `JYTD_XS_01`「普通销售（有发货）-通达」（自定义、可编辑）
> 与预置的「普通销售（有发货）」。

## 一、弹窗总览

```text
.design-rule-dialog
  ├─ 左侧 7 个 li.el-menu-item        fieldid 前缀 businessFlowList_flow_<code>
  │    baseInfo 基本信息 / filterRule 来源数据过滤 / triggerSetting 触发设置 /
  │    makeBill 生单方式 / transferRule 转换规则 / separateRule 分单规则 / ysWriteBackRule 回写规则
  └─ 底部：[取消] businessFlowFe_designRuleIndex_btn1-cancelHandle
           [确定] businessFlowFe_designRuleIndex_btn2-saveHandle
```

- **当前在哪个页签**：看 `li.el-menu-item.is-active`。
- **预置流的弹窗字段几乎全是 `disabled`**，下拉展不开 —— 要研究"有哪些选项"，得找一条**自定义流**的规则，
  或者读 i18n 文案表（见本文第六节）。
- **「修改规则」比「新建规则」多一个「引用规则编码」字段**（新建时由「转换规则」下拉带出）。

## 二、基本信息（baseInfo）

| 参数 | 含义 | 可编辑 | 数据字段 |
|---|---|---|---|
| **规则名称** | 这条边在画布上显示的名字（连线名） | ✅ | `name` |
| 转换规则 | 引用的**单据转换规则**（平台预置或自定义），决定字段怎么映射 | ❌ | `refRuleCode` / `sysRuleCode` |
| 来源单据 | 边的起点单据 | ❌ | `originType` / `originDes` |
| 目标单据 | 边的终点单据 | ❌ | `targetType` / `targetDes` |
| **来源交易类型** | 起点单据的**交易类型**（如「普通销售（有发货）」） | ✅ | `srcBizTypeId` / `srcBizTypeName` |
| **目标交易类型** | 终点单据的**交易类型**（如「普通发货-通达」） | ✅ | `tarBizTypeId` / `tarBizTypeName` |
| 引用规则编码 | 引用的转换规则编码，如 `order_delivery` | ❌ | `refRuleCode` |
| 描述信息 | 备注，支持多语言 | ✅ | `description` |

**交易类型这个参数是整条业务流最容易踩的地方**，两点必须知道：

1. **核心单据的交易类型必须设**，否则保存报「核心单据的交易类型不能为空」。而它**只能在规则里设** ——
   节点属性面板的交易类型下拉永远是 `disabled` + placeholder「请到规则中设置交易类型」。
2. **它不一定设在"以核心单据为来源"的那一端**。实测两条流正好相反：
   - 预置「普通销售（有发货）」：**来源**交易类型有值、目标为空
   - 自定义 `JYTD_XS_01` 边①：**来源**为空、**目标**交易类型 =「普通发货-通达」

   所以别背"设在哪一侧"的口诀，**看哪一侧是核心单据，把它的交易类型填上**（两种落点都能通过校验）。

> i18n 原文提示（`00D1`）：**改变交易类型必须重新设置规则，否则可能会导致规则不可用，您确定要修改么？**
> 另一条（`1BEE1A9804980009`）：目标字段的交易类型若设置为**通过公式指定**，需谨慎检查公式配置；
> 且**基本信息里设了就以基本信息为准**。

## 三、来源数据过滤（filterRule）

页内标题「**过滤条件**」。是一个**异步加载的条件构造器**（打开时短暂显示「加载中…」），
用来限定"哪些来源单据参与推单"。

**运算符**（i18n）：等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 / 包含 / 不包含 / 开始于 / 结束于 /
仅等于 / 空。
**连接词**：与 / 或 / 或者 / 并且。

数据字段 `filterItems`。**原流和实测的自定义流这里都是空的** —— 不做过滤就是全量参与。

## 四、触发设置（triggerSetting）

页内标题「**推送时机**」。**7 个单选项，决定这条推单规则什么时候执行。**

| 界面名称 | `label` 取值 | 无泳道时 | 业务含义（i18n 原文） |
|---|---|---|---|
| 流程开始 | **6** | disabled | 指流程由发起人提交成功后触发 |
| 流程结束 | **0** | disabled | 指流程全部环节审批完成后触发 |
| 环节开始时 | **5** | disabled | 指审批流程的各个环节收到待办任务后触发，可多选 |
| 环节完成时 | **1** | disabled | 指审批流程的各个环节处理完成后触发，可多选 |
| 流程操作 | **3** | disabled | 指审批处理时的操作，如终止流程、驳回制单、撤回驳回制单、已经结束的流程做撤回、发起人撤回单据等操作触发 |
| **手工触发** | **2** | ✅ 可选 | 由按钮点击触发 |
| 单据动作 | **4** | ✅ 可选 | 指单据的保存、审核、弃审、删除等操作触发 |

- 取值落在 **`pushOpportunity`**（实测 `2` = 手工触发，与界面选中项一致）。
- **`isLane=false`（未启用业务泳道）时，前 5 项全部 disabled**，只能选「手工触发」或「单据动作」。
  业务流列表「新增」弹窗里的「启用业务泳道」开关就是控制这个的。
- **取值怎么读**：`.yy-radio-group` 的原生 `input.value` 恒为 `on`，必须读子组件
  `YYRadio.$options.propsData.label`。

**「流程操作」的 5 个具体操作**来自 `GET /form/processOperationList?tenantId=`：
`ACTIVITI_DELETED` 流程终止 / `WITHDRAWREJECTTOSTART` 撤回驳回制单 / `REJECTTOSTART` 驳回制单 /
`withdraw` 流程结束后撤回 / `deleteAll` 单据撤回。

**「单据动作」的可选动作**来自 `GET /opportunity/list`：它是「单据对 → 可用动作」的映射
（key 形如 `YS.0.1.voucher_delivery.voucher_saleinvoice`，value 如 `["audit"]`）。
选了「单据动作」后，规则里会多出**动作规则配置**（i18n：`00C4` 单据动作前规则配置 /
`00C3` 单据动作后规则配置 / `00C9` 动作名称 / `00CA` 动作编码 / `00C2` 插入规则）。

## 五、生单方式（makeBill）

页内标题「**推单设置**」。三项：

| 参数 | 含义 | 完整候选（i18n） | 数据字段 |
|---|---|---|---|
| **推送方式** | 目标单据不存在时怎么办 | 新增单据 / 仅更新单据 / 更新或新增 | `pushMode` |
| **推单过程** | 推单时走不走转单界面 | 转单画面（勾选）等 | `showConvertedBill` |
| **新建单据制单人** | 新建的目标单据算谁的 | 推送触发人 / 指定用户 | `createUserType` |

补充候选：**新建单据状态** = 草稿态 / 提交态。

> ⚠️ **这三个控件各自只渲染"当前可用的那一项"**，其余选项是 `<!---->` 注释占位、不进 DOM。
> 实测 `JYTD_XS_01` 边①的「推送方式」`yy-radio-group` 里只有「新增单据」一个 `yy-radio-wrapper`。
> **不要用下拉里的选项数去推断枚举全集** —— 枚举要靠 i18n 文案表或平台文档。

## 六、转换规则（transferRule）

页内标题「**注意事项**」+ 表格。**这是规则里最重的一页，决定目标单据的每个字段从哪来。**

### 列（4 列，实测）

| 列 | 控件 fieldid |
|---|---|
| **目标字段** | `businessFlowFe_designTransferRule_select1_<行号>_levelSelect_input` |
| **关联选择** | `businessFlowFe_designTransferRule_select2_<行号>` |
| **来源单据** | `businessFlowFe_designTransferRule_select3_<行号>` |
| **来源字段** | `businessFlowFe_designTransferRule_select4_<行号>_levelSelect_input` |

**「关联选择」这一列的取值才是"映射方式"**（i18n 里的简单映射/公式计算/常量…都属于它）——
**没有单独一列叫"方式"**，这一点容易看错。

**映射方式枚举**：简单映射 / 公式计算 / 常量 / 平铺计算 / 垂直计算 / 先横向在纵向 / 汇总 / 逐行推送 / 不转换。
- **简单映射**：来源字段直接赋值给目标字段。
- **公式计算**：用表达式算（配「表达式」+「表达式编辑器」）。
- **常量**：目标字段固定填一个值（数据里 `mapped_type=3`，实测 `origin_field="0"`）。
- **汇总**：按分类字段汇总（求和 / 计数 / 平均值 / 最大值 / 最小值 / 乘积）。

**顶部「目标单据」下拉** `businessFlowFe_designTransferRule_select0` 用来切换单据体
（主表 / 明细表），例如发货单有「发货单主表」与「发货单详情」。

**按钮**：新建 `businessFlowFe_designTransferRule_btn-newlyAdded` / 批量新建 `..._btn-batchCreate` /
查看全部 `..._btn-viewAll`。

> ⚠️ **表格是虚拟列表**（实测总行数 330，视口里只有约 3 行有 DOM）。
> **抓数据要翻页/滚动，或者直接读接口**（见 `04-数据模型与接口.md`），不要只 dump 一次 DOM 就以为只有几行。

> ⚠️ **点过「查看全部」之后，弹窗会卡在转换规则页，左侧 7 个页签全部点不动**（点「基本信息」也不切换）。
> **只能点「取消」关掉弹窗重开。**

**注意事项原文**（i18n）：
- `1C7E635A05B0000C`：同时配置了特征组和特征的转换规则时，需要**特征组规则在前，特征规则在后**。
- `0062`：当为「公式计算(目标单据)」时，运行时**按配置的规则先后顺序执行**。
- `1DDCE88C04600008`：转换规则填写不完整，存在来源/目标字段为空的行，请检查。

## 七、分单规则（separateRule）

页内标题「**分单规则**」。列：

| 列 | 含义 | 数据字段 |
|---|---|---|
| 来源单据 | 分组字段所在的单据/子表 | `childKey` |
| **分组字段** | 按哪个字段拆分成多张目标单据 | `sOriField` |
| **分组字段显示名** | 分组字段的显示名（带 `_name` 后缀的字段） | `sOriFieldName` |

实测 `order_delivery` 的分组字段有 4 条：`retailAgentName`、`orderPrices!originalName`、
`orderPrices!exchangeRateType_name`、`isDespatch`。

**业务含义**：来源单据按这些字段的**不同取值**拆成多张目标单据（一个分组生成一张）。
`!` 表示子表路径（如 `orderPrices!originalName` 是「订单价格子表的原币种名」）。

## 八、回写规则（ysWriteBackRule）

页内标题「**回写规则**」。列：

| 列 | 含义 | 数据字段 |
|---|---|---|
| **来源关联字段** | 来源单据上与目标关联的字段 | `sOrgRelateField` |
| **来源回写字段** | 要回写到来源的字段 | `sOrgKey` |
| **回写方式** | 怎么回写（实测 `sum`） | `sBackType` |
| 目标单据 | 目标子表 | `sTarChildKey` |
| **目标关联字段** | 目标单据上用来关联的字段 | `sTarRelateField` |
| **目标回写字段** | 目标侧取值来源，**可含公式** | `sTarKey` |

实测 `order_delivery` 的回写规则一条：`sOrgKey=sendQty`（回写到来源的"累计发货数量"）、
`sTarKey="qty-stopQty"`（目标侧取值 = 数量 − 中止数量，**是个公式**）、`sBackType=sum`、
`sOrgRelateField=id`、`sTarRelateField=sourceautoid`。

**业务含义**：目标单据生成/变更后，把数值按「回写方式」累加回来源单据的某个字段
（典型用途：订单的"已发货数量"由发货单回写）。

**回写相关枚举**（i18n）：回写方式候选里有 覆盖 / 追加 / 公式 / 固定值 / 单据属性；
回写类型有 数据回写 / 凭证回写；还有 回写时机、回写条件、上游单据、仅提示 / 禁止下一步 / 强制更新业务数据。

## 十、还没确认的

以下几条实测时没拿到确凿结论，**用之前先验证**：

1. **「关联选择」的完整候选**：只确知界面显示「简单映射」，以及 i18n 里有那 9 种文案；
   各候选在什么条件下出现没验证。
2. **`mapped_type` / `mapped_relation` 的数值与界面选项的精确对应**：只知 `mapped_type` 取值
   `{0:320, 1:1, 3:6}`、`mapped_relation` 取值 `{0:87, 1:14, 2:17, 3:209}`（对 `order_delivery`），
   以及 `mapped_type=3` 是常量。**`mapped_relation` 四个值各是什么没确认。**
3. **分单规则页 / 回写规则页有数据时的可编辑控件**：只读了数据结构，没在界面上实际增删改。
4. **来源数据过滤的运算符与取值**：只拿到 i18n 文案，条件构造器的实际操作没试。
5. **「推单过程」的其余取值**：实测只渲染出「转单画面」一项，i18n 里还有 拉单画面设置 /
   选择页面 / 选择字段 / 允许查看详情 等，归属未逐一确认。
