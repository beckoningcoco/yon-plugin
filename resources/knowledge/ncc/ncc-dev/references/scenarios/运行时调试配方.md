# 运行时调试配方（NCC）

> **什么时候读我**：手上有一个**具体症状**（"这个方法到底走到没有"、"返回的值不对"、"偶发异常"、
> "这个方法怎么这么慢"），想直接抄一条命令去用。
> 原理、实测细节、为什么这么设计，看 **`运行时调试与现场重放.md`**；本文件只按症状给做法。

> **边界**：本文件只讲**运行中的 Java 进程**。性能报告看 `spr-log-analysis.md`，
> 静态调用链走查用 `ncc-call-chain` 技能，报错堆栈先看 `<HOME>/nclogs/`。

> **三条纪律**（每条都由实测换来）：
> 1. **用完必须 reset。** `watch`/`trace` 结束后增强**仍然装着**（实测：trace 跑完再 reset，
>    报的 `classCount=1`）。`arthas_watch_stop` 就是干这个的。
> 2. **观察会拖慢服务。** 每个命中都要过一次切面。用完就撤，别挂着过夜。
> 3. **不要用 `ognl` 调有副作用的方法。** 它执行的是真实方法：写库、发消息、写文件都拦不住。
>    拿不准就 watch 观察，不要主动调。

---

## 〇、先备好两件东西

**一是目标进程。** `arthas_targets` 里带 `-Dnc.server.location=` 的那个就是 NCC；
它还会告诉你 agent 挂在哪个 PID 上。没挂就先 `arthas_attach`。

**二是 classloader hash（只有 `ognl` 需要）。** `watch` / `trace` 用的是被增强类自己的加载器，
不用带；但 `ognl` 走系统类加载器，**不带 hash 就找不到业务类**：

```
arthas_sc className=nc.vo.pub.lang.UFDouble
  → classLoaderHash: 7c29daf3
```

后面 `ognl -c 7c29daf3 '…'` 里的那个 hash 就是这么来的。**它随进程重启而变**，别记死。

## 一、「这个方法到底走到没有？」

症状：怀疑某段逻辑被跳过了，但日志里什么都没有。

```
arthas_watch_start pid=<PID> className=<你的类> methodName=<你的方法>
  → 会话 #1
（去做那个业务动作）
arthas_events session="1"
```

**读什么**：

| 结果 | 含义 |
|---|---|
| 命中 1 次，`params` 有值 | 走到了，而且拿到了入参 |
| 一直不命中 | **没走到**（或被别的分支挡住了）——这时才该去查条件判断 |
| `⚠ 观测没有注册成功：No class or method is affected` | 类名/方法名写错了，**不是**"没走到" |

**这个区分很值钱**：把"没走到"和"名字写错了"混起来，会让人去改一段根本没被调用到的逻辑。
注册失败一定会报出来，看到它先改名字。

---

## 二、「页面显示的值不对」

症状：列表/单据上某个值不对，想知道**后端算出来的到底是什么**。

```
arthas_watch_start pid=<PID> className=<你的类> methodName=<你的方法> expression="{returnObj}"
（触发一次查询）
arthas_events session="1"
```

`expression` 默认是 `{params, returnObj}`，看返回只要 `"{returnObj}"` 更清爽。

**读什么**：`returnObj` 里那个字段就是后端交给前端的值。

- `returnObj` 里也不对 → 问题在**后端算法**，接着往下看第三节（入参）和第四节（落库）
- `returnObj` 对、页面不对 → 问题在**前端或转换层**，这一层帮不上，转去抓 HTTP 响应

---

## 三、「前端传的参数对不对？」

症状：怀疑前端没传、或者传了个空值。

```
arthas_watch_start pid=<PID> className=<Action 类> methodName=<方法> accessPoint=before
arthas_events session="1"
```

`accessPoint=before`（默认）看的是**进入方法时**的入参 —— 这正好是"前端传了什么"。
对比下一层 Service 的入参，就能定位**是哪一层把值丢了**：

```
# 同一时刻挂两层，一次操作拿两份入参
arthas_watch_start pid=<PID> className=<Action 类> methodName=<方法>
arthas_watch_start pid=<PID> className=<Service 类> methodName=<方法>
```

**读什么**：Action 有值、Service 没值 → 在 Action 到 Service 之间丢的（转换/赋值漏了）。

---

## 四、「字段没写进库」

症状：保存成功了，但库里那一列还是空的。

顺序是**先看后端有没有拿到值，再看 SQL 有没有写**：

```
# 1) 保存方法进入时，入参里的那个字段是什么
arthas_watch_start pid=<PID> className=<保存 Service> methodName=<save> accessPoint=before

# 2) 拿到 classloader hash 后，直接看 VO 里的值（只读，安全）
arthas_sc className=<你的 VO 类>
arthas_exec command="ognl -c <hash> '#vo=…'"
```

更省事的一步：**用 `datasource_query` 直接查那张表**。
写入前 VO 有值、库里没有 → 问题在**落库/映射**（列名对不上、被覆盖、事务回滚）；
VO 就没值 → 问题在**上游赋值**。

**哪张表、哪一列**用 `wiki_lookup` 查实体，别猜。

---

## 五、「偶发异常，事后不知道当时的输入」

症状：用户报"保存报错"，你去查的时候请求早没了，日志里只有堆栈。

这是 `arthas_catch` 的用途：**只抓抛异常的调用，把异常和入参一起落盘**。

```
arthas_catch pid=<PID> className=<你的类> methodName=<你的方法> tag=save-fail
（让用户再操作一次）
arthas_events session="1"
```

**读什么**：事件流里**直接显示异常**（不用打开文件）：

```
命中 1 次 · <类>#<方法> · AtExceptionExit
   @NumberFormatException[For input string: "abc2"]
```

同时落盘两个文件（`count=1` 时名字在挂上之前就报出来了）：

| 文件 | 内容 |
|---|---|
| `…_<时钟>.thrown.ser` | 异常对象，**含完整堆栈** |
| `…_<时钟>.args.ser` | 当时的入参，**原样是 `params` 数组** |

`args.ser` 可以直接喂给 `replay_run`，**离线复现这次失败** —— 不用等用户再操作一次。
`count` 设大于 1 时文件名尾巴由目标 JVM 决定，路径要列 `前缀_*` 找，也没有侧车（面板里要手填类名方法名）。

**两个坑**：

- 异常变量是 **`throwExp`**，不是 `throw`（自己写表达式时踩：`{throw}` 报
  `NoSuchPropertyException: …Advice.throw`）。
- **JDK 自己的类（`java.*`）挂不上**，会报 `No class or method is affected … options unsafe true`。
  要抓"解析失败"，抓 NCC 自己的值类型：`nc.vo.pub.lang.UFDouble` / `UFDateTime` 这类。

## 六、「这个方法怎么这么慢？」

症状：某个操作慢，日志里看不出时间花在哪。

```
arthas_trace pid=<PID> className=<你的类> methodName=<你的方法> count=5
（触发几次调用）
```

**读什么**：每次调用的耗时（毫秒）+ 平均/最小/最大，并且**与上一次测的同一方法自动对比**。

**注意第一发**：实测同一个方法第一次 **222.9 ms**、第二次 **47.8 ms** —— 第一次带着类加载和缓存预热，
**别拿单次结果下结论**，`count` 至少给 3~5。

**更要紧的是分布**：同一个方法连测两批（各 5 次），最小值 47.6 → 46.6 ms（**没变**），
平均却是 80.3 → 99.9 ms，工具报的是「+24.5% 变慢」—— 差别只是第二批多了一次 156.9 ms 的离群值。
所以**优先看最小**（热态，离群值动不了它），平均只作参考；一批里最慢是最快的 2 倍以上时，
工具会自己提示「样本波动大」。**把噪声当成结论，会让人去优化一段根本没变慢的代码。**

**读完记得撤**：`arthas_watch_stop session="<id>"`（trace 的增强不会自己走）。

**更细的问题**（慢在哪一层）：`trace` 的结构化结果里带**调用树**，
需要看子调用时用 `arthas_exec` 跑 `trace --skipJDKMethod false -n 1 <类> <方法>`。
和 SPR 的分工：SPR 看**整个请求**（哪个接口、哪条 SQL），这里看**一个方法内部**。

## 七、「事件监听器 / 插件没生效」

症状：写了 `IBusinessListener`，但看起来什么都没发生。

**第一步不是看逻辑，是确认它有没有被调用**：

```
arthas_watch_start pid=<PID> className=<你的监听器类> methodName=doAction
（触发那个业务动作）
arthas_events session="1"
```

| 结果 | 结论 |
|---|---|
| 完全不命中 | 监听器**没被注册/没被调用** —— 查组件注册、事件类型，别改逻辑 |
| 命中，但 `returnObj=false` | 被**自己的代码**拦下了（条件判断提前返回） |
| 命中且正常返回，库里没变化 | 逻辑走到最后了但没生效 —— 查它调用的那个 Service |

这一步能把"没注册"和"逻辑错"分开，而这两种问题的改法完全不同。

## 八、「定时任务没执行」

症状：配了后台任务，但没看到结果。

```
arthas_watch_start pid=<PID> className=<你的插件类> methodName=executeTask
（等触发时刻到来，或者手动触发一次）
arthas_events session="1"
```

- 不命中 → 任务**没被调度到**：查任务注册、触发器配置、以及服务是不是在计划时间点是活的
- 命中但抛异常 → 用第五节的 `arthas_catch` 抓下来看

**计划任务的等待可能很久**：`arthas_watch_start` 挂上后不用一直等，
会话是持久的，等触发过后再 `arthas_events` 读即可。

---

## 九、「这个类加载的是哪个版本的 jar？」

症状：改了代码、重启了，但行为还是旧的（怀疑加载了旧的 jar）。
或者同一个类在多个模块里都有，想知道**运行时到底用的哪一份**。

```
arthas_sc className=<你的类>
```

**读什么**：`code-source` 就是答案，例如：

```
nc.vo.pub.lang.UFDouble
  classLoaderHash: 7c29daf3
  code-source:     E:/NCProject/NCC1909/shouchuang/home/ncc1909new/external/lib/basic.jar
```

NCC 尤其要看这一条：**服务真正加载的是工程的 `bin/`，不是 `HOME/modules`**
（实测 `code-source` 指向 `<工程>/bin/`）。补丁放进 `modules/` 但没重启对地方，
就是这样表现出来的。

---

## 十、「静态配置/常量的值不对」

症状：怀疑运行时那个静态字段的值和源码里写的不一样（被改过、被初始化逻辑覆盖）。

```
arthas_sc className=<你的类>        # 拿 hash
arthas_exec command="ognl -c <hash> '@<全限定类名>@<字段名>'"
```

**读什么**：直接就是那个字段的值。**只读，安全**。

反过来，**要改**它就得用 `ognl` 赋值 —— 那是在动运行中的状态，做完要么重启要么清楚它的影响面。
这一条属于"知道就行，别顺手做"。

## 附：命令都从哪来

| 工具 | 用来做什么 |
|---|---|
| `arthas_targets` / `arthas_attach` | 找到进程、把 agent 挂上去 |
| `arthas_sc` | 拿 classloader hash、看类从哪个 jar 加载 |
| `arthas_watch_start` / `arthas_events` / `arthas_watch_stop` | 观察方法的入参/返回值/异常；**stop 负责 reset** |
| `arthas_catch` | 抓失败调用的异常 + 入参，可离线复现 |
| `arthas_trace` | 测耗时、留基线、与上次对比 |
| `arthas_capture` | 抓一个对象落盘，喂给离线回放 |
| `arthas_exec` | 逃生口：跑上面没覆盖的 Arthas 命令（`jad`、`monitor`、`sm`…） |

`redefine` / `stop` / `shutdown` 在这套工具里**被直接拒绝**，没有参数能解锁 —— 它们离"把环境搞坏"只有一步。
