# 业务流设计器：界面总览与操作纪律

> 实测环境：金隅共享 `dev-fssc.bbmg.com.cn`，BIP 旗舰版，2026-10 用 Edge + CDP 驱动。
> 选择器与数字都来自真实页面，**用之前先用 `browser_eval` 确认一遍**，不要当常量照抄。

## 一、这是什么、在哪

业务流设计器是旗舰版「**业务流设计**」节点里的画布，用来把**若干单据**按**推单关系**串成一条业务链路
（销售订单 → 销售发货单 → 销售出库单 → 销售发票 就是预置的「普通销售（有发货）」）。

| 项 | 值 |
|---|---|
| 菜单节点 | 「业务流设计」，路由 id `degree4th-XTLCZX0032`（查 `bip-menu-dict`） |
| 前端微服务 | `iuap-apcom-supportcenter` |
| 设计器 URL | `https://<host>/iuap-apcom-supportcenter/ucf-wh/businessflow/index.html#/formRelation/businessDesigner?serviceCode=form-relation&id=<业务流id>&jDiworkServiceCode=XTLCZX0032` |
| 后端接口前缀 | `/iuap-apcom-supportcenter/businessFlow/`、`/domainMakeBillRule/`、`/flowRule/` |

**点列表页的「设计」按钮会 `window.open` 新开一个页签**，不是在原页签内跳转 —— 用 `browser_targets`
重新找页签，不要以为点击失败了。

## 二、三层概念（先分清，否则配置会串层）

```
业务流（businessFlow）
 └─ 节点（node, type=ruleItemNode）      一个节点 = 一张单据，如「销售订单」
     └─ 边（edge, type=billPush）        一条边 = 一次推单，如「订单发货」
         └─ 规则（flowRule）             边上的规则，决定推单细节
```

- **节点**只记「是哪张单据、是不是核心单据」；交易类型、是否自制、参照生单在节点属性面板里。
- **边**本身只有拓扑（谁推谁、从哪个锚点到哪个锚点）；**它的业务含义全在规则里**。
- **规则**是 7 个页签的那张表（见 `02-规则配置-七个页签.md`），是配置的主体工作量所在。

**"核心单据"是业务流的起点单据**：`isCore="1"` 的那个节点。一条业务流有且只有一个核心单据。

## 三、入口：列表页与「预置 / 其他」两个分类

列表页左侧是云分类树，**每个云下都有「预置」和「其他」两个叶子**：

| 分类 | 内容 | 能不能新增 |
|---|---|---|
| **预置** | 平台自带的业务流（`isPreset=true`），如「普通销售（有发货）」 | ❌ **「新增」按钮 `disabled=true`** |
| **其他** | 使用者自定义的业务流（金隅环境实测 36 条，如 `JYTD_XS_01`） | ✅ 可新增、可编辑、可删除 |

**要在「其他」下才能点新增** —— 选在「预置」上时按钮是灰的，别以为是权限问题。

列表列：编码 / 名称 / 交易类型 / 启用状态 / 版本 / 修改人 / 修改时间。
选中一行后底部工具栏：新增、设计、停用、复制、编辑、日志、删除、加入迁移清单。

## 四、设计器分区

```text
.design-header                          流程名 + 「属性设置」 + 「保存」
.design-body
  ├─ #designMenu.design-menu            左：辅助工具 / 分支 / 核心单据 + 单据树（可拖）
  └─ .design-center
       └─ .designer-main > .main > #designer.designer-canvas
            └─ div.canvas.ys-plane.ys-droppable      ← 画布本体
```

**画布是自研 `ys-*` 图形引擎，节点是 HTML 元素不是 SVG**（这点与 X6 类画布不同，选择器要按 HTML 找）。

| 想找 | 选择器 |
|---|---|
| 画布 | `#designer`，内层 `div.canvas.ys-plane.ys-droppable` |
| 画布上的单据节点 | `#designer .list-item.ys-node.ys-draggable` |
| 节点显示名 | `#designer span.content-name.ruleItemNode` |
| 连线名 | `#designer div.rule-name` |
| 左侧可拖单据 | `.design-menu .list-item.draggable.is-can-drag.billItemNode` |
| 左侧搜索框 | `.design-menu input.el-input__inner`（placeholder「搜索」） |
| 缩放控件 | `.designer-transform`（`-` / `.transform-per` / `+`） |

**右侧属性面板是复用的同一个容器 `.relation-item`，标题随选中对象变**：

- 点**节点** → 标题「**单据信息**」（单据名称只读、交易类型、是否自制、参照生单、动作规则配置）
- 点**边** → 标题「**规则信息**」（推单/拉单/回写 三个页签 + 规则卡片 + 「+ 新建规则」）

**「属性设置」面板（`div.attr-setting.flow-setting`）里没有交易类型**，只有流程名称、创建人/时间、修改人/时间。
业务流的编码、多语言名等属性**不在这里配**。

## 五、操作纪律

1. **动预置流之前先说清楚**。预置流（`isPreset=true`）是平台资产，学习它请**只读**：点开面板看、不点保存。
   要练手就在「其他」分类下**新建一条**，练完删掉。
2. **能复用已登录的页面就复用**：先 `browser_targets` 找到使用者开着的列表页，再 `browser_attach`；
   设计器是新开页签，点完「设计」要重新 `browser_targets`。
3. **拖拽一律用 `browser_drag` 的 `mode="mouse"`**。这个画布用的是 `mousedown`/`mousemove`/`mouseup`
   手势（`ysDesign` 拖拽库），源元素的 `draggable` 属性是 `false`。`mode="html5"`（默认）**不能作为判据**：
   实测里它的手势其实进过引擎（引擎弹过自己的提示，也真建成过节点与连线），但浏览器不回
   `Input.dragIntercepted`，工具于是报「没有东西可以投递」——**报的结论会和页面事实相反**，看到这句
   就直接重拖，会得到重复的节点与重复的连线。mouse 这条路才有一份说得清的回报：事件序列确实发出、
   四个时刻指针底下是谁都读得到。
4. **落点要精确就插探针**。`browser_drag` 只能指定元素目标，要落到坐标就先 `browser_eval` 插一个
   固定定位的透明 `<div id="__probe">`，拖完删掉。详见 `01-画布操作-加节点与连线.md`。
5. **回报的元素名现在取的是"看得见的文字"**（隐藏的候选下拉不再算进来——实测报过「ERP销售合同」的
   那个毛病已修），但它仍然不是业务判据：它说的是"你拖的元素叫什么、手势发去了哪里"，**不是"引擎
   建成了什么"**。以拖后实测的坐标/数量为唯一依据。定位源元素务必用 CSS 选择器 + 临时属性，不要用
   `by:"text"`（会命中节点里的 `font`/`span`，退化成平移画布）。
6. **保存前先确认交易类型已设**，否则会弹「核心单据的交易类型不能为空」而保存失败。见 `03`。
7. **动完使用者的流要告诉他改了什么**，不要默默改。
8. **`el-select` 选定后 `input.value` 仍为空串**，只有容器 `innerText` 才反映已选值 ——
   用 `input.value` 判断会误判成"没选上"。

## 六、边界

- 本技能只管**业务流设计器的界面操作与配置含义**。单据转换规则本身的**字段映射内容**
  （哪个字段映射到哪个字段、公式怎么写）属于单据转换规则的领域，不在本文覆盖范围。
- 表名、字段名、实体元数据不要靠看页面猜，用 `yonyou-bip-dev` 或 `bip_meta_*`。
- NCC / NC Cloud 是另一条产品线，业务流不是同一套东西，不适用本技能。
