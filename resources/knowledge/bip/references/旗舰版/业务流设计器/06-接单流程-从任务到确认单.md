## 0. 总流程

```text
一句话任务
  → G0 项目确认（project_list / project_read / memory_recall）
  → G1 环境确认（browser_targets / getById 探活 / tenantId）
  → G2 数据源确认（datasource_list / SELECT 1）
  → G3 能力确认（读 / 写 / 启用 / 运行期）
  → G4 出确认单（A 决策页 + B 施工底稿 + C 待确认）
  → 人确认（A 页 5–7 个决策）
  → 施工（按 B 页）
  → 回读验收（D.1 / D.2 / D.3 / D.4）
  → 交付（快照 + 验收记录 + 交付说明）
```

**门禁**：G0–G3 不通过，**不进 G4 的 A 页**，先出「能力缺口清单」——告诉使用者缺什么、怎么补。
G4 的确认单里，B0 必须回填 G0–G3 四项的结果。

## 1. G0 项目信息

**查什么**

| 项 | 工具 | 判据 |
|---|---|---|
| 项目是否已登记 | `project_list`（可带 query） | 有匹配项 |
| 项目 code / 名称 | `project_list` / `project_read` | code 可用于确认单编号 `<项目code>-BFL-<序号>` |
| 产品线 | `project_read` 的字段 / 使用者说明 | **必须是旗舰版（BIP）**；NCC 走 `yon-ncc-dev`，不适用本流程 |
| 项目记忆 | `memory_recall`（project=…） | 先看有没有「这个项目上已经踩过的坑」 |
| 需求条目 | `requirement_list`（project=…） | 有同类条目先复用，不重复建 |

**通过**：项目存在、产品线 = 旗舰版。
**不通过**：项目未登记 → 不阻塞，B0 写「项目未登记，用临时标识」；若是 NCC → **停**，转 NCC 技能。
**产物**：B0 的「项目」行 + 项目记忆召回结果。

> 项目信息是**配置记录**，不是代码工程；不要拿当前工作目录当项目。

## 2. G1 环境信息

**查什么**

| 项 | 工具 / 接口 | 判据 |
|---|---|---|
| 已登录页面 | `browser_targets` | 有旗舰版页签（`dev-fssc.bbmg.com.cn` 或目标 host） |
| 环境指纹 | 页面地址 / `getById` 返回 | `host`、`tenantId`、`orgId` 可读 |
| 接口探活 | `GET /iuap-apcom-supportcenter/businessFlow/getById?id=<已知流id>` | 200 且 `data.name` 有值 |
| 列表可达 | `GET /businessFlow/list?tenantId=&type=1&flowCategoryId=&index=1&size=10&orgId=` | 200，返回列表 |
| 元数据索引 | `bip_meta_find`（旗舰版快照） | 标准实体可查；查不到不一定是环境问题，可能是快照未覆盖 |
| 登录态能否复用 | `browser_attach` | 能接管，不要求重新登录 |

**通过**：host + tenantId + `getById` 200 + 列表可达。
**不通过**：让使用者打开/登录页面；**不能猜 tenantId / orgId**，也不要自己开新环境。
**产物**：B0 的「环境」行 + 环境指纹（host / tenantId / orgId / 当前账号）。
**注意**：设计器点「设计」会 `window.open` 新页签，点完要重新 `browser_targets`。

## 3. G2 数据源信息

**先明确：业务流配置本身走页面 + 接口，不依赖数据库连接。**
数据源在业务流任务里有三个用途，缺了会影响验收，不影响配置：

1. **字段核对**：`bip_meta_*` 查不到、或实体字段与物理列对不上时，用 `datasource_query` 实测；
2. **运行期验证**：推单后查目标单据是否真的落库、字段值对不对；
3. **数据核对**：交易类型、单据类型、组织等基础数据的实际值域。

**查什么**

| 项 | 工具 | 判据 |
|---|---|---|
| 是否登记了对应连接 | `datasource_list`（query=host / 项目名） | 有匹配 key |
| 连接是否可用 | `datasource_query` → `SELECT 1` | 返回 1 |
| 库类型 | `datasource_list` 返回 | Oracle / 达梦 / MySQL / PostgreSQL… |
| 是否需要 DB | 任务性质 | 只配拓扑/规则 → 不需要；要核对字段/运行期验收 → 需要 |

**通过**：有 key 且 `SELECT 1` 通；或任务明确不需要 DB。
**不通过**：
- 需要 DB 但没登记 → 让使用者提供连接信息（`datasource_upsert` 需要密码，不能猜）；
- 没登记且任务不需要 → 降级为「仅页面 + 接口」，B0 注明，运行期验收改用页面查看。
**产物**：B0 的「数据源」行 + 一句「DB 可用/不可用，影响哪些验收项」。

## 4. G3 能力确认（能不能完成需求确认单）

这一节回答：**在当前环境里，确认单上的信息查不查得到、配置写不写得进去、能不能验。**
逐项探测，结果决定能力等级。

### 4.1 能力项

| # | 能力 | 探法 | 失败影响 |
|---|---|---|---|
| C1 | 读业务流列表 | `businessFlow/list` 200 | 无法找参照流/查冲突 |
| C2 | 读业务流主体 | `getById` 200 | 无法回填拓扑 |
| C3 | 读边上规则 | `flowRule/list` 200 | 无法回填规则/校验 |
| C4 | 读系统转换规则 | `getRuleByCode` 200（系统规则） | 无法填 B4 基线；自定义规则改走 `flowRule/list` |
| C5 | 读交易类型 | `getTransTypeTypeByFormId?formId=<域>.<单据>` 200 | D4 候选列不出 |
| C6 | 扫描同类型流 | 遍历 `businessFlow/list` 各分类 | D6 冲突无法判 |
| C7 | 打开设计器 | 点「设计」新页签，读到 `#designer` | 看得到、配不了 |
| C8 | 保存 | 测试流保存一次，`browser_messages` 读成功 | 只能诊断，不能施工 |
| C9 | 启用（保存后） | 列表「启用」按钮；保存自动生成版本，无发布动作 | 启用已验证；无发布动作 |
| C10 | 运行期验证 | 打开单据页、做一次推单 | D.3 无法打勾 |

### 4.2 能力等级

| 等级 | 通过项 | 能承诺什么 | 确认单怎么填 |
|---|---|---|---|
| **L0 只读诊断** | C1–C6（读全通），C7–C10 不通 | 只出诊断/方案，不承诺施工 | 不出 A 页，先出「能力缺口清单」 |
| **L1 可配置** | C1–C8（能保存），C9–C10 未通 | 出确认单 + 施工 + 回读 + 启用 | D7 默认「保存并启用」 |
| **L2 可交付** | C1–C10 全通 | 配置 + 保存 + 启用 + 运行期验收完整闭环 | D7 可写「保存并启用」 |

> **当前实测（2026-10-18，金隅共享）**：C1–C8 可用；**C9 启用已验证；保存自动生成版本，没有独立「发布」动作；C10 运行期未做**（见 `08-启用与发布-实测.md`）。
> 所以现在最高只能承诺 **L1**——「配置 + 保存 + 启用 + 回读」可以自动；**推单成功还不能自动打勾**。
> 这不是模板问题，是能力边界；确认单的 D.2 最后一项、D.3 全部要如实留空或标「待验证」。

## 5. G4 出确认单

**前提**：G0–G3 通过，且能力等级 ≥ L1。

1. 按模板建 `业务流需求确认单_01.md`；
2. **B0 回填 G0–G3**：项目、环境、数据源、能力等级；
3. **A 页只放 5–7 个决策**：链路、核心单据、触发方式、交易类型、字段映射怎么处理、冲突（若有）、交付方式；
4. **B 页预填**：拓扑、每条边的规则、资产盘点、字段映射基线+差异；
5. **C 页只放缺口**：查不到的、冲突的、需要业务方拍板的，逐条列；
6. 业务方确认 A 页（勾默认或改一项）；C 页答复后，状态改「已确认」。

**若能力等级 = L0**：不出 A 页，先出「能力缺口清单」：
```
能读的：…
不能写的：…
不能验的：…
需要补：页面权限 / 保存权限 / 启用权限 / 测试单据
```
**若任务跨技能**：要改系统规则映射、或改预置流本身 → 拆成「业务流 + 转换规则」两件事，转 `yonyou-bip-dev`。

**施工与交付**：确认单冻结后，按 `07-配置交付完成-DoD与交付单.md` 的 D1–D6 施工并填交付单；
运行期验证由业务员做，AI 的 DoD 到 D1 / D2 / D3（配置层）/ D4 / D5 / D6。

## 6. 判定表：接 / 暂停 / 转

| 情形 | 判定 | 动作 |
|---|---|---|
| G0–G3 通过，L1+ | **接** | 出确认单草稿，等 A 页确认 |
| 环境不可达 / 未登录 | **暂停** | 要页面；不猜环境 |
| 无数据源，但任务不需要 DB | **接** | B0 注明「仅页面+接口」 |
| 无数据源，且要做字段/运行期验证 | **暂停** | 补连接，或降级验收方式 |
| 找不到参照流 / 单据 / 交易类型 | **暂停** | 要业务方确认资产是否存在 |
| 同交易类型已有生效流 | **暂停** | D6 必须回答：合并 / 停用 / 新建独立 |
| 目标流是预置流，要改 | **暂停 / 复制** | 预置只读；复制行为未验证，按新建处理 |
| 任务要改系统规则映射 | **转** | 拆「业务流 + 转换规则」，转 `yonyou-bip-dev` |
| 产品线是 NCC | **转** | 走 `yon-ncc-dev`，本流程不适用 |

## 7. 自动化执行清单（给 AI 的伪代码）

```text
1. project_list(query=项目名) → 匹配项目；memory_recall(project=…)
2. browser_targets → 选旗舰版页签；browser_attach
3. getById(参照流 id 或列表首条) → 200? 取 tenantId/orgId
4. datasource_list(query=host) → 有 key? datasource_query(SELECT 1)
5. 能力探测 C1–C10 → 定级 L0/L1/L2
6. 读参照流：getById → content.nodes/edges
7. 逐边 flowRule/list → refRuleCode / pushOpportunity / pushMode / createUserType / dataItems
8. 逐条 getRuleByCode → isSys / detailCount / groupCount / backCount（B4 基线）
9. 冲突扫描：**优先 `datasource_query` 直查** `TRANSACTION_TYPE_ID LIKE '%<id>%' AND STATUS=1 AND IS_CURRENT_VERSION=1`（见 `10`）；
   没有 DB 才遍历 `businessFlow/list` 各分类。⚠️ 交易类型字段是**逗号拼接**的，等值 `=` 会漏（实测漏过一条启用流，把"已占用"判成"可用"）
10. 生成 A/B/C：A 页 5–7 决策；B 页预填；C 页只放缺口
11. 等 A 页确认 → 施工 → 回读（D.1/D.2）→ 运行期（D.3，L2 才做）→ 交付
```

**每一步都要留下可复核的证据**：接口返回的字段、条数、id。不要用「界面上看到了」当证据。

## 9. 当前边界（诚实）

1. **保存后版本递增 / 复制**：保存自动生成新版本（使用者确认，未截取保存前后对比）；复制行为未验证。
2. **运行期验证**：需要测试单据、权限、业务操作；当前只做到「配置态 + 保存/启用态」。
3. **同类型冲突扫描**：有 DB 连接时用 `TRANSACTION_TYPE_ID LIKE '%<id>%'` 直查最快（见 `10`）；无 DB 才遍历 `businessFlow/list` 分类。**不要用等值 `=`**——该字段可存 `"idA,idB"`，实测因此漏判过启用中的占用流。
4. **非默认枚举**：界面只渲染当前可用项，全集多处未确认；需求要非默认值时停下来确认。
5. **系统规则映射只读**：要改只能在边上加 `dataItems`，或复制成自定义规则；系统规则本身不能改。
6. **字段映射的数值语义**：`mapped_relation` 四个值未确认，确认单里写中文映射方式，验收回读数字对账。

> 这六条不是「以后再说」，而是确认单里必须如实标注的边界——**不承诺做不到的事**，自动化才有可信度。
