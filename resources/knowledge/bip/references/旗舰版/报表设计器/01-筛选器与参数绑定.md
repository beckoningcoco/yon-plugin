## 1. 加一个筛选器的完整路径

1. 顶部 **「插入」→ 菜单最后一项「自定义筛选器」**。
   （「插入」是 `a.dropdown-text`，菜单项是 `.wui-dropdown-menu-item`；开菜单与点项要在同一次
   `browser_eval` 里做完，见 [[00-设计器总览与操作纪律]] §4。）
2. 顶部筛选器面板（`.filter-pane`）里出现一个筛选器组件，**默认类型是「下拉」**：
   组件 class 为 `filter-component active DROPDOWN reference filterPanel`，
   结构是 `<label>自定义筛选器</label>` + 控件 + 基本属性设置。
3. 选中它，右侧属性面板切到「**<类型> 设置**」→「属性」页签，在这里改：名称、
   **筛选器类型**、基本属性、类型专属设置、数据设置。

> 进筛选面板的另一条路：顶部菜单「筛选」（面板空时显示「请拖入筛选器类型或字段」）。

## 3. 「树形参照」怎么配 —— 组织树推荐走这条

右侧 →「**树形参照设置**」：

| 项 | 取值 | 说明 |
|---|---|---|
| **来源** | 该报表可用的**数据集 / 语义模型** | 实测下拉里就是这张报表挂的数据集，如「账户直联情况统计_总览」「账户直联情况统计_合计」 |
| **字段** | 拖入字段，可多个 | 如 `id`（值）、`code|name`（显示） |
| **树类型** | 父子树 | |
| **子级字段** | `id` | |
| **父级字段** | `parent_id` | |

其下还有「数据设置」：默认值 / 数据过滤 / 排序设置 / **参数绑定**。

### ⚠️ 口径（金隅 2026-10 实测结论）

组织树的**数据源要选语义模型自带的组织字段**，**不要**挂平台组织档案参照（即别用「系统参照」）：

- 语义模型里挂业务数据用的是 `org_source_id`（真实组织档案 ID，与业务表的 `orgid` 同一 ID 空间）；
- MDF 组织档案参照返回的是**平台档案自己的 ID**；
- 两边看着都像雪花 ID，其实不是一套，过滤条件会**恒不成立**且不报错。

配套事实：只有**带组织字段的那个语义模型**能用来组树。实测「账户直联情况统计_**合计**」里
只有 `name` ＋ 六个「合计××」指标，没有组织字段，必须先切到「账户直联情况统计_**总览**」
（含 `id` / `org_id` / `name` / `parent_id` / `code` / `source_org_id`）。

## 5. 参数绑定：把筛选器的值送进 SQL

### 5.0 ⚠️ 先看这条：语义模型改了参数，报表要先「更新模型」

**现象**：语义模型新增了参数，报表里「参数绑定」的**参数下拉是空的**（显示"暂时没有数据哦~"）。

**原因**：报表前端缓存了语义模型的**旧元数据**（页面加载早于你改模型）。

**解决（不用刷新页面、不丢编辑态）**：

1. 左侧字段区右上角那个 **加号**（`fieldid=design|datamodel_aside|ana_plus_icon`）
2. 弹出菜单 →「**选择模型字段**」
3. 面板右上角 →「**更新模型**」
4. 等 2~3 秒，报表设计器页签**自动刷新**，新参数就出现在参数绑定下拉里了

> 实测 2026-10-10：语义模型新增 `zlqk_orgid` 后，报表参数下拉为空；走完上面四步，
> 下拉立刻列出 `ytenant_id` / `org_epm_systems_id` / `zlqk_orgid`。

> ⚠️ **但「更新模型」同步不到"另一个数据集"的新参数**。同日实测：给「_合计」模型加了
> `zlqk_orgid_t` 后，走「更新模型」参数下拉里**仍然没有它**（只列主数据集 `_总览` 那三个）；
> **改成整页刷新（F5）后，四个参数齐全**。
>
> 结论：新参数属于**当前主数据集** → 「更新模型」够用；属于**另一个（如合计）数据集** → **整页刷新**。
> 另注意：「更新模型」之后**编辑态里未保存的参数绑定会消失**（已保存的不受影响），
> 刷新前后先对一下绑定表再动手。

### 5.1 绑定步骤（实测）

1. 选中筛选器组件（画布上方），右侧出现「<类型> 设置」
2. 右侧「**数据设置 → 参数绑定**」→ 弹「参数绑定」窗（含 `赋值参数` / `接收参数` 两个页签，默认「赋值参数」）
3. 点「**添加**」→ 行内新增一行，列：序号 / **参数** / **来源类型** / **值**
4. **参数**：选语义模型的参数（如 `zlqk_orgid`）
5. **来源类型**：`筛选器字段 / 系统变量 / 权限标签 / 常量`
   - 要取本筛选器选中的值 → 选「**筛选器字段**」
6. **值**：选该筛选器所绑的**字段**（如 `id`）—— 这里列的是**字段**，不是筛选器的名字
7. 「确定」→ 回设计器 **保存**（不保存不生效）

### 5.2 预览验证

- 右上角图标「**预览**」（`i.ap-yulan-01`）
- 预览态点筛选器右侧的参照图标 → 弹出组织树 → 勾选组织 → 「确定」
- 再点**筛选面板右上角的查询按钮**（`fieldid=filter_panel_handle_search_btn`）
- ⚠️ 报表设置 `filterQueryData=false` 时**改条件不会自动查询**，必须手点查询

> **筛选器加了不生效，按顺序查四件事**：① 参数绑定做了没；② 语义模型 SQL 里有没有对应的
> `${param(...)}` 与 `<#if>` 兜底；③ 改完语义模型后，报表里「更新模型」/整页刷新了没；
> ④ **明细与合计是两个数据集 —— 合计要单独绑一条**，只绑主数据集的话合计不会动。

### 5.3 实测结果（2026-10-10，账户直联情况统计表-管理口径）

| 已选条件 | 明细 | 合计 |
|---|---|---|
| 无 | 北京金隅集团股份有限公司 36 / 27 / 2 / 0.75 / 9 / 2 | 36 / 27 / 2 / 0.75 / 9 / 2 |
| `1003 冀东集团` | 冀东集团 2 / 1 / 1 / 0.50 / 1 / 0 | 同明细 |
| `1003 冀东集团,1005 地产集团` | 冀东集团 2/1/1/0.50/1/0 ＋ 地产集团 1/1/0/1.00/0/0 | **3 / 2 / 1 / 0.67 / 1 / 0** ✅ |

合计经过两个阶段（这就是"合计为什么要单独绑"的由来）：

1. **只给「_总览」加参数时** —— 合计**不随筛选变化**，恒为全量 36/27/2/0.75/9/2
   （合计行绑的是另一个数据集「_合计」，它没有那个参数）
2. **给「_合计」也加了 `zlqk_orgid_t`（子树口径）并在报表侧单独绑一条后** ——
   合计 = 2+1 / 1+1 / 1+0 / 2÷3=0.67 / 1+0 / 0+0，**逐项等于明细两行之和** ✅

> 要点：**明细与合计是两个数据集、两个参数名，报表侧要各绑一条**
> （`zlqk_orgid` 给明细、`zlqk_orgid_t` 给合计），来源类型与值都选「筛选器字段 / `id`」。

- 其余背景：参数语法、空值兜底、FreeMarker 位置规则 → [[07-经验-语义模型报表开发]] §一

### 5.4 ⚠️ 筛选器下拉「暂时没有数据哦~」/ 报表查出 0 行

这是一整类问题，**成因至少有五种**，别一上来就改配置：

| 命中率 | 根因 | 一眼判据 |
|---|---|---|
| ★★★ | **模型参数的默认值压根没被带上** | 参数在「参数设置」里**有默认值**，报表取数时却拿到空（**不是被别的数据集抢，而是根本没人传**）→ 该列全空。判据：同一 SQL 把值**写死在库里跑有数、报表里没数**。修法：SQL 里 `<#if>/<#else>` 兜底（见 [[../语义脚本编辑器/01-参数与固定值替换]] §6） |
| ★★★ | **同名参数冲突** | 该参数在报表里只有**一个** paramId，却有多张数据集的 SQL 引用它；而**独有**参数（如 `orgCode`）一直正常 |
| ★★★ | **改动没保存** | 模型页面「执行」能过、报表取数却是旧 SQL（模型「执行」读**编辑态**，报表读**已保存定义**） |
| ★★ | 引入的模型是**副本** | 取数请求 `wideTableModel.name` 带"‑副本"（编码形如 `..._copy1`） |
| ★★ | **控件类型错** | 模型没有层级字段却配成「树形参照」（面板里"子级字段/父级字段"下拉是空的，就是信号） |
| ★ | 参数被刷成 `$$$` | 筛选器绑了该参数但还没选值 → 参数默认值被覆盖成空 |

**完整排查法（抓请求 / 解 gzip body / 抓响应 / 库上实跑 / 逐参数对比）见 [[02-取不到数怎么排查]]。**

一句话：**先分层（下拉空 ≠ 报表 0 行）→ 找一张能用的报表做参照 → 看平台实际用了哪个模型、每个参数拿到什么值 → 库上把参数换固定值实跑一次**，就能把问题钉死在"参数"还是"SQL"上。

> 实测 2026-10-10：「组织报表体系」筛选器下拉空，最终钉死在**同名参数冲突** ——
> 该模型 SQL 用了 `${param('ytenant_id')}`，而报表里 `ytenant_id` 只有主数据集 `_总览` 的那一个 paramId，
> 模型自己的同名参数拿不到值、渲染成空 → 0 行（库上把该值写死能查出 2 行）。
> 租户这类"每个数据集都要用"的参数，改用**系统变量** `${var('tenantId')}` 可绕开合并。

### 5.5 两种「来源 = 语义模型」的参照筛选器：怎么挑、怎么配

同一个入口下其实是**两种控件**，选错要么取不到数、要么建不出树：

| | **普通参照** `REFERENCE` | **父子树参照** `REFERENCE_TREE` |
|---|---|---|
| 用途 | 选**平铺列表**里的一项（如"组织体系"列表） | 选**树**上的节点（如组织层级） |
| 来源 | 语义模型 | 语义模型（**别挂平台组织档案参照** —— 两边 ID 空间不同，过滤恒不成立且不报错） |
| **模型要求** | 有"值列 + 显示列"即可 | **必须有「子级 ID 列」和「父级 ID 列」两列**。缺了的话面板里"子级字段/父级字段"下拉是**空的**，配下去也查不出数据（本项目第一次就栽在这） |
| 面板要多配的项 | 来源 / 字段（拖入） | 来源 / 字段（拖入） / **树类型 = 父子树** / **子级字段** / **父级字段** |
| 定义里的标记 | `"iType":"REFERENCE"` | `"iType":"REFERENCE_TREE"` ＋ `"type":"PARENT"` ＋ `"tflds":[…]` |

**字段区（"拖入字段"）**：把来源模型要用的字段拖进去 ——
普通参照本例拖了 `id`/`code`/`name` 三个；父子树参照拖了 `id` 与 `code|name`。
拖少了只影响**展示列**，**不会**造成取不到数。
⚠️ 这个区域**不接受合成 `DragEvent`**（HTML5 拖放要真实手势），要走 CDP（见 [[00-设计器总览与操作纪律]]）。

⚠️ **定义里 `tflds` 的顺序与面板相反**（实测对照 2026-10-10）：

| | 面板显示 | 定义 JSON |
|---|---|---|
| 子级字段 | `id` | `"tflds":["parent_id","id"]` 的**第 2 个** |
| 父级字段 | `parent_id` | 同上的**第 1 个** |

即 **`tflds = [父级字段, 子级字段]`** —— 读定义时别按面板顺序理解。

**两个在用实例（可直接当样板）**：

| 筛选器 | 类型 | 来源 | 树类型 | 子级 / 父级 | 参数绑定 |
|---|---|---|---|---|---|
| 「单位」 | 树形参照 | 账户直联情况统计_总览 | 父子树 | `id` / `parent_id` | → `zlqk_orgid`（合计另绑 `zlqk_orgid_t`） |
| 「组织报表体系」 | 参照 | 报表组织体系查询模型 | —（无此项） | —（无） | → `org_epm_systems_id`（合计另绑 `org_epm_systems_id_t`） |

> 取证方式：**普通参照**那一列是本次**亲手配通**的（含拖字段、绑参数、保存、预览验证）；
> **父子树参照**那一列来自**在用实例**（「单位」筛选器）的**面板值与报表定义对照**，
> 不是本次新配 —— 下次若亲手配一遍，可把过程补到这里。

## 7. 用 `browser_*` 操作筛选器面板的坑（实测）

见 [[00-设计器总览与操作纪律]] §4，此处只列最常踩的三条：

1. 「插入」菜单**失焦即收起** —— 开菜单 + 点「自定义筛选器」必须在同一次 `browser_eval` 内完成。
2. 读下拉选项要过滤 `width > 0` —— 旧下拉的 option 残留在 DOM 里会串台。
3. **输入框分两种，别一律用原型 setter**（2026-10-10 修正）：
   - **参数值 / 脚本类**输入框：原型 setter + `input`/`change` 事件即可；
   - **筛选器「名称」这类属性输入框**：**不认**任何 setter 合成事件 —— 设了值看着变了，组件却仍显示旧名，
     **必须走真实键盘输入**（CDP `Input.insertText`，即 `browser_type`；先 `focus()` + `select()` 再输入可整体替换）。
   - 补救：**改一次「筛选器类型」**能让它"救活"（React 重渲染时把 DOM 值同步进 state）。
4. **「值字段」只认真实拖拽**（点击只弹树、双击不绑定）—— 见 §9 的 CDP 方案。
5. **勾选模型字段要点 `span.wui-tree-checkbox`**，点节点文字只会高亮 —— 见 §10.1。

## 8. 配一个筛选器的完整流程（实测：2026-10-10，账户明细表 一次配了 8 个）

> 这是"照着做就能成"的版本。**每一步用什么手段**都标出来了 ——
> 因为同一个面板里，**下拉认合成点击**、**「名称」只认真实键盘**、**「值字段」只认真实拖拽**，
> 手段用错的表现都是"看着设好了，其实没生效"。

```text
① 顶部「插入」→「自定义筛选器」     真实指针 browser_click（合成点击时灵时不灵）
② 改「名称」                        focus() + select() → browser_type（真实键盘！见 §7.3）
③ 改「筛选器类型」                  合成点击对下拉有效
④ 选「数据源」（下拉类型）          合成点击；选「数据模型」
⑤ 选「来源」= 本报表的数据集        合成点击
⑥ 拖「字段」（值字段）              ★ CDP 真实拖拽（点击/双击都不绑定，见 §9）
⑦ 「数据设置 → 参数绑定」→ 添加     合成点击
   三个下拉：参数 / 来源类型(筛选器字段) / 值    合成点击
⑧ 确定 → 保存                      留意「当前对象未保存」「已被对象引用」两个弹窗
```

### 8.1 筛选器类型与组件 class（实测补充）

| 界面名 | 组件 class 片段 | 备注 |
|---|---|---|
| 输入框 | `TEXT` | 面板有「值字段」拖放区 |
| 下拉 | `DROPDOWN` | 有「下拉设置 → 数据源」：**数据模型 / 自定义 / 接口** |
| 日期 | `DATE date` | 面板有「值字段」拖放区 |
| 树形参照 | `REFERENCE_TREE` | 见 §3 |
| 系统参照 | `REFERENCE_MDF` | 见 §4 |

**「下拉」的三种数据源**：

- **数据模型**（推荐）：选「来源」数据集 → 拖「字段」→ 选项即该字段的去重值，**传出去的就是字段值**；
- **自定义**：手动维护「值 / 显示值」两列 —— 适合作死的少量选项；
- **接口**：未实测。

### 8.2 参数绑定三个下拉怎么填

| 列 | 填什么 | 备注 |
|---|---|---|
| **参数** | 语义模型里已定义的参数名 | 选项来自**模型参数定义**，看不到新参数就是没「更新模型」（见 §10） |
| **来源类型** | 一般选 `筛选器字段` | 另有 `系统变量 / 权限标签 / 常量`；选完才会出现第三个下拉 |
| **值** | 该筛选器**绑定的字段** | **是字段，不是筛选器名字**；选项里可能带"来源××××"前缀 |

### 8.3 最容易踩的三条

1. **「名称」不能用原型 setter / 原生 setter** —— 只改 DOM，平台状态不接收（组件仍显示旧名）；
   > **补救**：改一次「筛选器类型」能把它"救活" —— React 重渲染时会把 DOM 值同步进 state。
2. **「值字段」点击只会弹字段树，点/双击节点都不会绑定** —— 必须 CDP 真实拖拽（§9）；
3. **「插入 → 自定义筛选器」合成点击不稳定** —— 用真实指针。

## 9. 用 CDP 真实拖拽绑定「值字段」

「值字段」是**纯 HTML5 DnD**：合成 `DragEvent`（`isTrusted=false`）不被接受，点击/双击节点也不绑定。
必须走完整序列：

```text
Input.setInterceptDrags(true)
  → dispatchMouseEvent(mouseMoved, 源)
  → dispatchMouseEvent(mousePressed, 源, button=left, buttons=1)
  → 分段 dispatchMouseEvent(mouseMoved, 逐步移向目标)   ← 过程中收到 Input.dragIntercepted
  → dispatchDragEvent(dragEnter / dragOver / drop, 目标, data=拦截到的 data)
  → dispatchMouseEvent(mouseReleased, 目标)
```

**要点**：

- `Input.dragIntercepted` 是**事件**（没有 `id`），要在 ws 的 message 里**单独接**；
- 必须**分段移动**（实测 12 段、每段 60ms 稳定触发）；
- 投递的 `data` 用**拦截到的原样**回填，不要自己造；
- **成功判据**：拖放区文案从「拖入维度或度量 / 拖入字段」**变成字段名**（`drop-area` 元素被替换掉）。

**可复用脚本**（本机跨会话）：`node drag-node.mjs <page片段> <源选择器> <目标选择器>`
用法：先用 `browser_eval` 给源/目标元素打上 id，再跑脚本。

> 同目录还有：`real-click.mjs`（按元素中心发真实左键、**不做 scrollIntoView**，适合点画布/菜单）、
> `right-click.mjs`（真实右键）、`activate-tab.mjs`（切页签）、`insert-column.mjs`。

## 10. 模型加了「字段 / 参数」之后，怎么让报表看得见

**三件事是分开的，都要做**（①②是老坑，③ 是 2026-10 新踩出来的）：

| 动作 | 作用 | 入口 |
|---|---|---|
| **① 更新模型** | 刷新**模型元数据** —— 新**参数**、新字段定义 | 左侧字段区右上角 **加号** →「选择模型字段」→ 面板右上角「**更新模型**」 |
| **② 勾选字段** | 决定**哪些字段进报表**（字段树、可选值字段） | 同一个面板里**勾选**目标字段 → 确定 |
| **③ 把新参数加进「分析参数」** | 决定它**能不能被"传参"选中**（筛选器参数绑定 / 超链接参数赋值） | 顶部「数据」→「参数」→ 页签「**分析参数**」→「添加」→ 填参数名 + 类型 → 「确定」→ **保存报表** |

> ⚠️ **①和③写的是两张不同的表，别指望①能把③带出来。** 这一步单独讲，见 §10.5。

### 10.1 ⚠️ 勾选不是 `input[type=checkbox]`

字段行是 `<li class="wui-tree-treenode">`，**勾选控件是里面的 `span.wui-tree-checkbox`**：

```html
<li class="wui-tree-treenode ...">
  <div class="wui-tree-treenode-line-content">
    <span class="wui-tree-switcher ..."></span>
    <span class="wui-tree-checkbox">              <!-- ← 点这个！ -->
      <span class="wui-tree-checkbox-inner"></span>
    </span>
    <a class="wui-tree-node-content-wrapper">…<span class="wui-tree-title">字段名</span></a>
  </div>
</li>
```

- **点 `li` / `a` / `span.wui-tree-title` 只会高亮，不会勾选** —— 本轮就在这儿白折腾了很久：
  以为勾上了，其实没有，字段当然进不了报表；
- **点 `span.wui-tree-checkbox` 才切换**；勾上后 class 变 `wui-tree-checkbox-checked`；
- **已在报表里的字段**是 `wui-tree-checkbox-disabled wui-tree-checkbox-checked`（**不能取消**）；
- 判定：

```js
const li = [...document.querySelectorAll('.wui-modal li')].find(e => e.textContent.trim() === '字段名');
/checked/.test(li.querySelector('span.wui-tree-checkbox').className);   // true = 已勾选
```

### 10.2 「更新模型」会弹确认窗 + 触发整页刷新

- 弹「**更新模型字段**」窗，里面有个 **`删除原宽表已删除未使用的字段`** 复选框 —— **默认不勾就别动它**（勾了会删字段）；
- 点确定后**报表页签整页刷新**：`browser_eval` 会报 `Inspected target navigated or closed`，**这是正常的**，等 3~5 秒重连即可；
- **刷新之后**，新参数会出现在「**模型参数绑定**」那一页里（`数据 → 参数`）；
- ⚠️ **但它不会自动进「分析参数」** —— 所以筛选器的「参数绑定 → 参数」下拉、超链接的「所需参数」下拉里**仍然看不到它**，还要做 §10.5 那一步。

> 🔄 **2026-10-11 修正**：金隅 dev 实测，本版本「更新模型」**确实会把新参数一并带进「分析参数」**
> （打开 `数据 → 参数 → 分析参数` 就能看到它，无需再手动「添加」）。
> **但界面里看到 ≠ 已落库** —— 必须再**保存报表**；保存前读服务端 `analysisModel.params` 里**仍然没有它**。
> 判据：保存后 `GET /iuap-data-analytic/report/design/<报表ID>` 的 `analysisModel.params` 里能否找到该参数名。
> 若你的版本没带进来，仍按 §10.5 手动「添加」即可。

### 10.3 顺序建议

```text
模型侧：定义参数 / 改 SQL → 执行 → 保存（弹「已被对象引用」点「修改」）
报表侧①：加号 →「选择模型字段」→（勾新字段）→「更新模型」→ 确定 → 等刷新
报表侧②：数据 → 参数 →「分析参数」→ 添加（参数名 + 类型）→ 确定
报表侧③：保存报表（右上角保存图标 ap-baocun-011）
        → 之后筛选器的「参数绑定」、超链接的「参数赋值」才能选到它
```

> **反例一（老坑）**：模型加了参数，报表里直接去配参数绑定 → 参数下拉里**没有那个参数**，
> 因为报表还没「更新模型」。
> **反例二（2026-10 踩的，更隐蔽）**：「更新模型」也做了，报表的「模型参数绑定」里也
> 明明白白列着这个参数，可超链接的「所需参数」下拉里**还是没有** —— 因为那个下拉读的是
> 「**分析参数**」，而它没被加进去。**见 §10.5。**

### 10.4 另一个容易漏的弹窗

切换/刷新过程中会弹「**当前对象未保存，请确认是否保存？**」—— 点「**确定**」= 保存当前编辑，
点「取消」= 丢弃。它常和未保存的筛选器改动一起出现，别习惯性点取消。

### 10.5 ⭐「模型参数绑定」≠「分析参数」（2026-10 实测）

`数据 → 参数` 那个弹窗有**两个页签**，名字都带「参数」，作用完全不同：

| 页签 | 是什么 | 谁在读它 |
|---|---|---|
| **模型参数绑定** | 「**模型参数 → 分析参数**」的映射表。列：序号 / 名称 / 源操作符 / 源参数 / 值类型 / 值 | 「更新模型」**只写这里** |
| **分析参数** | 报表**自己的**参数清单。列：序号 / 参数名称 / 参数类型 / 设置默认值 | **筛选器的参数下拉、超链接的「所需参数」下拉读的是这里** |

**症状**（本次实测）：语义模型里加了参数 → 报表侧「更新模型」→ 报表的「模型参数绑定」里
**已经出现它**（实测某行：`账户明细表 等于 组织含下级`）→ 但配超链接时，
「参数赋值 → 所需参数」下拉里**始终没有它**，在输入框里搜它只回一句「暂时没有数据哦~」。
**刷新页面、关掉弹窗重开、保存报表，全都没用。**

**解法**：

```text
设计器 → 顶部「数据」→「参数」→ 弹窗「参数设置」
  → 页签「分析参数」→ 点「添加」
      → 新行填：参数名称 = <与模型参数同名>、参数类型 = 字符
  → 「确定」
  → 保存报表（右上角保存图标）
```

做完之后下拉里立刻能选到它（本次实测报表 `analysisModel.params` 由 22 项变 24 项）。

**判据**（不用来回试下拉）：

```js
// 该参数有没有进「分析参数」—— 看 analysisModel.params
const j = await (await fetch(
  `/iuap-data-analytic/report/design/<报表ID>?serviceCode=report-51&listType=DIRREPORT&locale=zh_CN&systenant=U8C3`,
  {credentials:'include'})).json();
JSON.stringify(j.data.analysisModel.params).includes('参数名');     // true = 已经进去了
```

> 另有一个接口一次性返回目标报表的页签、数据集和参数，查「超链接能选到什么」很方便：
> `GET /iuap-data-analytic/analysis/params/<报表ID>` → `{ sheets, wideTableModels, params, anaModelType }`。
> 其中 `sheets` 里的 id 就是超链接「页面选择」用的**页签 id**。

## 12. 「日期范围」筛选器：一个控件、两个参数

实测 2026-10（账户明细表，由使用者配好后对照面板与定义确认）。

**一个「开始 ~ 结束」的日期区间不需要两个筛选器** —— 一个日期筛选器改一下「操作符」就够了。

| 项 | 取值 |
|---|---|
| 筛选器类型 | **日期** |
| 名称 | 例如 `开户日期起`；面板上会显示成 **`开户日期起 ~`** |
| **操作符** | **介于** ← 开关就在这一项 |
| 值字段（拖放区） | 日期字段，如 `开户时间` |
| 默认规则 | 空值返回所有数据 |
| 提示文本 | **两个**输入框（开始 / 结束各一个） |
| 日期天数跨度 | 无限制 |

「操作符」改到「**介于**」之后，控件从单个日期框变成 `开始日期 ~ 结束日期` 一对；
筛选器的 class 也从 **`DATE date`** 变成 **`bt DATE date`**（`bt` = between）。

⚠️ **参数绑定要写两行** —— 这是最容易漏的一点：

| 序号 | 参数 | 来源类型 | 值 |
|---|---|---|---|
| 1 | `开户日期起` | 筛选器字段 | **`开户时间开始`** |
| 2 | `开户日期止` | 筛选器字段 | **`开户时间结束`** |

也就是说：**日期字段在「值」下拉里会派生两个选项 —— `<值字段>开始` 与 `<值字段>结束`**，
分别对应控件的左右两个输入框。一个筛选器同时驱动两个参数，不必再配两个筛选器。

配套 SQL（两个参数各自一个 `<#if>`）：

```sql
<#if param('开户日期起')?? && param('开户日期起')!=''>
  and a.accountOpenDate >= to_date('${param('开户日期起')}', 'YYYY-MM-DD')
</#if>
<#if param('开户日期止')?? && param('开户日期止')!=''>
  and a.accountOpenDate &lt; to_date('${param('开户日期止')}', 'YYYY-MM-DD') + 1
</#if>
```

> 上面用 `< 止 + 1 天` 来实现**按日期的左闭右闭**（时间列本身带时分秒）。
> 口径要严格 `<= 止` 时直接把条件写成 `a.accountOpenDate <= to_date(...)` 即可。

## 13. 筛选器显示在哪：弹出框模式 / 顶部平铺模式

实测 2026-10（账户明细表，由使用者指路后亲手切了一遍）。

**默认是「弹出框模式」**：预览（点设计器右上角的眼睛图标）时界面上**一个筛选器都看不到**，
必须点右上角的「**查询**」按钮，才弹出「高级查询」面板，筛选器都藏在那个面板里。

**要让它直接平铺在报表表头**：

```text
设计态 → 顶部菜单「浏览」→「筛选器设置」→「筛选器模式」→ 选「顶部平铺模式」→ 保存
```

⚠️ **「筛选器设置」是子菜单，不是普通菜单项** —— 它右侧有个小三角
（`<span class="ap ap-anglearrowpointingtoright">`）。
**点击它只会把整个「浏览」菜单关掉**，什么也不会发生；必须把**鼠标悬停**上去，
子菜单才会展开，「筛选器模式」在里面。程序化操作时点击/合成事件都不行，要用 **`browser_hover`**
（工具内置：两段式 CDP `mouseMoved` 并停住，默认 900ms。老的 `scripts/hover.mjs` 是同一件事，
但它要 shell 跑 node —— 能用工具就别用脚本）。⚠️ 悬停后指针不能再动：要读 DOM 只用 `browser_eval`，
再 `browser_click` 或再 hover 一次都会让子菜单收回去。

「筛选器模式」只有两个单选项：

| 选项 | 含义 |
|---|---|
| **弹出框模式** | 默认。筛选器收在「查询」按钮弹出的「高级查询」面板里 |
| **顶部平铺模式** | 筛选器平铺在表头，任何时候都看得见 |

**切换后的现象**（实测）：预览时表头直接出现筛选器，右上角按钮由「**查询**」变成「**收起查询**」。

⚠️ **平铺是横向排的，一行能放几个由筛选器自己的宽度决定**。
本例每个筛选器在设计态是 `width: 20%`，所以**一行只放 5 个**；容器
`div.filter-panel-box` 的高度固定（实测 40px），**放不下的会换行然后被裁掉、看不见**。
本报表 9 个筛选器，切到平铺后只看得到前 5 个（账户编码 / 账户户名 / 是否直联行 / 账户状态 / 开户日期起 ~），
后 4 个（开户银行 / 账户用途 / 组织 / 报表体系）在 DOM 里但不可见。
→ **筛选器多的时候，要么把每个的宽度调窄，要么减少数量。**

相关 DOM（便于定位与取证）：

```text
div.filter-panel-box              容器（display:flex，实测高 40px）
  div.filters-container           放筛选器（高 32px，overflow:auto）
    div.filter-component.<类型>   每个筛选器，宽度写在行内 style 上
  div.f-operations-brower         右侧操作区，顶部平铺模式下放「查询」按钮
                                  (fieldid = filter_panel_handle_search_btn)
```
