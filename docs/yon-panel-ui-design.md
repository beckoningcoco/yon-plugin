## 二、方法：结论只能来自实测

三种证据，缺一不可。**前两种会骗人，第三种不会。**

| 证据 | 是什么 | 能回答 | 不能回答 |
|---|---|---|---|
| **宿主的真实样式源码** | `deepseek-harness-neuron/packages/client/ui-primitives/src/*.module.css` | 原子到底画了什么（token、尺寸、有没有 focus 规则） | 合成后的实际观感 |
| **预览出图** | `preview/render.spec.tsx` → `panel-*.html` + `node preview/shots.mjs` → PNG | 整体观感、对齐、溢出 | 具体数值；**而且截图最容易骗人，因为它看起来像证据** |
| **临时度量脚本** | headless Chrome + 注入探针，量 computed style 与几何 | 一切可判定的事实 | — |

度量脚本全部写在临时目录（`%TEMP%\mk*.mjs` + `run*.mjs`），**不进仓库** —— 它们是一次性的，
进仓库就会有人以为要维护。

三条铁律：

1. **读代码得到的结论不算结论。** "Input 的边框是 `border-l4`" 是在源码里读到的，
   但"这个 select 的边框和它一样"必须量出来。
2. **量出来的数字要能推翻自己的方案。** 本轮有两处方案是被数据推翻的（3.2 / 3.4），
   推翻后按数据改，并把实测值写进注释 —— 否则下一个人会再"修"回去。
3. **根因未明就写"未明"。** 本轮有一个未解的观察（见第七节），它的价值就在于标着"未解"。

## 三、可直接抄的结论

### 3.1 亮色模式下，层级只能用描边 —— 不能用填充

**主题在亮色下把三个背景层解析成同一个值。** `bg-layer-1` / `bg-layer-2` / `bg-layer-3`
全部等于 `--dsw-static-neutral-bluish-00`。实测（启动器 / 面板所在的那张对话框）：

| 元素 | 亮色 computed background | 与容器的判定 |
|---|---|---|
| 对话框 | `rgb(255,255,255)` | — |
| 输入框的 `.wrap` | `rgb(255,255,255)` | **FLUSH**（和容器同值） |
| 未选中的药丸 ×2 | `rgb(255,255,255)` | **same-as-dialog = true** |
| 选中的药丸 | `rgb(235,238,242)` | raised |

后果：任何"用背景色深浅表示层级"的手法，在亮色下**什么都不会发生**；而暗色下它会生效
（实测未选中药丸的填充是 `44,44,46`，对话框是 `67,69,74`）。所以填充方案会变成
"一个主题有效、另一个主题看起来像漏改了"。

主题自己的注释就写着：**「柔光几乎不可见，由描边承担分离」**。

**给下一个面板的结论**：层级差一律用描边（`border-l*`），不要用背景填充。药丸、分段控件、
未选中态都属于这一类 —— 本项目里分段控件的轨道就是一条 `border-l2`，而不是一个底色。

### 3.2 平台的状态色是按**暗色**调的

实测对比度（对对话框底色）：

| token | 亮色 | 暗色 | 本插件用它画 |
|---|---|---|---|
| `state-success-primary` | **2.28:1** | 6.12:1 | 「合格」徽章、可写查询的进度条 |
| `state-error-primary` | 4.50:1 | 4.24:1 | 「不合格」徽章、失败行 |
| `state-warn-primary` | 2.40:1（作文字）/ 2.15:1（作环） | 未测 | 没敢用（见第七节） |

**给下一个面板的结论**：绿色在亮色下**不能当小字用**。这不是本插件的问题，是宿主状态
调色板的缺口，正确的修法是宿主侧补一档亮色专用的对比度，而不是在插件里编一个绿。

### 3.3 用"文字自己的颜色"去 tint 填充，只会让对比度更低

宿主新版的 `Tag` 原子就是这么做的：`background: color-mix(in srgb, <状态色> 10%, transparent)`
+ `color: <同一个状态色>`。看起来优雅（一个 token 同时管填充和文字），实测是**净损失**：

| tone | 填充后的文字对比（亮色） |
|---|---|
| outline | 3.71:1 |
| quiet | 3.71:1 |
| success | **2.09:1** |
| info | 3.74:1 |
| warning | **1.96:1** |
| danger | 3.80:1 |
| solid | 18.90:1 |
| neutral | 5.36:1 |

八个 tone 有六个不到 4.5:1；**同一批在暗色下全部通过**（4.94 起）。同一个模式在本插件
`.error` 块上也量到过：红字单独 4.50:1，放在 10% 自身红的底上掉到约 **3.8:1**。

**给下一个面板的结论**：小徽章用**描边**（文字色 + 同色描边），不要用自身色 tint 填充。
tint 只会把底色往文字色推近，数学上永远降对比，不会升。

### 3.4 `-secondary` 是**色阶**，不是**音量**

`state-success-secondary` 的语义是"这个色相的浅一档"，不是"更安静的那个"。对照明暗两色：

- 亮色下，浅一档看起来更安静 —— 符合直觉；
- 暗色下，`state-success-secondary`（`78,209,126`）比 `state-success-primary`（`34,197,94`）
  **更亮**，于是"更安静"的环反而盖过了它围着的字；
- 更糟的是 `state-error-secondary` 和它自己的 `-primary` **是同一个红**（`242,90,90`），
  整个改动在失败态上是个 no-op。

**给下一个面板的结论**：**一对在明暗两色下语义会翻转的 token，承载不了"更轻/更重"这种
跨主题稳定的含义。** "音量"要靠尺寸、字重、描边有无来表达，不要靠色阶。

### 3.5 字号与圆角的收口（具体数值）

**字号从 6 档收到 4 档**，判据是"每一档要有明确的职务"：

| 档 | 职务 |
|---|---|
| 16px | **不是文字层级**：只有一处，`.rowIcon` 里那个 `×` 字形（24px 按钮内的图标字号），刻意不动 |
| 14px | 面板标题 / 关键数值 / 正文强调 |
| 13px | 次级**内容**：列表行名、卡片标题、搜索结果的页名。**控件不在这档**——控件全归 12px（见 3.14） |
| 12px | 其余全部：说明、标签、时间戳、表格文字、脚注 |

被删掉的两档：**11px**（21 处；它是"比最小还小"，没有职务）和 **15px**（4 处；它夹在
16 的 chrome 标题下 1px —— 那不是一档，是"差一点"，读起来像没收干净）。

**圆角从 9 种收到 3 种**：`8px`（一切盒子）、`999px`（一切胶囊/标签/进度条）、
`12px`（只有一处：启动器弹层 `YonPanelRoot .panel` 的外壳），外加零散的
`border-*-radius: 0` 归零。

**给下一个面板的结论**：**先列直方图，再问每一档的职务。** 只有一个使用者的尺寸不是一档。
"看起来差不多"的相邻值（14/15、11/12）要合并 —— 相邻两档差 1px 时，读者看到的是
"没对齐"，不是"有层次"。发丝描边的两档 alpha 同理（见 3.6）。

### 3.6 描边分三级，第四级刻意不用

| token | alpha | 职务 |
|---|---|---|
| `border-l1` | 0.04 | 物体**内部**的线：行分隔、tab 下划线、芯片内边 |
| `border-l2` | 0.10 | 插件的**容器**：卡片、说明块、筛选胶囊、分段轨道 |
| `border-l4` | 0.16 | **控件与小物件**：要和 Input 看齐的 picker、徽章 |
| `border-l3` | 0.12 | **不用** —— 见下 |

`l3` 是宿主描边 Button 的档位，和 `l2` 只差 **2 个 alpha 点**。采用它等于在"刚把 11 种圆角
收敛到 3 种"的同一次改造里，重新引入一个**肉眼不可辨的区别**。

**给下一个面板的结论**：**一个刻度值得存在，前提是它的档位能互相区分。**
如果两个值在合成后落进同一条看不见的区间，那它们不是两档，是一档写了两遍。

### 3.7 焦点环用**状态** token，不用 primary 填充

`.filter:focus-visible { outline: 2px solid var(--dsw-alias-button-primary-fill) }` 看起来
很"主色"，但 `button-primary-fill` 在亮色下解析成 **`rgb(15,17,21)`** —— 和 `label-primary`
是同一个近黑色。于是这个环在说"这是一个主操作"，而它真正要报的新闻只是"键盘在这"，
用的还是这个界面上最没有信号的颜色。

对照：宿主自己的 `Input.module.css` 里 `.wrap:focus-within { border-color: var(--dsw-alias-state-business-primary) }`。

**给下一个面板的结论**：**焦点是状态，所以用状态色。** 全部焦点环统一到
`state-business-primary`，和宿主 Input 的 focus 一致。`outline-offset` 的各个值
（本轮是 −2/−2/1/−2/2/2）**是几何不是审美** —— 每一个都是为了不被祖先的 `overflow`
裁掉、或不被邻居的边框压住，不懂就不要顺手改。

### 3.8 小物件要**更强**的描边，不是同一档

徽章一开始用 `border-l2`（和容器同档）。出图后发现：**选中行里的「已归档」胶囊整个消失，
正下方同一行的却清清楚楚。** 量下来：选中行的填充是 `rgba(38,49,72,0.1)`，
`l2` 合成在上面只有 **1.25:1**，`l4` 是 **1.44:1**。

**给下一个面板的结论**：**描边强度要随物体变小而变强。** 300px 的卡片可以承受 10% 的线，
19px 的胶囊不行 —— 那条线就是它的全部形状。改 `l4`。
（诚实备注：两条都不到 3:1 的非文字标准，落在染色行上**仍然是淡的**；真正的修法是宿主侧
再给一档更硬的 outline。别在插件里编颜色。）

### 3.9 自研规则 vs 宿主原子：先查有没有，但要查**运行时的那个**

宿主发布了 `Tag` 原子（`border-radius: 999px; padding: 1px 8px; font-size: 11px`，
以及 `outline/solid/neutral/quiet/success/info/warning/danger` 八个 tone），
看起来正是本插件四个手写徽章该迁移过去的地方。查完**不能采用**，两条独立理由：

1. **插件运行所在的那个宿主根本没有它。** primitives 是 `devDependencies`
   （`package.json:74`）+ 构建时 external（`tsdown.config.ts:42`），**由宿主在运行时提供**。
   宿主自己的 `ui-primitives/src/index.ts` 导出清单里没有 `Tag` —— 原子比宿主新
   （已发布 `0.1.7-rc.2`，宿主 `0.1.2-rc.1`）。写 `<Tag>` 会解析成 `undefined`，**面板渲染直接崩**。
2. 即使有，它的配色在亮色下更差（见 3.3）。

**给下一个面板的结论**：
- 迁移前必须核**宿主导出清单**（`ui-primitives/src/index.ts`），不是 `node_modules` 里那份
  发布包 —— 两者版本可以不一致，而崩溃现场在宿主那边。
- 即使不采用，也把几何**贴齐**它（本插件保留了 999px 胶囊与同样的 1px 内缩），
  这样将来迁移是"换四行渲染点"，不是重新设计。
- 差异要写明（本插件 12px/16px/侧边 6px，原子是 11px/17px/侧边 8px，因为 11px 已从刻度中删除）。

### 3.10 CSS 变量跨消费上下文时，相对单位会出错

`--time-col` 同时被用在两处：网格轨道（`.logHead` 的 `grid-template-columns`）和
`calc()` 内边距（`.logDetail` 的 `padding-inline-start`）。两处**字号不同**，
所以 `em` 会各自解析成不同的 px，**两处立刻对不上**。这就是它必须是 px 值的唯一原因。

**给下一个面板的结论**：一个自定义属性被两个不同字号的上下文消费时，**不能写相对单位**。
写成 px，并把"为什么不是 em"写在旁边。

顺带一个真回归：这个值原本是 `132px`，是按 11px 时间戳定的；字号统一到 12px 后，
同 19 个字符在 Consolas 需要 **125.4px**、在 SF Mono（macOS 的 `ui-monospace`）需要 **136.8px** ——
132px 在一端已经放不下、在另一端只剩 6.6px 余量。改成 `140px`。
**收口量表的时候，要去检查所有"按老字号算过"的固定尺寸。**

### 3.11 折叠线外的提交：底部吸顶，且必须写 `:last-child`

一个面板**唯一的写入路径**落在折叠线外时，用底部吸顶治（`.detailActions:last-child`
的 `position: sticky; bottom: 0`）。下面所有绝对数都来自 900x820 预览视口下的探针布局
（探针报的数与出图那份布局对不齐，见 5.1 末条）；pane 多高是窗口的事，规则本身对
"装得下"和"装不下"两种情形都成立。四条可抄的：

1. **用 sticky，不用固定页脚。** 它不需要预算高度、也不需要知道内容多高：`bottom: 0`
   只在"自然位置本来就在折叠线下方"时生效，滚到内容末尾它会回到流里。所以凡是这一行
   本来就在可视区内的状态（数据源详情态：内容 265px 装进 450px 的 pane，行底距 pane
   底 185px）**逐像素不变**。
2. **底色只能用对话框自己的那个 token。** 吸顶行必须不透明，否则内容从按钮底下透出来；
   而写死 rgb 会同时踩两条规矩。判据是"宿主画卡片用的是哪个"——`ui-primitives/Modal.module.css`
   用 `--dsw-alias-bg-layer-2`，且 `.detailPane` 自身没有底色，所以 `layer-2` 就是它坐着的
   那个面。两个主题都量过：`rgb(255,255,255)` / `rgb(44,44,46)`，各自等于卡片底色。
   于是这条 bar 平时**完全不可见**，只有内容从底下经过时才看得见，加一条 `border-l1`
   顶描边（与 `.rule` 同一档）交代边界。
3. **`:last-child` 是前提，不是装饰。** 吸顶只对"这一行的内容就是被滚掉的那部分"有意义。
   项目管理那一行后面还有 `<hr>` 和字段表，静止时在 pane 底上方 302px——视口滚 50px 它
   跟着上移 50px，**它没吸**，也不需要吸：它的动词一直在屏幕上，吸顶在那里只会多出一条
   离 `<hr>` 10px 的描边，并把一个破坏性动词钉在滚动表上方。
4. **判据必须可证伪：别看静止截图。** 该吸的地方在静止时本来就"看起来正常"（数据源表单
   改前那张截图里 `保存/取消` 只是位置低一点，看不出它是"唯一的提交"）。判据是**视口滚
   50px，看这一行的 `rect.top` 动不动**：不动=吸顶，跟着上移 50=还在流里。顺带量两项副
   作用：`rect.bottom` 是否贴住 pane 底（贴住=不会有一条缝把内容漏出来）、滚到 max 时它
   是否回到自己位置（回到=没有任何内容被永久盖住）。

### 3.12 "标签 + 值 + 分母"的量表：整块共用一张网格，不要每行一张

一行一条、值要按内容定宽又要跨行对齐的量表（wiki 概览的"连通度"五行），三条可抄，
数值来自 900x820 视口、pane 宽 387.5px 的探针：

1. **网格写在容器上，行本身 `display: contents`。** `max-content` 是**按网格算的**：
   每行各成一张网格时，五行的值列各按自己那行的值定宽（实测 29.60 / 22.20 / 37.01px
   三种），值列之后的所有列都跟着抖。写到容器上一次算：`132px 37.0078px 200.492px`，
   三列左右沿差全部为 0。
2. **每行第 1 列的元素要显式 `grid-column: 1`。** 行里缺末尾格子（有的行没有分母）
   会在那一行留下一个洞，**下一行的首个元素会被自动排布填进那个洞里**——实测两行挤到
   同一行上（标签顶差 `21 21 0 64`），一个标签跑到第 3 列、一个值跑回第 1 列。
   首列钉住后：五行 15px 高、行距 21px（15 + 6 沟）。
3. **跨满整块的一行注脚要 `grid-column: 1 / -1`**，它会独占一整行；实测行距 43px
   = 15 行 + 6 沟 + 16 注脚 + 6 沟。

配套的两条：值列 `max-content` 只是让**列**定宽，值本身还要 `text-align: right` 才对齐
（值右沿→分母左沿实测 8px，改前 50.4px）；而"值列写死 72px"这种拍脑袋的宽度必须删掉。
**注脚放不进行里就别硬塞**：段注脚一行要 293.48px，塞进 165.5px 的格子里会把那一行撑成
两行（30px，其余四行 15px）；它放得进整块宽（387.5px），所以挪出去自成一行，五行才等高。

**两个代价，先认下**：

- 值列右对齐后，**没有分母的行**的数字会往右多推一段（最多个值列宽 − 该值墨迹宽 ≈ 37px）。
  这是右对齐数字列的正常长相；真正占大头的是它左边那条 132px 的标签列——**别为了这个去
  收窄标签列**：实测最长的标签正好占满 132px、零余量，收窄它会连累下面能力条的长度。
- `display: contents` 的元素**没有盒子**：`getBoundingClientRect()` 在它身上没有意义，
  `getComputedStyle(行).gridTemplateColumns` 读出来是 `none`。探针要量格子，别量行
  （本该量 `.statValue` 三个字）。

### 3.13 行尾那个控件：它的宽度不能随状态变；"读我"的文字不能挂在清单下面

缺口行的网格是 `20px minmax(0,1fr) auto auto`。后两列都是 `auto`，于是**倒数第二列
（被引用次数）的右沿 = 行右沿 − 末列宽 − 8px**；而末列是展开键，标签在「看谁引用它」
与「收起」之间换 —— 被引次数就跟着跳：实测同一页上展开那一行比其余九行**靠右 36px**
（688 → 724），只要有一行展开，这一列就不再是一列。

1. **判据**：量"同一列在不同行上的右沿差"（探针按列取 min/max）。0 = 齐；36 = 差一整段
   标签。**别去怀疑数字宽度**：数字宽度只值 7.03px（4 位数与 3 位数差一位），36px 那个
   量级一定来自控件。
2. **修法**：让控件的宽度与状态无关——两个标签**叠在同一格里**（`display: inline-grid`
   + 子元素全 `grid-area: 1 / 1`），隐形的那个 `visibility: hidden` + `aria-hidden`，
   只贡献宽度。于是按钮宽 = 最长标签宽，与本行展开与否无关，也没有写死 px（写死会在别的
   语言里崩：en 的 `See who cites it` 比 `Hide` 长得多）。修后第 3 列右沿差 0、第 4 列
   左沿差 0。代价是末列从"右对齐"变成"左对齐"（收起那行右边留下一段空），可接受。
3. **配套**：这种"右沿固定、左沿随内容"的数字列要 `font-variant-numeric: tabular-nums`
   才从右往左一位一位对齐。同一张表里 `.tabCount` / `.statValue` / `.levelCount` /
   `.levelShare` / `.gapRank` / `.relCount` / `.termCount` / `.logDate` 八个都带着，
   只有 `.gapCited` 和 `.statNote` 漏了（本批一起补）。**左沿仍差 7.03px 是右对齐数字列
   的固有长相，不要再追。**

同页量到的另一条：**"读我"的文字不能挂在清单下面。** `wiki.gapNote` 原本挂在缺口清单
**下面**——探针量它顶边在 pane 顶下方 **460px**、本身 **48px**（三行），而 pane 只有
**450px 高**：一个字都看不见。也就是说"这份清单要读，不能当待办直接执行"这句提醒，从来
没有被人读到过。挪到清单上面后 top=185，进画面；代价是清单被推下 66px（可见行 10 → 8）。
**判据：任何"读我"的文字都要量 `rect.top` 与 pane 高**，不要只看它在 DOM 里的顺序对不对。


### 3.14 按钮不继承字体，也不继承字号——所以按"是不是拿文字画的"分流

平台给表单控件的是浏览器 UA 默认值：Chrome/Windows 上是 `font: 400 13.3333px Arial`。
宿主的六张主题表**没有一张**写 `font-family`，宿主的 `Button.module.css` 也只写了
`font-size` / `line-height`——**宿主自己的按钮也是 Arial，纯属巧合**，不是设计。所以
"插件里的按钮是 Arial" 从来不是"跟随了宿主"，只是两边都拿到了同一个默认值。

**代价很小，但不是零，而且不是观感问题。** 实测（同一串字，12px，Arial vs system-ui）：

| 串 | Arial | system-ui | 差 |
|---|---|---|---|
| `概览`（纯 CJK 2 字） | 24 | 24 | **0** |
| `刷新`（纯 CJK 2 字） | 24 | 24 | **0** |
| `看谁引用它`（纯 CJK 5 字） | 60 | 60 | **0** |
| `ucfbases.ucfbaseItf.IYTenant`（纯拉丁） | 154.10 | 160.29 | −3.9% |
| `被引用 1566 次`（数字 + CJK） | 81.37 | 83.25 | −2.3% |
| `2026-09-29 01:44:30`（数字 + 符号） | 111.43 | 118.23 | −5.8% |
| `报价历史表头自定义项-lawbid_…`（CJK + 拉丁） | 397.50 | 421.16 | −5.6% |

Arial 里没有汉字，纯中文串两种写法**落到同一个中文回退字体**，墨迹完全相同——所以
"跟面板"对一个中文界面几乎没有可见代价。真正的理由是换台机器（Arial 不一定还在）
之后连纯中文的宽度都会变；把字体写死在一个 UA 默认值上，等于把排版交给抽签。

**还有一个更隐蔽的坑：按钮连 `font-size` 也不继承。** `.citerList` 声明了
`font-size: 12px`，而 `.citerLink` 是 `<button>`——它渲染成 **13.3333px**，同一串引用者名
**441.56px** 而不是 **421.16px（宽 4.8%）**。**容器声明的字号对表单控件等于没声明**，
要显式再写一遍 `font-size: inherit` 才接得上。

**本批采用的划线：按"是不是拿文字画的"分流。**

| 类别 | 例子 | 跟谁 |
|---|---|---|
| 用文字画的控件 | wiki `.tab` / `.citerLink` / `.cardClose`，共享的 `.foldToggle` | **跟面板**（`font-family: inherit`，必要时 `font-size: inherit`） |
| 带盒子的宿主原子 | `.pb-button`（刷新 / 重建索引）、`.pb-input`（搜索框） | **跟宿主，不改** |

后者不动的原因是**将来**：宿主哪天自己补上 `font-family`，这两种会一起变；而插件里
这几条会变成应用里唯一的例外——一个只有我们看得见的接缝。

**字号也跟着这条线走**：控件全归 12px，13px 只留给内容。依据是宿主的两档制
（`Button`/`Input`/`Menu.item` 14px，`Button.sm`/`Pill`/分组标签 12px，13px 全库只有
3 处），以及"一排选择"这种控件在插件里必须是同一个字号。实测：页签 13 → 12 后与
digest 的筛选同号，页签盒高 30.5 → 29（下面内容上移 1.5px）；数据库类型下拉
13 → 12，盒高仍是 28px。

**判据：** 对整页的 `button, input` 做一次普查，打印 `getComputedStyle` 的
`fontFamily` / `fontSize` 与**该串在该字体下的墨迹宽**。改完要能看见那条分界线：
面板自己的按钮是 system-ui，宿主的按钮仍是 Arial；并且容器与控件的字号要**逐对相等**
（`.citerList 12px` ↔ `.citerLink 12px`）。这条普查也顺带翻出一颗没有文字的按钮
（对话框的 `×`，UA 给它 Arial——无字，无害）。


## 四、改动顺序：为什么是 ① → ④ → ② → ③ → ⑤

不是按重要性排的，是按**依赖关系**排的：

1. **① 表面层级**放最前，因为它可能推翻其余决策的底层前提（结果是：亮色下填充无效，
   这一批直接塌成一处描边）。**先做地基，哪怕结论是"没有地基"。**
2. **④ 状态音量**第二，因为它决定"颜色承担多少语义"。它没定下来之前调尺寸/圆角是在
   两套前提上做事。
3. **② 量表收口**第三：字体和圆角的档位一旦定死，后面所有对齐、尺寸、内边距的计算才有基准。
4. **③ 徽章统一**第四：徽章同时受"颜色语义"（④）和"量表"（②）约束，必须等这两个定稿。
5. **⑤ 描边与焦点**最后：它是分类学，要等所有"盒子"都收敛到同一套圆角与尺寸之后，
   才谈得上给它们分级。

**给下一个面板的结论**：**先动可能让别的决策作废的那一层，最后动只描述现状的那一层。**

## 五、踩过的坑

### 5.1 非设计类，但一定会再踩

| 现象 | 根因 | 判据 |
|---|---|---|
| **改完界面没变化** | 只跑了 `tsc` / 单测 / 预览出图 —— 它们**只校验、不产出可运行产物** | 改完必须 `npm run build`；产物是 `lib/client.js`。核对方式：从产物里把 CSS 字符串抠出来看，别只看源码 |
| 探针报"没有 probe block" | 用 Bash heredoc 生成 `.mjs` 时 `\\` 被折叠成 `\`，`replaceAll('/', '\')` 被打断 | **脚本一律用编辑器/写文件工具创建**，不要 heredoc |
| `grep -P` 假通过 | Git Bash 下 `\` 被提前归约 | 验证落到字节（`od`）或 `tr` 数字节，不要靠 `grep -P` |
| 量到的文字宽度是垃圾 | 用 `span.style.cssText = 'font:' + cs.font` 想"重新施加字体" —— **不会传递** | 用 `document.createRange()` + `selectNodeContents(el)` + `getBoundingClientRect()`，在页面自己的布局里量 |
| 探针报出"相撞" | 配对逻辑取到了同一个 flex 列的**上下**兄弟，不是左右 | 配对只在真正并排的网格轨道上有意义；报出的数先问"这两个真的并排吗" |
| 颜色对不上 token | `color-mix()` 计算成 `color(srgb …)` 而不是 `rgb()` | 用 1×1 canvas 归一化后再比对 |
| 对比度算出 21:1 | `lum()` 只读 `[0][1][2]`，**忽略了 alpha** | 10% alpha 的描边要先把 alpha 合成到真实底色上再算 |
| 0.5px 描边量出 1px | DPR 1 下的正常取整 | 不要当成 bug |
| 量出"共享样式表溢出 280px" | 预览页**不给类名加哈希**，同一页上两份样式表里同名的类就是同一个类：面板自己的 `.body` 撞上共享表的 `.body`，后加载那条 `overflow: auto` 落到了错的元素上 | 面板自己那份样式表不要与共享表重名。`preview/render.spec.tsx` 里有一条守卫会点名报出（唯一豁免是消化面板有意改写共享 `.body`，同一元素挂两个类，靠层叠顺序分胜负） |
| 探针报"左栏最后一行被裁 1px" / "某个面板没找到" | 基准元素选错：`cls()` 在元素没有 className 时回退到 `tagName`，文档 `<body>` 于是以名字 `body` 成了一个合法基准；另外 `overflow: auto\|scroll` 的筛选会漏掉**不滚动但内容铺到面板外**的列 | 基准只按**类名**匹配并显式排除文档元素；每个面板容器单独一节比；探针的 `--window-size` 必须与 `shots.mjs` 一致，否则两边量的是不同视口 |
| **渲染器 mock 是死的** | mock 把 `onClick` / `disabled` 从解构参数里拿走、没传给 DOM，于是一整类按钮在预览页里点不动，且该禁用的按钮画成可点 | 两个方向都是假证据：只有点了才能进入的状态（新增表单、删除确认、无连接器行）**一张图都没有**，看起来像"面板没实现"；而"禁用态确实禁用了"这句话一张图都支持不了。判据：**把 mock 改回坏的状态跑一遍**，那几页必须全挂（本次三页全挂才收工） |
| **量出"深色主题下文字不可读"** | 渲染器没设 `color-scheme`，而宿主 `theme-presenter.ts` 的 `apply()` 在 documentElement 上设它；它决定的是浏览器初值 `canvastext` 的取值 | 少了它，任何"没写 color"的元素在暗色预览里读作 `#000000 on #2c2c2e`（1.51:1）——真客户端一直是对的（补上这一行是 `#ffffff`／13.94）。**假证据比缺证据更难发现**。判据：扫"自己有文字却算成 `rgb(0,0,0)`"的元素，暗色页应为 0 |
| **一条断言永远为真** | 文案撞车：`datasource.remove` 和 `datasource.removeYes` 都是「删除」；「保存」是密码框占位符「留空表示不修改已保存的密码」的子串 | `expect(inner).toContain('删除')` 在确认行根本没打开时照样成立。断言落在**类名**或**独有文案**（含变量的那句，如 `removeConfirm`）上，不落在按钮文案上；同样用"改回坏状态跑一遍"验它真会挂 |
| 探针报"某角色这页上没有" | 一个元素常叠好几个类（`inlineText inlineValue fieldValueRead`），而匹配用的是**整串相等** | 按"类名**含**目标"判断，不能按整串相等——相等会把所有多类元素静默漏掉，看起来像"这页没有" |
| **量出一条不存在的"缝隙"** | 探针只对齐了 `--window-size`，没抄 `shots.mjs` 另外两个 flag（`--force-device-scale-factor=2`、`--hide-scrollbars`），于是**页面高度不同** → 对话框 `max-height` 不同 → pane 高度不同：一边 442/内容 568，另一边 450/552 | 报出的是"吸顶行底边离 pane 底 8px，露出一条内容"。真要照这个去改，就会给一条本来就不存在的缝补丁。**判据：探针的 flag 集合要与出图那条命令逐字相同**（本项目的量法是 `node runsticky.mjs preview/panel-x.html`，flag 抄 `preview/shots.mjs`）；再补一条：吸顶行 `rect.bottom` 与 pane 底之差必须是 0 |
| **探针报的坐标与同一页画出来的位置对不上**（根因未明） | 即便 flag 逐字相同，`--dump-dom` 那份布局与 `--screenshot` 出图那份**仍不是同一份**：数据源表单页上探针报 `.pm-dialog` 419 高、`detailPane` 449.5 高（`clientHeight` 450 / `scrollHeight` 568），而同一页画出来的卡片有 613 高、pane 的子元素（表单）从 166.8 一路画到 ~734（超出探针那个 pane 下沿 68px）。把探针报的上下沿画成横线（cyan/magenta）出图核对：**上沿对得上、下沿落在"密码"标签那一行**，而画面里的动作行在它下面；等 `document.fonts.ready` 之后再量一次、再画一根橙线，位置与 magenta 相同（不是字体换入造成的）。推测与"整页截图会把视口撑到文档高度、而宿主那几份样式表里有 `vh` 尺寸"有关，但**没查到确证**，所以按未明记录 | 后果：`shots.mjs` 打印的 PROBE 数字**不能当作旁边那张 PNG 的说明**（任何与视口有关的几何都不行）；这一轮吸顶的三条结论因此只用了**同一次 dump 内部的相对量**（滚 50px 位移是否为 0、底边距是否为 0、按钮是否同一行），它们不跨布局。核坐标要落到像素：把要核的坐标画成横线出图（本项目用的是一次性脚本 `shotinj.mjs` + `pngrows.mjs`），不要靠眼看截图上的 y |

### 5.2 设计类

| 现象 | 根因 | 判据 |
|---|---|---|
| 一个改动"代码全对、界面没动" | 该状态**没有任何预览产物**（例：折叠态是每页默认长相，展开行里的九枚指标片一张图都没覆盖） | **每个会被改的状态都要有可审的产物**；没有就补一张预览页，并断言它真的渲染了（`expect(inner).toContain('metricStrip')`） |
| 徽章颜色作用到空处 | 复合选择器 `.logOutcome.tonePass` 的优先级陷阱 | 单一类叠单一类，靠**源码顺序**覆盖，不要靠复合选择器 |
| 同一角色在两个面板尺寸不同 | 各自手写（wiki 的 tab 13px vs digest 的 filter 12px） | 跨面板先比"同一个东西"的直方图。**这一条已修**：页签收到 12px，与筛选同号；做法是量"同一控件在两个面板的 computed 字号"，不是看两处 CSS 写得像不像（见 3.14） |
| 一段注释在描述一个已经为假的事实 | 注释写于改动之前，改动时没回头改（本项目就有一处写着"same height"、实际差 4px 的注释） | **改值时顺手核一遍它周围的每一句断言**，要么改对、要么改成"报告未改" |
| **同一个类，在两个面板里长得不一样** | 类被放在不同标签上，而标签带着自己的 UA 默认值：`.sectionTitle` 在技能面板是 `<h4>`（浏览器给 `1.33em` 上下距，实测各 15.96px，于是那个 12px 的组标题泡在 16+10+16px 的空气里），在字段表里是 `<span>`（没有）；`.foldToggle` 是 `<button>`，而**按钮不继承字体**（浏览器给 `font: 400 13.333px Arial`，宿主的六张主题表没有一张把它改回来），于是同一条规则在 wiki 面板渲染成 Arial、在技能面板渲染成系统字体 | 会换标签的类，把 `margin: 0` / `font-family: inherit` 写在**类**上而不是调用方。判据取**计算值**（`getComputedStyle` 的 `fontFamily`、`marginTop`、`lineHeight`），不是读样式表——这两条规则看上去一模一样。**wiki 那份本地副本已经删掉、改用共享 `.foldToggle`，共享规则补上了 `font-family: inherit`**；按钮的字体/字号按什么分流见 3.14 |
| **一条规则看着在管某件事，其实从来没生效过** | 宿主自己已经用 `!important` 做了同一件事（`.markdown > *:first-child`），插件那条同名规则永远输；而它会让人把别处的原因（这里其实是 `.sectionTitle` 的默认外边距）记到它头上 | 加规则前先问"它赢不赢得了"（特异性、`!important`）。**死规则比没有规则更糟**：下一个人会以为这里有人管。删就删干净，并把"宿主已经做了"写进注释。同一族的第二例：`.citerList` 声明了 12px 而 `.citerLink` 是按钮——**字号也不继承**，实测渲染成 13.3333px（宽 4.8%，见 3.14） |
| **一个类从来没写过 `color` / `font-size`** | 插件里没有一处声明基础前景色，所以"忘了写"的类拿到的是浏览器默认值：`canvastext` + `16px/normal`。`.propValue` 正是如此——同格的 `.propLabel` 是 `12/18` 三级色，它是 `16px/normal` + UA 色，四个面板一模一样；同角色的 `.inlineValue` 早就是 `13/18` 二级色，`.fieldKey` 的注释也是按"旁边的 13px/18px 值"算的对齐 | 判据：扫"规则里没有 `color:` 的类" + 扫"自己有文字却算成 `rgb(0,0,0)`"的元素。**注意别被单个面板骗过去**：`.propValue` 在项目面板看不出问题，因为那里的值是 `inlineText inlineValue` 按钮、`.inlineValue` 自己给了 13/18——"某个面板看着没事"不等于这个类有人管 |
| **"改了值列宽度，列还是不对齐"** | 两个原因叠在一起，先修的那个不是主因：`max-content` 是按**每张**网格算的（行各成网格 → 值列各宽各的），而缺末尾格子的行会把洞留给下一行的首个元素（**自动排布填洞**）。第一处修完，量出来反而多了一条"某列跑到别的列去了" | 出现"某列左沿差 100+ px、两行挤在同一行（行距里出现 0）"时，先问**是不是排布串了行**，再问宽度。判据：`grid-column` 是否显式钉住首列、网格是否挂在容器上（见 3.12） |
| **量出"数字宽度不齐"，只改数字没用** | 量到的是**整列的位置**在动，不是数字的宽度：行尾两列都是 `auto`，末列（展开键）标签一换（看谁引用它 → 收起），被引次数整列就挪 36px；数字本身只差 7.03px | 先看**差值的量级**：一个字符 ≈ 7px、一整段标签 ≈ 36px。差值对不上"一个字符"时，去查这一列右边有没有会随状态变宽的东西（见 3.13） |

## 八、给下一个面板的最短路径

1. 读本文档第三节（结论），跳过已经证过的部分。
2. 列这个面板的字号 / 圆角 / 描边 / 颜色四个直方图。
3. 对每一档问"它的职务是什么"，只有一个使用者的合并掉。
4. 所有层级差改描边，所有焦点环用 `state-business-primary`，所有小物件用 `l4`。
5. **补预览产物**覆盖你改到的每个状态，然后按第六节跑完整验收。
6. **`npm run build`** —— 否则以上全部不可见。

凡是被实测推翻的结论，**把实测值写进它旁边的注释**，并写明"为什么不是另一个写法"。
本项目的注释密度就是这么来的：注释解释的是**取舍**，不是代码。
