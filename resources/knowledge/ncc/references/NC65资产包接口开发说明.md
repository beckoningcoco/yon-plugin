# NC65 资产包接口开发说明（区别于 NCC）

> **适用版本**：NC65（NC 6.5）| **补充**：[NCC资产包接口开发指南](./NCC资产包接口开发指南.md)
> **核心差异**：NC65 资产包接口**不需要注册 OPENAPI 路由**（不需要 opm_apimanager/opm_relateapi），走的是 `/nc/api/` 的 UAP 接口通道。

---

## 一、NCC vs NC65 差异总览

| 项 | NCC | NC65 |
|----|-----|------|
| 请求地址前缀 | `/nccloud/api/{module}/{resource}/{action}` | **`/nc/api/{module}/{resource}/{action}`** |
| OPENAPI 路由注册 | 需要 opm_apimanager + opm_relateapi 授权 | **不需要** |
| 鉴权 | OpenAPI 签名（client_id/secret/token） | 基于 groupCode + 数据源配置 |
| 关键配置 | opm 路由/授权 + 三方应用 | **opm.properties + hotwebs + 启动参数** |

---

## 二、NC65 资产包接口的 4 项处理

### 1. 请求地址

```
ip:port/nc/api/xx/xxx/xx
```
注意是 `/nc/api/`（不是 NCC 的 `/nccloud/api/`）。

### 2. 资产包补丁需包含 hotwebs 模块

确保部署的资产包补丁里有 `hotwebs` 模块（api 相关 web 模块），否则接口无法访问。

### 3. Home/resources 需有 opm.properties 配置文件

`Home/resources/opm.properties` 内容：

```properties
groupCode=XDBX
dataSource=XDNC65
```

**参数来源**：`ierp --> sf --> busiCenterConfig.xml`

```xml
<code>XDBX</code>               <!-- → groupCode -->
<dataSourceName>XDNC65</dataSourceName>  <!-- → dataSource -->
```

- `groupCode` = busiCenterConfig.xml 的 `<code>` 值（业务中心编码）
- `dataSource` = busiCenterConfig.xml 的 `<dataSourceName>` 值（数据源名）

### 4. 后端启动参数

JVM 启动参数增加：

```
-Duap.hotwebs=nccloud,fs,nc,lfw,portal,api,uapws
```

（把 `api` 加入 hotwebs 列表，NC65 才能加载 `/nc/api` 接口。）

## 三、代码层面仍一致的部分

NC65 资产包 REST 资源类与 NCC 结构相同：

- 继承 `nccloud.api.AbstractRestResource`（华科 BaseResource，getModule() 返回模块名，如 `fa`）
- `@Path("fa/newalter")` + `@POST @Path("add")` + `@Consumes/@Produces application/json`
- `transferBill(交易类型编码, map)` 按集成规则翻译编码→主键
- `ResultMessageUtil.toJSON(...)` 统一响应
- 集成规则表 `pub_interule` / `pub_interuleitem` 相同

> 前置 DDL 相同：`ALTER TABLE pub_interuleitem MODIFY (vfieldtype VARCHAR2(36));`（md_class.id 36 位 UUID）

## 五、经验教训

1. **先判版本**：NCC 需要 opm_apimanager 路由注册 + 授权；NC65 不需要，但要 opm.properties + hotwebs + `-Duap.hotwebs` 启动参数。**别把 NCC 的路由注册流程套到 NC65**。
2. **验证接口通不通**：先确认 ① hotwebs 模块在补丁里 ② opm.properties 存在且参数对 ③ 启动参数带 `api`。这三条缺一个，接口就 404。
