# 启用与版本：实测记录

> 2026-10-18，金隅共享测试环境（`dev-fssc.bbmg.com.cn`，租户 `jd4ofb7k`），BIP 旗舰版。
> 目的：把 `07-配置交付完成-DoD与交付单.md` 的 **D3「已启用」** 从「待验证」变成可判定。
>
> ⚠️ **文件名里的「发布」是历史叫法**：平台没有独立「发布」动作。
> 编辑业务流 → **保存即自动生成新版本**；刚保存时**未启用**，需要单独点「启用」。
> （平台口径由使用者于 2026-10-18 确认；本文的实测结果与之一致。）

## 一、实测对象与操作

**对象**：`TD-ZYQSXSCKTH`「直运签收-销售出库退回」，交易类型 `--`，`V1.0`，未启用，`isVerSupport` 未开启。

**操作**：列表选中行 → 工具栏「启用」→ 确认框「是否启用」→ 点「确定」。

**结果**：

| 项 | 启用前 | 启用后 |
|---|---|---|
| `status` | `false` | **`true`** |
| `version` | `V1.0` | `V1.0`（启用不产生新版本） |
| `isCurrentVersion` | `true` | `true` |
| 列表「启用状态」列 | 未启用 | 已启用 |
| 列表排序 | — | 按修改时间重排，该流跳到第 1 条 |

**恢复**：再选中 →「停用」→ 确认 → `status` 回到 `false`（原状态）。

## 二、启用成功的判据（可直接写进 D3）

- 按钮是**同一个**：未启用时文字「启用」，已启用时「停用」；`fieldid` 前缀
  `businessFlowFe_businessFlowList_list_btn_status`，**后缀随选中实例变**（实测 `status0` / `status2` / `status6` / `status8`），不要写死。
- 确认框：`是否启用` / `是否停用`；按钮
  `businessFlowFe_businessFlowList_list_status_modal_modal_footer_ok` / `..._cancel`。
- 接口：`getById` 的 `status` 变 `true`；`version` / `isCurrentVersion` 不变（启用不是保存）。
- 列表：启用状态列变「已启用」，并按修改时间重排。

## 三、启用失败的实测：交易类型唯一性

**对象**：`JYTD_XS_09`「测试调拨推生产」，交易类型「普通销售（有发货）-通达」，未启用。

该交易类型已被 `JYTD_XS_01`「普通销售（有发货）-通达」占用。点「启用」→ 确定，报：

> **状态码 `000-533-020003`：交易类型不滿足唯一性校验！**

**结论**：

- 同交易类型冲突**在启用时就被拦截**，不是等到运行期点下推按钮才报；
- 所以 D4 的冲突检查必须在「点启用」之前做；
- 冲突未解决时，不要点启用——它不是「配错可以改」，而是直接失败。

## 四、版本：开版本控制的流，重新启用时更新版本号

**平台机制（使用者确认，2026-10-18）**：

1. **没有独立「发布」动作**；
2. **开启版本控制（`isVerSupport=true`）的流**：保存后变为未启用；**重新启用时会更新版本号**；
3. **未开启版本控制的流**：保存后保持原启用状态（`_06` 实测仍 `status=true`），`version` 不变；
4. 保存本身是否递增 `version`：`_01` / `_03` / `_06` / `_07` 保存前后都是 `V1.0`，**未观察到保存时递增**——
   「更新版本号」发生在**重新启用**时。

**实测佐证**：设计器头部只有「属性设置」「保存」；属性设置只有流程名称/创建人/时间；
`isVerSupport=true` 的流也没有「发布 / 生成新版本」按钮；列表「编辑」的版本控制开关是 `disabled`。
这些都不是「入口藏起来了」，而是**平台没有这个动作**。

> `_07`（`isVerSupport=true`）保存后 `status=false`、`version=V1.0`；改用「服务交付订单」后重新启用成功，
> 但 `version` 仍 `V1.0`，**没有更新**。数据库里 `_07` 的 `SYS_FLOW_ID` 为空；
> 非预置且 `SYS_FLOW_ID` 非空的流为 0 条。
> 所以「重新启用更新版本号」在**复制流**上未复现；需要一条有 `SYS_FLOW_ID` 的正常流才能验证。
> **版本号不作为交付阻塞项**，先记在这里。

## 五、对 D3 的结论

**D3 = 已保存（版本自动生成）+ 已启用**，两件事都要做：

| 项 | 状态 | 证据 |
|---|---|---|
| 保存（版本记录） | **✅ 机制确认** | 开版本控制的流保存后变未启用；重新启用更新版本号（使用者确认）；本次未测到版本号变化 |
| 启用（测试环境） | **✅ 已验证** | `TD-ZYQSXSCKTH`：`status` false→true→false；`version` 不变 |
| 独立「发布」 | **不存在** | 平台没有这个动作，不要在文档/交付单里再写「发布」 |

所以交付单 D3 应写：

- 保存：`✅ 已保存（开版本控制的流，重新启用时更新版本号）`；
- 启用：`✅ 已启用（status=true）`；
- 不要再列「发布」为未验证项——它不是「没做」，是「没有这个动作」。
