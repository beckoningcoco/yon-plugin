# 排查方法论：配置还是缓存？—— 怎么把"报表某处传了个看不见的值"钉死

> 实测：2026-10-11，金隅共享 `dev-fssc.bbmg.com.cn`，旗舰版，租户 `U8C3`，
> 报表《账户余额分析表》（`edbd891f-…`，`report-51`）。
> 场景：**语义模型预览 441 行、报表预览 26 行**，使用者坚持"我没绑这个参数"。
> 关联：[[02-取不到数怎么排查]]、[[04-参数设置与默认值]]、[[00-设计器总览与操作纪律]]

---

## 0. 什么时候需要这一篇

| 症状 | 用这一篇 |
|---|---|
| **同一份数据，两处看到不一样**（模型预览 vs 报表预览、设计态 vs 运行态） | ✅ |
| 使用者问"**是不是缓存**？" | ✅ |
| 某个**看不见的值**在以某种方式生效，界面里找不到 | ✅ |
| 报表 0 行 / 下拉空 | 不用，走 [[02-取不到数怎么排查]] |

**核心心法**：这类问题不要靠"看界面"。**把一个值从"它在界面哪"转成"它在数据结构的哪个字段"**，
结论才立得住。下面四步，从便宜到贵。

---

## 1. 第一步：先证明它**不在浏览器缓存里**（十分钟内闭环）

使用者第一反应几乎都是"缓存吧"。**别争，直接列证据**：

```js
const needle = '<可疑的值>';
const scan = (st, label) => {
  const hits = [];
  for (let i = 0; i < st.length; i++) {
    const k = st.key(i); const v = st.getItem(k) || '';
    if (v.includes(needle)) hits.push({ key: k, at: v.indexOf(needle) });
  }
  return { label, total: st.length, hits };
};
return {
  url:     location.href.includes(needle),
  html:    document.documentElement.outerHTML.includes(needle),
  local:   scan(localStorage, 'localStorage'),
  session: scan(sessionStorage, 'sessionStorage'),
  cookies: document.cookie.split(';').filter(c => c.includes(needle))
};
```

**判读**：

- 全空 → **浏览器端没有缓存**，换无痕窗口、清缓存都不会变 → 排除"本地缓存"。
  ⚠️ 这只排除了**浏览器**。**服务端配置**（以及框架自己持有的对象）要接着往下走。
- 命中了 → 记下是哪个键，比如 `sessionStorage.lockInfo`（那是**编辑锁**，不是数据，别误判）。

> 顺手看一眼 `sessionStorage` 里的 `lockInfo`：它只存"谁在编辑、锁号"，
> **不含报表配置** —— 实测确认过，别把它当缓存。

## 2. 第二步：读**前端拿到的配置对象**（问题的答案通常就在这里）

设计器是 React，配置对象就挂在你脚边。**不必抓接口，也不必读源码** ——
从根节点往上爬 fiber，找到持有 `analysisModel` 的组件：

```js
(() => {   // 拿报表的 analysisModel（含 params / wideTableModels / filterModel）
  const root = document.getElementById('root') || document.body;
  const key = Object.keys(root).find(k => k.startsWith('__reactContainer'));
  let fiber = root[key]; if (fiber && fiber.current) fiber = fiber.current;
  const stack = [fiber]; let am = null; let n = 0;
  while (stack.length && n < 20000) {
    const f = stack.pop(); if (!f) continue; n++;
    const p = f.memoizedProps;
    if (!am && p && p.analysisModel && p.analysisModel.id
        && Array.isArray(p.analysisModel.wideTableModels)) am = p.analysisModel;
    if (f.child) stack.push(f.child);
    if (f.sibling) stack.push(f.sibling);
  }
  return am && { id: am.id, params: am.params.map((p,i) => ({
      i, id: p.id, code: p.items?.[0]?.code,
      defaultValues: p.items?.[0]?.defaultValues, value: p.items?.[0]?.value,
      vt: p.items?.[0]?.vt, baseParam: p.items?.[0]?.baseParam })) };
})()
```

**可以从中读到**（都是实测有效的字段）：

| 要看的 | 字段 |
|---|---|
| 参数有没有被设默认值、设成什么 | `params[i].items[0].defaultValues` / `.value` / `.vt`（`CONST`=常量） |
| 参数有没有被传给模型 | `wideTableModels[].conditions.paramRelations[]` 的 `label`/`target` |
| 筛选器有几个、绑了谁 | `filterModel.filters[]` 的 `code`/`from`/`iType`/`paramOut` |

**再做一次"全量搜值"**，把可疑值在**整个配置对象**里出现的位置列出来
（本次就是这样发现它藏在 4 个字段里，而不是 1 个）：

```js

```

> ⚠️ 两个纪律：
> ① **`fiber.memoizedProps` 是"页面当前这份"，不保证等于服务端** —— 所以第 3 步不能省；
> ② 搜索时要跳过 `_pageStorage` 和 `__react*` 这些自引用字段，否则要么漏、要么爆栈。

## 3. 第三步：拿**服务端定义**对账（区分"配置问题"还是"改了没生效"）

| 目的 | 手段 |
|---|---|
| 读**报表定义**（设计态） | `GET /iuap-data-analytic/report/design/<报表ID>?isAjax=1&locale=zh_CN&systenant=<租户>&listType=DIRREPORT&serviceCode=<服务码>` —— 写法与字段含义见 [[02-取不到数怎么排查]] §4 |
| 读**语义模型定义** | `GET /iuap-data-common/semantic/model/get/<模型ID>?isAjax=1&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC&serviceCode=report-28` → 取 `data.model`（`tables[0].sql` 是 SQL 正文、`params` 是参数声明） |
| 看**参数被传下去的值** | 抓取数请求的 body（gzip+base64 解码法见 [[02-取不到数怎么排查]] §2.2） |

**对账的结论只有三种，各对应一个动作**：

| 服务端 vs 前端 | 说明 | 怎么办 |
|---|---|---|
| 一致，值确实存在 | **配置问题**（不是 bug、不是缓存） | 去改配置，见 [[04-参数设置与默认值]] |
| 服务端已空、前端还有 | 前端拿的是**旧快照**：没保存，或保存后没重载 | 保存 + **刷新页面**再验 |
| 服务端还有、前端已空 | 你改的是**本地**，没落库 | 保存（注意 [[02-取不到数怎么排查]] §3.2 那个"已被对象引用"弹窗） |

> 💡 **最省事的判据**：清掉可疑配置 → **保存** → **刷新** → 再读第二步的字段。
> 若四五个字段里还剩一个没清干净（本次 `defaultValues` 清了，`value` 没清），
> 那说明"清一半"比"没清"更危险 —— **平台取数用的是 `value`**。

## 4. 第四步：用**数据**证明"这个值确实在生效"（而不是只证明它存在）

配置里存在 ≠ 它被用了。闭环要用数据：

1. 在库里按"带这个值"和"不带这个值"各跑一次口径，看行数差；
   本次：`org_fin_bankacct`（`dr=0`）共 **441** 行，其中 `account_org_id='<常量>'` 的 **26** 行 ——
   正好对应"模型预览 441 / 报表预览 26"。
2. 算一下"该值指向什么对象"（本次是**冀东发展集团**的组织档案 ID），确认它是个**业务维度**而不是巧合。
3. 再看"这个维度一共有多少个取值"（本次 53 个组织），就能说明**丢失的不是边角数据**。

> 用 `datasource_query` 跑这几条，比在界面上数行数可靠得多。
> 找表名/字段名先 `wiki_lookup`，别猜（见 yon-db-query 技能）。

## 5. 这次实战的完整链条（当模板看）

| 步 | 动作 | 结论 |
|---|---|---|
| 1 | 扫 `localStorage`/`sessionStorage`/`cookie`/`html`/`url` | 该值**不在浏览器**，不是缓存 |
| 2 | 读前端 `analysisModel.params` + 全量搜值 | 值在 `params[3].items[0]` 的 4 个字段里；`paramRelations` 声明了它会被传给模型 |
| 3 | 读模型定义 `/semantic/model/get/<id>` | SQL 里是 `<#if param('orgId')?? …> and a.account_org_id = ${param('orgId')} </#if>` —— 传了就过滤、不传就全量 |
| 4 | 库上数行数 | 441 / 26 对上，常量 = 冀东发展集团的组织档案 ID，全库 53 个组织 |
| 5 | 使用者自己打开 `数据 → 参数 → 参数设置 → 默认值` | 找到了那个**常量**：`2531236811194761226` |

**教训**：第 1、2 步很便宜，但**最容易漏的是"默认值有一个二级弹窗"** ——
界面主表格不显示值，所以"我在界面上找不到"是真的，不是使用者没仔细看。

## 6. 试过但**不可靠**的路子（省得别人再踩）

| 做法 | 结果 |
|---|---|
| `GET /iuap-data-analytic/report/view` | 405 |
| `POST /iuap-data-analytic/report/view` 手搓 body | JSON 用错参数名 → `使用了无效参数`；form 编码 → `Expected BEGIN_OBJECT but was STRING`。**参数名是内部的**，别硬猜，直接抓真实请求或走 §3 的 `report/design` |
| 在页面里 hook `fetch`/`XHR` 后**刷新页面** | hook 随文档销毁，**抓不到加载期的配置请求**；要抓就得让 hook 先于请求装上（或直接用现成接口） |
| 把 `sessionStorage` 当持久钩子仓 | 刷新会重建文档，钩子本身也没了（只能存"装过没有"这种标记） |
| 依赖"菜单点开"读配置 | 这个设计器的下拉菜单**失焦即收起**；要开菜单和点菜单项在**同一次** `browser_eval` 里做完（见 [[00-设计器总览与操作纪律]] §4） |
| 直接读页面上"参数设置"的「值」列 | 它显示的是**参数名**（如 `orgId`），不是值 —— 会被误导成"没配" |
| 用单元格的 `interaction` 字段判断"有没有配超链接" | **会误判**：超链接存在 `analysisModel.links` 数组里，`cells[…].interaction` 一直是 `null`（本次据此误判过"没保存"，其实早就落库了）。见 [[06-超链接跳转与跨表传参]] §4 |
| 对只读下拉（`input[readonly]` 外套 `div.wui-dropdown-trigger`）派发合成的 `mousedown/mouseup/click` | **打不开**。要取它的 React props 直接调用 `onMouseDown`/`onClick`，或点外层 trigger。见 [[06-超链接跳转与跨表传参]] §6 |
| 以为"刷新页面/重开弹窗"能解决"参数下拉里没有新参数" | **不能**。那是「分析参数」没加，属于配置缺失而非缓存，见 [[01-筛选器与参数绑定]] §10.5 |

---

## 7. 一句话总结

> **"是不是缓存"用一张表就能否掉；真正的答案在前端持有的配置对象里；
> 拿服务端定义对账判断"改了没生效"；最后用库上的行数证明这个值确实在生效。**
> 界面看不到 ≠ 不存在 —— 它只是藏在一个二级弹窗里。
