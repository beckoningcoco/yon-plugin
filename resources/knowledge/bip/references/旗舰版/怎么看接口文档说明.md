# 怎么看接口文档说明

> 以东软载波 MES 集成字段对照 Excel 为范本，说明如何从接口文档提取测试所需的关键信息。

---

## 一、文档整体结构

一个典型的 BIP→MES 集成字段对照文档，每个页签 = 一个接口场景，下面的内容为示例，只是举例，具体的文档具体分析。

### 1.1 页签命名规则

```
{单据名}{操作类型}BIP传MES

例如：
  出库申请审核BIP传MES
  出库申请弃审BIP传MES
  调拨申请审核BIP传MES
  调拨申请弃审BIP传MES
```

### 1.2 页签内部结构

每个页签按行组织，分为以下几个区块：

| 区块 | 位置 | 说明 |
|------|------|------|
| 基本信息 | Row 1~7 | 集成单据名、方向、触发时机、接口地址、业务场景 |
| 输入-字段映射表头 | Row 10 | 列定义 |
| 输入-主表字段 | Row 11~27 | 主表字段映射（含请求示例） |
| 输入-子表字段 | Row 28~33 | 明细行字段映射 |
| 输出 | Row 34~39 | MES 返回字段定义 |

---

## 二、怎么看"输入"区的字段映射表

字段映射表是最核心的部分，每个字段占一行，列含义如下：

### 2.1 "MES" 列（左侧）— 外系统要什么

| 列号 | 列名 | 说明 |
|:--:|------|------|
| [0] | 所在区域 | 主表 / 明细表 |
| [1] | 外系统字段描述 | 字段中文含义 |
| [2] | 外系统字段编码 | **MES 字段名，代码里 JSON key 就用这个** |
| [3] | 字段类型 | 文本/数值/日期 |
| [4] | 是否必填 | **Y = 必须传，N = 可空** |
| [5] | 默认值 | 有默认值时要传 |
| [6] | 备注 | 额外说明 |
| [7] | 参数示例 | 完整请求示例 JSON |

### 2.2 "BIP系统" 列（右侧）— BIP 这边给什么

| 列号 | 列名 | 说明 |
|:--:|------|------|
| [8] | BIP字段所在区域 | 出库申请主表 / 出库申请子表 |
| [9] | BIP字段描述 | 中文含义 |
| [10] | BIP字段编码 | **BIP 实体字段路径，代码要从这里取值** |
| [11] | 是否特征 | "是" = 特征字段（路径较特殊） |
| [12] | 字段类型 | 参照/文本/日期/数值 |
| [13] | 是否必填 | Y/N |
| [14] | 默认值 | — |

## 三、请求示例 JSON 怎么用

Row 11 的列 [7] 通常嵌了一个完整 JSON 示例，当然不同的文档可能在不同的地方给了示例报文，也有可能没有：

```json
{
  "strSysPara": { "HandlerName": "MES", "QueryType": 2892, "ClientType": "4" },
  "strBusPara": {
    "QueryCode": "TestDevice01",
    "QueryString": {
      "ObjectName": "OTHEROUTSTOCK",
      "RequestString": [
        {
          "ERP_NO": "APPLY20260530001",
          "ERP_DOCID": "APPLYID001",
          "BILLSTUATE": "0",
          "STOCKORGANIZ": "01",
          "DOC_TYPE": "领用出库",
          "ITEMS": [
            {
              "ERPLINEID": "LINE001",
              "OSD_ITEM_CODE": "MAT060",
              "OSD_AMOUNT_PLAN": 200,
              "OSD_UNIT": "个"
            }
          ]
        }
      ]
    }
  },
  "strOtherPara": "R8GAPp065FiY vsbYDC..."
}
```

### 3.1 三层结构

```
strSysPara          ← 系统参数（HandlerName/QueryType/ClientType），代码里 MesHttpClient 自动填
strBusPara          ← 业务参数（QueryCode + QueryString），QueryCode 来自配置
  └─ QueryString    ← ← 代码里 buildRequest() 的返回值就是这一层
       ├─ ObjectName  ← 接口标识（OTHEROUTSTOCK / TWOMOVE / IQCREJECTION）
       └─ RequestString[] ← 包含主表 + ITEMS 子表
strOtherPara        ← 加密串，MesConfig 配置
```

### 3.2 你的 buildRequest 应该造出什么

只需要造 `ObjectName` + `RequestString[]` 这一层。外面的 `strSysPara`/`strBusPara`/`strOtherPara` 由 `MesHttpClient` 自动包装。

```java
// ✅ buildRequest 的正确返回格式
{
  "ObjectName": "OTHEROUTSTOCK",
  "RequestString": [{
    "STOCKORGANIZ": "001",
    "ERP_NO": "CKSQ20260611000002",
    "ITEMS": [{...}]
  }]
}
```

---

### 3.3 很重要的一点，有时候BIP的字段上会写

busType.code 这种情况下，大概率是一个参照字段，取值上要格外小心。例如出库申请单，实际传入的参数可能是 busTypeId ,并不是真的有busType.code这个字段。那么我们检查入参中，是否包含了 busType.code 接近的，能代表编码的字段，如果没有，则需要在代码中去写查询方法做翻译了。

不同的参照字段都对应着不同的档案，要明确翻译时查询的是哪个档案，一般通过URI来判别，如果自己无法判断则让用户提供URI。

例如 auditor.code 参照的是 用户档案的编码   operator.code 申请人参照的其实是员工档案的编码。 如果不明确则容易混淆，都是用用户或者员工档案。



### 3.4 对于文档上有的业务逻辑 ，但是 代码中并没有写

此时，则要向用户确认是否需要补充逻辑了，文档的优先度一定是高于代码的！

## 四、看文档的检查清单

拿到一个新接口文档，按顺序核对：

- [ ] **ObjectName** — Row 11 示例 JSON 的 `QueryString.ObjectName`，代码里 `buildRequest` 写死
- [ ] **必填字段** — 遍历所有 [4]="Y" 的行，确保代码里都传了值
- [ ] **字段编码** — [10] 列的值就是 BIP 实体路径，如 `orgId.code`、`SYR.code`
- [ ] **特征字段** — [11]="是" 的字段，路径带 `DefineCharacter`，如 `requisitionDefineCharacter.SYR.code`
- [ ] **默认值** — [14] 有值要写死传，如 `DOC_TYPE`="24"
- [ ] **编码 vs 名称** — [6] 备注里写了"传编码"的要传 code 而非 name
- [ ] **主表 vs 子表** — [0] 标注了"明细表"的字段要从子表 entity 取，不能挂主表查
- [ ] **日期格式** — [6] 写了格式要求如 `yyyy-mm-dd`
- [ ] **BILLSTUATE** — 0=审核，1=弃审，分别对应两个页签

## 五、典型问题识别

### 5.1 必填字段缺失

文档 [4]="Y" 但代码没传 → MES 报 `NG:DB ERROR` 或 `NG:缺少XX字段`。

**定位方法**：在服务器日志里搜实际 `requestBody`，逐一对比。

### 5.2 传了 ID 没传编码

BIP 实体路径取到的是 ID（如 `"2557979656985247748"`），但 MES 要编码（如 `"00000010"`）。

**识别**：[10] 列的路径以 `.code` 结尾，或者写了"传编码"。需要额外查档案/实体翻译。

### 5.3 传了名称没传编码

BIP 的 `String` 字段是中文名，但 MES 要员工号。

**识别**：[6] 备注写了"传员工号"。需要用 `xxxId.code` 或查用户/员工表翻译。

### 5.4 请求结构不对

代码用 `{"OPERATIONTYPE":"...", "DATA":{...}}` 但文档要求 `{"ObjectName":"...", "RequestString":[...]}`。

**识别**：对比代码 `buildRequest` 返回的 JSON 和文档 Row 11 的示例 JSON 的 `QueryString` 结构。
