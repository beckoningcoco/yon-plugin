# 语义脚本编辑器：怎么用

> 详细手册（实测）在参考库：`bip/references/旗舰版/语义脚本编辑器/`
> 用 `knowledge_search` / `knowledge_read` 读；新经验直接往那个目录加文档（**不用编译，重启 DSH 即可检索**）。

## 它是什么

**语义模型编辑页里的 SQL 脚本抽屉**，不是独立页面：

```text
https://<host>/iuap-data-common/ucf-wh/intelliv/index.html#/semantic/query/edit/<语义模型ID>?serviceCode=report-28&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC
```

主界面点**表清单里的表名**进入抽屉；抽屉是全屏的，右侧是 CodeMirror 6 的 SQL 编辑器，
顶部右侧有「执行」和「参数」两个按钮。

## 三类可替换的值（别只会用自定义参数）

| 值的性质 | 用什么 | 在哪取 | 怎么写 |
|---|---|---|---|
| 使用者在报表上选的 | **自定义参数** | 抽屉「参数」→ 参数设置弹窗 | `${param('编码')}` |
| 随运行日期变的 | **系统变量** | 右侧「系统变量」面板（`currentYearMonth`、`lastIssueMonth`、`currentYearSeason`…） | `${var('编码')}` |
| 随登录者身份变的 | **权限标签** | 右侧「权限标签」面板（`orgId`、`orgCode`、`deptId`、`roleId`、`staffCode`、`productLine`…） | `${var('编码')}` |

## 多选参数（报表多选传 `id1,id2` 时）

```sql
<#if param('参数名')?? && param('参数名')!=''>
  and 字段 in ('${param('参数名')?replace(",", "','")}')
</#if>
```

外层单引号要有；参数为空则条件不成立 → 退化成**不过滤**。

## 合计（一行汇总型）模型：过滤要作用在**组织集合**上

明细是"一行一个组织"、过滤作用在**行**上；合计是**一行汇总**，没有行可过滤 ——
要过滤**它统计的那个组织集合**（通常是 `m` 子查询），且必须用**含下级**口径
（8 段 `union all` 子树展开），否则与明细的上卷数对不上。

改完合计模型，**报表侧还要给合计单独绑一条参数**（参数名要与明细不同，
如 `zlqk_orgid` / `zlqk_orgid_t`），否则报表上的合计行不会动。
详见 `语义脚本编辑器/01-参数与固定值替换.md` §3.6。

## 参数替换的四条硬规则（照抄能省一次报错）

1. SQL 正文写 **`'${param('参数名称')}'`** —— **外层单引号要自己包**。
   2026-10 实测：不包会立刻「执行失败」（错误提示 012-501-030155）；包上才通过。
2. `<#if …>` 标签**内部**写 `param('x')`，不能再带 `${}`；写错报
   `You can't use ${...} (an interpolation) here as you are already in FreeMarker-expression-mode.`
3. 空值兜底判断要**双重**：`<#if param('x')?? && param('x') != ''>`；只写 `??` 时传空串仍会过滤。
4. 日期参数**不要**用 `TO_DATE` / `STR_TO_DATE` / `CAST` 去包。

## ⚠️ 同名参数：跨数据集共用的参数会被"抢值"

**同一个模型自己的参数，只要名字与报表里别的数据集重名，就可能拿不到值。**

机制：报表的参数**按名字合并** —— 主数据集（如 `_总览`）的同名参数拿到了值，
**其他数据集的同名参数拿不到**，`${param('x')}` 渲染进 SQL 就成了空 → 条件恒不成立 → **0 行**（而且不报错）。

**判据**：出问题的都是**同名**参数；模型**独有**的参数（如本例的 `orgCode`）一直正常。

**解法（三选一）**：

| 方案 | 写法 | 适用 |
|---|---|---|
| **① 系统变量**（推荐） | `'${var('tenantId')}'` | 租户这类"每个数据集都要用"的值；平台自动填，**不参与报表参数合并** |
| ② 固定值 | `'jd4ofb7k'` | 单环境够用；换租户要改 SQL |
| ③ 参数改名 | 改成 `ytenant_id_org` 之类 | 最正统，但模型 + 报表侧绑定都要动 |

> 实测 2026-10-10：「报表组织体系查询模型」的 SQL 用了 `${param('ytenant_id')}`，而报表里 `ytenant_id`
> 只有主数据集的那一个 paramId → 该模型渲染成空 → 筛选器下拉"暂时没有数据哦~"。
> 把同一个值写死、在**库里实跑能出 2 行**；改成系统变量后正常。
>
> 这类问题的完整排查法（抓取数请求、看每个参数实际拿到什么值）见 `报表设计器/02-取不到数怎么排查.md`。

## ⚠️ 参数设了默认值，报表取数也可能**拿不到**

模型「参数设置」里填了默认值，**报表取数时不保证带上**（筛选器没选 / 参数绑定被刷空）→ 关键列会整列空。
凡"**不选也必须出数**"的关联/过滤，SQL 里自己兜底：

```sql
and cd8.custdocdefid = <#if param('x')?? && param('x')!=''>'${param('x')}'<#else>'兜底值'</#if>
```

**判据**：同一 SQL 把值**写死在库里跑有数、报表里没数** → 就是它。

> 与上面「同名参数被抢」是**两类**问题：那条是**被别人抢走**，这条是**根本没人传**。两条都要防。
> 详见 `语义脚本编辑器/01-参数与固定值替换.md` §6。

## 纪律

1. **先定义参数、再引用**：SQL 里用了参数列表里没有的编码，替换会失败或留空。
2. **写死的值往往不止一处**（本例每个 `union all` 分支一处），只改一处＝口径不一致的**静默错误**：不报错，数字不对。
3. **改动要保存才生效 —— 而且"在哪看"决定了你看到的是哪一份**：
   - 抽屉里点「**执行**」跑的是**编辑态**（不保存也能通过）；
   - **报表 / 筛选器取数读的是已保存的定义** —— 不保存，报表用的还是旧 SQL。
   所以"模型里执行成功、报表还是 0 行"是**正常现象**，不是脚本没改对：抽屉「确认并返回」→ 主界面「保存」。
   只想看的时候别点这两个；保存时若弹「当前语义模型已被对象引用，是否修改？」**必须点「修改」**，否则等于没保存。
4. **「执行」真的会跑 SQL**（只读查询），别在没确认过的脚本上随手点。
5. **SQL 既能读也能程序化改**：`document.querySelector('.cm-content').cmView.view` 就是 CodeMirror 的
   EditorView —— 读用 `state.doc.toString()`、改用 `dispatch({changes})`；**别用 `innerText` 读，它会漏内容**。
   批量替换 → 执行 → 保存的完整套路见 `语义脚本编辑器/02-用脚本改SQL并保存.md`。
