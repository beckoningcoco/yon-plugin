# 查用友环境的数据

> 这个技能由 `dsh-plugin-yon-panel` 插件预制：安装插件时它自动进入技能目录，卸载时自动消失。
> 查询脚本、驱动适配都在插件包里，**不依赖 `~/.claude`、`~/.agents` 或任何外部技能目录**。

## 三个工具，不要绕开

| 工具 | 用途 |
|---|---|
| `datasource_list` | 看有哪些数据源：项目、环境、类型、地址、可用登录名 |
| `datasource_upsert` | 登记或改一条连接：新建环境、改地址、换密码、绑定项目（要使用者点头） |
| `datasource_query` | 对指定数据源执行一条 SQL |

**不要**自己去找 `db_query.py`、也不要拼 `python ... -p xxx -e test` 这类命令：插件的安装路径每台机器都不同，
而工具已经把连接解析、驱动选择、超时和结果格式化都做完了。

**不要**凭记忆写连接串。连接信息存在插件管理的数据源配置里，`datasource_list` 是唯一可信的来源。

## 推荐顺序

1. `datasource_list` —— 看清有哪些环境、各自的 `key`、类型和登录名；
2. 用**完整 key**（形如 `天九(NCC2312)::test`）调 `datasource_query`，不要用简称：键是精确标识，简称可能匹配到别的项目；
3. 拿不准表名或字段名时，先查元数据表（例如 Oracle 的 `user_tab_columns`）再写正式 SQL。

## SQL 写法要点

- 限定数据库方言：Oracle 用 `SELECT 1 FROM DUAL`，MySQL / 达梦 / PostgreSQL 用 `SELECT 1`；
- 一次只发一条语句，工具返回的是结果集，不做多语句编排；
- 大结果集会占用上下文：先 `COUNT(*)` 或加 `WHERE`/`ROWNUM`/`LIMIT` 收敛，再取明细。

## 连不上时：先分清是驱动、加密库还是网络

连接信息和驱动由宿主处理，但插件**不会自动安装**驱动。报错基本落在这三类里，**不要**把它当成表名写错或数据问题：

| 报错关键词 | 是什么 | 怎么办 |
|---|---|---|
| `缺少 Python 驱动` | 目标机的 python 没装对应驱动 | 按提示装：达梦 `pip install dmPython`、Oracle `pip install oracledb`、MySQL `pip install pymysql`、PostgreSQL `pip install psycopg2-binary` |
| `[CODE:-70089] 加密模块加载失败` | 达梦的加密库目录 `dmssl`（在 dmPython 旁边或 `DM_HOME` 下）没有被加载 | 查询脚本会自动把它挂上进程的库搜索路径并重启一次；仍失败时确认该目录存在、且与 dmPython 同为 64 位 |
| `[CODE:-70028] 创建SOCKET连接失败`、`Connection timed out`、`Can't connect` | 网络不通：没连 VPN、IP 白名单没放行、端口不通 | 与驱动无关，请使用者确认网络，不要去改表名或 SQL |

连接失败时错误后面会附一段**环境自检**（解释器、驱动、达梦加密库、到库地址的 TCP 是否可达）。照着那几行判断方向，不要把自检结论当成 SQL 错误。

## 写操作会被拦下来

`datasource_query` 遇到 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`TRUNCATE`、`ALTER`、`CREATE`
这类语句会先停下来等使用者确认，并且**生产环境**的写操作一律要明确批准。这不是可以绕过的提示：

- 不要为了"先试试"而对生产库发写语句；
- 使用者没有明确要求时，默认只发 `SELECT`；
- 被拒绝就把原因原样告诉使用者，不要换一条等价写法重试。

## 登记连接：用 `datasource_upsert`，不要去改配置文件

使用者把地址、账号、密码交给你、让你「维护数据源」时：

- `key` 写「名称::环境」（如 `首创(NCC1909)::test`），不存在即新建；**省略的字段一律沿用已存值**，
  只想改地址就只给 `host`；
- `db_type` / `host` / `port` 在新建时必填；`service_name` 给空串是「清空」，不是「沿用」；
- `user` 与 `password` 必须成对给，不给就是沿用已存的登录名与密码；一个分支上已存多个登录名时，
  只给一个会被拒绝，要显式 `replace_logins: true`；
- `project` 可以按项目名 / 编码 / id 绑定（空串解绑）；
- 每次写入都会停下来等使用者确认，只读会话直接拒绝。被拒绝就把原因告诉他，不要绕道去改
  `db_config.json`——那个文件写坏了整个列表一起坏；
- 密码只进不出：它写进使用者的配置，回答与审批卡里都不会再出现。

## 边界

- 本技能以**查询**为主：新增与修改连接模型也能做（见上一节），**删除**仍然只在面板里做
  （侧边栏底部的 `Y` → 数据库图标）。
- 数据源里没有你要连的库、而使用者也没给连接信息时，告诉他去哪加，不要自己去改配置文件。
