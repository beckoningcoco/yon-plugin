## 4. 校验与依赖注入

```java
private SaveInfo info;
IValidationService validationService;                    // ★ 字段，不是 new 出来的

protected void validate(Object value) {
    if (this.validationService != null) {                // ★ 为空就跳过！
        try { this.validationService.validate(value); }
        catch (ValidationException e) { ExceptionUtils.wrapBusinessException(e.getMessage()); }
    }
}
public IValidationService getValidationService() { return this.validationService; }
public void setValidationService(IValidationService v) { this.validationService = v; }
```

> **入口类自带 `get/setValidationService`**——说明它**设计上由容器/配置注入校验器**。

## 5. 【核心】`ArapBillUIUtil.executeBatchPM`（781 行的公共执行器）

`ArapBillUIUtil`（`nccloud.web.arap.arappub.util`，`uiarap_nccloud.jar`）是 **arap 模块的公共 UI 工具类**，
有 **4 个 `executeBatchPM` 重载**（`:71` / `:106` / `:113` / `:691`），全部汇聚到 `:71`。
最内层实现：

```java
public static Object executeBatchPM(String actionType, BaseAggVO[] bills) throws BusinessException {
    if (null == bills || bills.length == 0) return bills;
    // ① 过滤 null
    ArrayList<BaseAggVO> list = new ArrayList<>();
    for (BaseAggVO agg : bills) { if (agg == null) continue; list.add(agg); }
    bills = list.toArray(new BaseAggVO[0]);
    // ② 每个单据一个空的 PfUserObject
    PfUserObject[] userObjAry = new PfUserObject[bills.length];
    for (int i = 0; i < bills.length; ++i) userObjAry[i] = new PfUserObject();
    if (actionType.equals(SIGNAL) || actionType.equals(ROLLBACK)) userObjAry = null;   // ★ 两个动作不带用户对象
    // ③ 装配 context
    CloudPFlowContext context = new CloudPFlowContext();
    HashMap<String, String> ob = new HashMap<>();
    ob.put("nosendmessage", "Y");                              // ★ 不发消息
    context.seteParam(ob);
    context.setActionName(actionType);                          // ★ 动作类型就是 actionType 参数
    String billType = (String)bills[0].getParentVO().getAttributeValue("pk_billtype");   // ★★ 从 VO 读！
    context.setBillType(billType);
    if (!StringUtil.isEmpty((String)bills[0].getParentVO().getAttributeValue("pk_tradetype")))
        context.setTrantype((String)bills[0].getParentVO().getAttributeValue("pk_tradetype"));
    context.setUserObj(userObjAry);
    context.setBatch(false);                                   // ★ 非批量
    context.setBillVos(bills);
    // ④ 引擎
    ICloudScriptPFlowService service = (ICloudScriptPFlowService)ServiceLocator.find(ICloudScriptPFlowService.class);
    Object[] objects = service.exeScriptPFlow(context);
    return objects;
}
```

**五个与前 14 份都不同的点**：

| # | 点 | 与前 14 份的差别 |
| --- | --- | --- |
| 1 | **`billType` 从 VO 属性 `pk_billtype` 读** | 销售/采购是硬编码字面量或 `SOBillType`/`POBillType` 枚举、库存是 `ICBillType` 枚举；**财务是从数据里读** |
| 2 | **`trantype` 从 VO 属性 `pk_tradetype` 读** | 业务单据用 `context.setTrantype(...)` 时传的是单据类型本身（第 8 份的 `isSaveAction` 分支），财务是独立的交易类型属性 |
| 3 | **`eParam` 固定带 `nosendmessage=Y`** | 前面都没有这个开关——**财务保存不发消息** |
| 4 | **`SIGNAL` / `ROLLBACK` 两个动作把 `userObjAry` 置 null** | 说明这两个动作**不需要用户身份**（系统级信号/回滚） |
| 5 | **`context.setBatch(false)`** | 明确声明非批量模式 |

**但底下是同一个引擎**：`CloudPFlowContext` + `ICloudScriptPFlowService#exeScriptPFlow` ——
与销售订单保存（第 7 份）、销售出库/采购入库（第 13、14 份）**完全相同**。
即：**五条不同形态的入口，最终都汇到 `ICloudScriptPFlowService` → `CloudPfUtil` → `IplatFormEntry` → `PFBusiAction` → 动作驱动表**。

### 5.1 `pk_billtype` 是什么

它是 **VO 上的一个属性**（`bill.getParentVO().getAttributeValue("pk_billtype")`），
即**每张单据自己知道自己是哪种单据类型**。它同时也是**动作驱动表的过滤键**
（`pub_actionconstrict.pk_billtype`）——所以 `executeBatchPM` 里这一行**直接决定了去动作表取哪一批业务类**。

> 排查"财务单据保存没执行应有的业务逻辑"时，**先确认 VO 上的 `pk_billtype` 值对不对**——
> 它错了，`pub_actionconstrict` 就查不到，业务类一个都不会执行。

## 6. arap 的动作类型体系（11 个常量）

`ArapBillUIUtil` 里定义的 `actionType` 常量（:55-65）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `START` | `"START"` | 启动（送流程） |
| `SIGNAL` | `"SIGNAL"` | 信号（**不带用户对象**） |
| `ROLLBACK` | `"ROLLBACK"` | 回滚（**不带用户对象**） |
| `RECALL` | `"RECALL"` | 撤回 |
| `MODIFY` | `"MODIFY"` | 修改 |
| `AUDIT` | **`"APPROVE"`** | 审批（常量名与值不同！） |
| `EDIT` | `"EDIT"` | 编辑 |
| `DELETE` | `"DELETE"` | 删除 |
| `CANCEL_AUDIT` | **`"UNAPPROVE"`** | 取消审批（常量名与值不同！） |
| `SAVETEMP` | `"SAVETEMP"` | **暂存**（业务单据没有） |
| `EDITTEMPSAVE` | `"EDITTEMPSAVE"` | **编辑态暂存**（业务单据没有） |

**保存时传的是字符串字面量 `"SAVE"`**（`EstiRecBillSaveAction:56`、`:65`），
**不是这 11 个常量之一**——即 `"SAVE"` 是调用方直接给的，常量表里没有单独的 `SAVE` 常量。

> ⚠️ **两个常量名与值不一致**：`AUDIT = "APPROVE"`、`CANCEL_AUDIT = "UNAPPROVE"`。
> 看到代码里写 `AUDIT` 时，传给引擎的其实是 `"APPROVE"`；
> 而第 8 份见过 `"APPROVE"` / `"UNAPPROVE"` 是**销售提交被 `hasFlow` 改写后的结果**——
> **同一个字符串在两个模块里由不同路径产生**。

**`SAVETEMP` / `EDITTEMPSAVE` 是财务链独有的**：业务单据（销售/采购/库存）没有"暂存"这个动作。
排查"财务单据的暂存与保存有什么不同"时，看这两个动作在动作驱动表里配的业务类即可。
