## 三、配置策略速查

| 场景 | FCONVERT | VCONVERTPARAM | VCONVERTRULE | VTRANSLATE |
|------|----------|---------------|--------------|------------|
| 编码→ID，集团级档案，找不到报错 | 1 | 1（集团） | **1**（按编码） | 1 |
| 名称→ID，集团级档案，找不到报错 | 1 | 1（集团） | **2**（按名称） | 1 |
| 编码→ID，组织级档案，找不到报错 | 1 | 2（主组织） | 1 | 1 |
| 编码→ID，全局档案，找不到忽略 | 1 | 0（全局） | 1 | NULL |
| 编码→ID，找不到自动新增 | 1 | 按实际 | 1 | 3 |
| 直接映射（值照搬，不翻译） | 1 | 不填 | 不填 | 不填 |
| 固定默认值（外部不传） | 0 | 不填 | 不填 | 不填 |
| 对照表转换 | 2 | 不填 | 不填 | 不填 |

> `VCONVERTRULE`：**1=按编码 / 2=按名称**。外系统传中文名时用 2，传编码时用 1。
> `VTRANSLATE`：NULL=忽略 / 1=报错 / 3=自动新增。
> 注意：`VCONVERTRULE` 只有在 `VFIELDTYPE` 和 `VCONVERTPARAM` 都非空时才生效。

## ⚠ 最容易漏的两条（详见开发指南 §11.6）

**① 凡是要在 NCC 单据上看到的字段，都必须有一条规则项。**

`transfer()` 是按**规则项**逐条遍历的（`AbstractRestResource.java:1030`），不是按 JSON key 反查。
没配规则项的 JSON 字段会被**静默丢弃**，不报错、日志里也看不出来。

> 最容易漏的是**验重键**（如 `def31` 存外系统单号）。漏了它的后果：NCC 单据上该字段永远为空
> → 下次按它查重查不到 → 每次都当新单插入 → **重复单据越积越多**。
> 而且**第一次跑看不出来**，跑第二次才暴露。

配置时先把字段分三类过一遍，**第 ② 类最容易漏**（界面上看起来"不需要配置"）：
① 要翻译的（VFIELDTYPE + VCONVERTRULE） ② 直接存值的（FCONVERT=1，VFIELDTYPE=`~`） ③ 固定默认值的（FCONVERT=0 + VDEFAULTVALUE）

**② 表体前缀 ≠ 报文数组 key**

- **VFIELD 前缀** = bmf 里 `BodyOfAggVOAccessor` 的 `name`（收款单 = `bodys`）
- **报文表体数组 key** = 子表 entity 的 `name`（收款单 = `gatheritem`）

报销单两者恰好同名（`er_busitem`）容易让人误以为相等，**别按前缀去拼报文 key**。

## 四、VFIELDTYPE 取值 SQL 模板

### 标准实体（OrgVO、DeptVO、PsndocVO 等）

```sql
SELECT id, displayname FROM md_class WHERE fullclassname = 'nc.vo.org.DeptVO';
```

### 自定义档案（管理费用类别、差旅类型等）

所有自定义档案的 `fullclassname` 都是 `nc.vo.bd.defdoc.DefdocVO`，按 `displayname` 区分：

```sql
SELECT id, displayname FROM md_class
WHERE fullclassname = 'nc.vo.bd.defdoc.DefdocVO'
  AND displayname LIKE '%关键词%';
```

### 不确定的字段 → 宽搜

```sql
SELECT id, displayname, fullclassname FROM md_class
WHERE displayname LIKE '%关键词%'
ORDER BY fullclassname;
```

## 五、bmf 前缀查询命令

```bash
# 在 HOME/modules/{模块}/METADATA/ 目录下
grep -o 'BodyOfAggVOAccessor[^>]*name="[^"]*"' {单据}.bmf
```

取 `name` 属性值即为前缀。例如 `name="er_busitem"` → 前缀为 `er_busitem`。
