# 单元格超链接：点格子跳到另一张表并传参

> 实测：2026-10，金隅共享 `dev-fssc.bbmg.com.cn`，旗舰版，租户 `U8C3`，`serviceCode=report-51`。
> 场景：汇总表《集团外部账户汇总表-管理口径》（`9f730654-…`）**数据行的「账户总数」格子**，
> 点击后跳到《账户明细表》（`18503d72-…`），把**当前行的单位**传给目标表的参数。
> 关联：[[00-设计器总览与操作纪律]]、[[01-筛选器与参数绑定]]（**§10.5 参数要先进「分析参数」**）、
> [[04-参数设置与默认值]]、[[05-排查方法论-配置还是缓存]]

---

## 0. ⭐ 一句话

**平台原生支持「单元格超链接跳转 + 跨表传参」，不用写代码。**

跨表传参靠「传值设置 → **参数赋值**」，三个字段就够：

| 字段 | 填什么 |
|---|---|
| **所需参数** | 目标报表的那个参数（**前提：它已存在于目标报表的「分析参数」里**，见 §3） |
| **值类型** | **`图表字段`** ← 这就是"取源表当前行字段" |
| **值** | 源表（当前表）的字段名，例如 `id` —— ⚠️ 它的**取值空间必须与目标参数期望的一致**，否则跳过去是空白页（见 **§7.1**） |
| | ↑ 这只是**最常用**的一类。要**连源表的筛选器一起带过去**（如开始/结束日期），值类型改选 `筛选器`，见 **§7.2** |

## 2. 「链接设置」弹窗的全部配置项（实测）

### 2.1 上排：链接对象 + 标题 + 页面选择 + 打开方式

| 区域 | 选项 / 说明 |
|---|---|
| **链接对象** | 两排单选：`智能分析对象` / `当前分析对象` / `BIP应用服务` / `第三方页面` / `文件`；以及 `仪表板` / **`报表设计`** / `单表采集` / `数字大屏` |
| **链接标题** | 必填。开关：`链接标题作用于平台新页签标题` |
| **页面选择** | ⚠️ **先在上方左树里选中目标报表**，这里才会带出它**默认的第一个页签**（如 `报表1`），之后可切页签 |
| **打开方式** | `系统内新页签打开`(=`_blank`) / `当前页面打开`(`_self`) / `弹出窗口打开`(`_modal`) / `浏览器新页签打开`(`_webBlank`) |
| **传递同模型条件** | 勾选后"把作用于单元格的条件自动传给目标表"，**只当两表存在相同模型时生效** |

> ⚠️ **页面选择为空 = 你没在左树里选报表。** 实测「页面选择」下拉在校验前一直是
> 「暂时没有数据哦~」，选了报表后才自动填上「报表1」。**链接对象选了「报表设计」还不够。**

### 2.2 下排：五个页签

```text
传值设置
  ├ 普通过滤           对目标表字段做 等值/包含/介于… 过滤（**做不到"含下级"，见 §5**）
  ├ 参数赋值   ⭐       把源表的值送给目标表的【参数】（本次用的就是它）
  ├ 控制设置           单击 / 右键菜单、显示顶部工具栏、支持切换方案…
  └ 链接触发条件       满足下列所有条件(AND) / 任一条件(OR)
```

### 2.3 「参数赋值」表格

表头：`序号 | 所需参数 | 值类型 | 值 | 删除`

**值类型的全部选项（实测 7 个）**：

| 值类型 | 含义 | 存下来是什么 |
|---|---|---|
| **`图表字段`** | **取源表（当前表）的字段** | `valueType: "FIELD"`, `valueOrCodes: ["字段名"]` |
| `常量` | 写死一个值 | — |
| `参数` | 取当前报表自己的某个参数 | — |
| `系统变量` | 如当前日期、当前用户 | — |
| `权限标签` | 权限标签变量 | — |
| **`筛选器`** | 取**源表筛选器控件**的值 | `valueType: "FILTERKEY"`, `valueOrCodes: ["<筛选器参数UUID>"]`（见 **§7.2**） |
| `公式` | 用公式表达式算出来 | — |

> **"把当前行的单位传过去"就是 `图表字段` + 字段名**，不需要写表达式。

## 3. ⭐ 配置前必须先满足的前提（最容易卡死的地方）

**目标报表的那个参数，必须先存在于目标报表的「分析参数」里。**

否则「所需参数」下拉里**根本没有它** —— 而且表现得非常像"缓存问题"：
刷新页面、关掉弹窗重开、保存报表，全都没用；在输入框里搜它只回一句「暂时没有数据哦~」。

语义模型加了参数还不够，**两张表要分别照顾**：

```text
语义模型里定义参数
  → 目标报表「更新模型」        ⇒ 只写进【模型参数绑定】（能看见，但没用）
  → 目标报表「数据 → 参数 → 分析参数」→ 添加同名参数 ⇒ 这才进【分析参数】
  → 保存报表                    ⇒ 下拉里才选得到
```

完整机制与判据见 [[01-筛选器与参数绑定]] **§10.5**。

## 5. 「普通过滤」为什么替代不了传参

「普通过滤」是对**目标表字段**做等值/包含/介于这类过滤，它表达不了"含下级"这种
**需要递归展开组织树**的语义。要做到"按单位含下级过滤目标表"，只有一条路：
**把源行的单位值传给目标表的参数，由目标表 SQL 里的递归去展开**。

> 相关的含下级 SQL 写法（递归 CTE + 达梦方言的两个坑：必须 `UNION ALL`、递归分支不支持 `DISTINCT`），
> 见 [[07-经验-语义模型报表开发]]。

## 6. 用 `browser_*` 驱动这个弹窗的实测坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **「值」下拉点不开** | 它是 `readonly` 的 `<input>`，外包 `div.wui-dropdown-trigger.input-dropdown-trigger`；只发 mousedown/click 会没反应 | 往 trigger 上依次派发**完整事件序列**（实测有效）：<br>`['mouseenter','mouseover','mousedown','mouseup','click'].forEach(t => trigger.dispatchEvent(new MouseEvent(t,{bubbles:true,cancelable:true,view:window,button:0,buttons:1})))`<br>⚠️ 直接调 React props 的 `onMouseDown/onClick` 本次**没生效**，先试事件序列 |
| **画布单元格怎么选中**（`hot.selectCell` 拿不到实例时） | 页面里没有可用的 Handsontable 实例（`window.Handsontable.instances` 为空） | 走 DOM：`.ht_master tbody tr` 的第 N 行 → 其中第 M 个 `td`，加个临时属性再 `browser_click` |
| **弹窗里的「值类型/所需参数」下拉** | 点击 `.wui-select-selector` 能正常打开，选项是 `.wui-select-item-option` | 先给目标 selector 打 `data-*` 标记再点，避免同一行多个下拉点错 |
| **「链接设置」是个折叠面板** | 直接点文字 `span` 没反应 | 点它的 `a.collapsible-header`（`aria-expanded` 变 `true`），**`+` 是展开后右侧那个 svg** |
| **不加号在哪** | 左侧字段区那一列有**两个**图标：上面是"数据库/数据集切换器"，**下面才是加号** | 加号的 `fieldid` 是 **`design|datamodel_aside|ana_plus_icon`**（`svg[fieldid="design|datamodel_aside|ana_plus_icon"]`），别点成上面那个 |
| **下拉选项要滚动收集** | 虚拟渲染一次只给一部分 | 边滚边 collect；本次实测「所需参数」12 项恰好一屏，但别假设 |
| **弹窗会随页面刷新消失** | 「更新模型」等操作会整页刷新 | 配置前先把前置条件（§3）做齐，再一次性配完弹窗 |

## 7. 完整实战（本次跑通的配置）

**需求**：汇总表数据行的「账户总数」格子 → 点击 → 跳转「账户明细表」→ 按**单位含下级**过滤。

| 项 | 实测值 |
|---|---|
| 源单元格 | 表样 `[5][3]`（第 6 行第 4 列），绑定字段 `accountCount` |
| 链接对象 | `报表设计`（在左侧树里选，然后选中目标报表） |
| 链接标题 | `账户明细表` |
| 页面选择 | `报表1`（= `a37b2853-7bf1-41e6-ae46-9353ff0c95bc`） |
| 打开方式 | `系统内新页签打开`（`_blank`） |
| 参数赋值 | 所需参数 `组织含下级` / 值类型 `图表字段` / 值 `id` |
| 触发 | 控制设置 → `单击`；`setting.trigger = "click"` |

### 7.1 ⚠️ 最大的坑：传过去的值，**ID 空间**必须和目标参数期望的一致

上面「值 = `id`」这一步，**第一次配完跳过去是空白的**，原因就在这里：

| | 值 | 说明 |
|---|---|---|
| 汇总表数据行绑定的 `id` 字段 | （一长串数字） | 模型里定义是 **`e.id`** = `org_epm_orginization_ext.id`（**体系成员 ID**） |
| 目标表参数期望的 | （另一串数字） | 组织档案 ID = `org_epm_organizations.org_source_id` |

库上实测（北京金隅集团股份有限公司）：

```text
汇总表传的 id（ext.id）   = 2570584346600144897
明细表期望的 org_source_id = 2531210465865367561
```

**两者不是一回事。** 传错 → 目标表按 `org_source_id = '<ext.id>'` 找不到起始节点 →
递归子树为空 → **跳过去一片空白，而且不报错**（静默失败）。

> **为什么不能"改成传 `source_org_id` 就算了"**：汇总表模型里**确实有** `source_org_id` 字段，
> 但它的**表样没有绑定**它；而「图表字段」的候选**只列表样里绑定过的字段**（本次只有
> `id / name / 法人公司数量 / 非法人公司数量 / accountCount / 合计accountCount`），
> 所以下拉里**根本选不到** `source_org_id`。

**解法（本次采用）：让目标表的参数兼容两种 ID**，不去动源表的表样：

```sql
       where o0.dr = 0
         and (o0.org_source_id = '${param('组织含下级')}'
              or e0.id = '${param('组织含下级')}')
```

**验证**：按 `ext.id` 展开子树 = 629 个成员 → 同口径 **287** 条，与按 `org_source_id` 展开**完全一致**。

> **通用教训**：「超链接传值」难的不是配置本身，而是**确认两边说的是同一个 ID**。
> 配完**必须真点一次**，别只看配置项都填上了 —— 传错 ID 是**静默失败**。
> 排查套路：拿到跳转时实际传的值，直接放到目标表 SQL 的起始条件上比一比。

### 7.2 ⭐ 把源表的「筛选器」值一起带过去（值类型 = `筛选器`）

**需求**：汇总表上有「开始日期 / 结束日期」筛选器，点击跳转时要把这两个值也带给明细表。

**做法**：在同一个「参数赋值」表里再加两行，**值类型选 `筛选器`**（不是 `参数`）：

| 所需参数（目标表） | 值类型 | 值（源表筛选器） |
|---|---|---|
| `开户日期起` | `筛选器` | `开始日期` |
| `开户日期止` | `筛选器` | `结束日期` |

存下来是这样：

```json
{ "field": "开户日期起", "valueType": "FILTERKEY", "valueOrCodes": ["e241f6df-823d-4648-8779-3368f1b279b5"] }
```

> **`筛选器` ⇒ `valueType: "FILTERKEY"`**，值是**筛选器参数对象的 UUID** ——
> 既不是筛选器显示名（`开始日期`），也不是界面控件的 `filter.id`（那个是 `f7e25147-…`）。
> **别手写这串 UUID**，走界面选。

**实测验证**（2026-10-11，金隅 dev）：

| 汇总表筛选器 | 跳转后明细表 | 库上同口径 SQL |
|---|---|---|
| 开始 = 2026-01-01 | **73 条** | 73 ✅ |
| 开始 = 2026-01-01 + 结束 = 2026-06-30 | **35 条** | 35 ✅ |

**两个必须知道的现象**：

1. **目标表的筛选器控件不回显。** 跳过去后明细表顶部「开户日期起」框里**是空的**，
   「已选条件」还写着「无」—— 但 SQL 已经按传进来的值过滤了。
   **别据此判断"没传成功"，看条数。**
   > 机制上：超链接赋给的是目标表的**分析参数**，而界面控件读的是**筛选器值**，平台里这是两套东西。
2. ⚠️ **别被"源表数字没变"骗了 —— 平铺模式下改完筛选器要手点「查询」。**
   查询按钮：`fieldid = filter_panel_handle_search_btn`（在筛选器右侧 `div.f-operations-brower` 里）。
   报表设置 `filterQueryData=false` 时不自动重查（同 [[01-筛选器与参数绑定]] §5.2）。
   **本次就在这儿误判过一轮**：填了日期、没点查询，看到汇总表「账户总数」还是 287，
   就断言"源表筛选器不生效"，白查了一大圈 API 定义 —— 其实点一下查询，它立刻变成 10（与库上同口径一致）。
   源表筛选器**本来就是有效的**，它和跳转传参是两条独立的路，互不影响。

### 7.3 ⭐ 一列一个链接 + 常量传参（多列各自传不同的固定值）

**需求**：汇总表六列「基本存款 / 一般存款 / 专用存款 / 临时存款 / 其他存款 / 保证金账户」，
点任意一格都跳明细表，且只显示**该单位下这一种账户性质**的账户。

**关键限制**：**一个链接的 `params` 对它覆盖的所有单元格是同一套** ——
所以"不同列传不同常量"**只能一列配一个链接**（共 6 个），一个链接管不了六列。

| 单元格（表样，0 基） | 列 | 账户性质常量 |
|---|---|---|
| `[5][4]` | 基本存款账户 | `D01` |
| `[5][5]` | 一般存款账户 | `D02` |
| `[5][6]` | 专用存款账户 | `D03` |
| `[5][7]` | 临时存款账户 | `D04` |
| `[5][8]` | 其他存款账户 | `D05` |
| `[5][9]` | 保证金账户 | `D06` |

每个链接里加同样的这一条参数：

```json
{ "field": "账户性质", "valueType": "CONST", "valueOrCodes": ["D01"] }
```

> **`常量` ⇒ `valueType: "CONST"`**，值放 `valueOrCodes`（数组）。
> 界面上「值类型」选「常量」后，「值」列会变成**普通文本框**，直接敲 `D01` 即可。

**目标表要能按这个值过滤**：明细表侧新增参数 `账户性质`，SQL 加

```sql
<#if param('账户性质')?? && param('账户性质')!=''>
  and cd8.code = '${param('账户性质')}'
</#if>
```

`cd8` 是明细表 SQL 里**已经 join 好的** `bd_cust_doc`（限定 `custdocdefid` = `JYSK0002`）。
⚠️ 汇总表那六列用的是**同一个档案的 `code`**（`purpose_code`）—— **两边同源，口径才对得上**；
若按名称过滤就换成 `cd8.name`，但编码比名称稳。

**实测验证**（2026-10-11，金隅 dev，北京金隅集团股份有限公司行）：

| 账户性质 | 汇总表列 / 库上 | 点进去的明细表 |
|---|---|---|

### 7.4 💡 配置量大时，搭平台自己的车批量改

配 §7.3 那 6 个链接，逐个点界面很慢。保存请求的真身：

```text
POST /iuap-data-analytic/report/save?isAjax=1&vtrace=…&locale=zh_CN&systenant=U8C3&listType=DIRREPORT&serviceCode=report-51
body: {"Datas":"<base64(gzip(报表定义整份JSON + token))>"}
```

解压后就是整份报表定义，链接在 `analysisModel.sheets[0].areas[0].setting.links[]`；
**尾部拼着** `xsrfIntellivSplitFIX_<token>!<数字>`（CSRF 令牌，**改内容时必须原样保留尾部**）。

**做法**：**别自己拼 HTTP 请求** —— Content-Type / 令牌 / 版本号任一处不对，就会报
`getObj() 为 null` 或「当前文件被其他人锁定编辑」。改成**拦截平台自己发出的那次请求**：

```text
1. hook open/send：open 里把 url 记到 this.__u，setRequestHeader 里把键值对记到 this.__h；
2. 在界面上做一次真实保存 → 在 send 里拦下：解压 body → 改 links → 重新压缩 →
   用**同一次的 url + headers + token** 新开 XHR 发出去。
```

> ⚠️ **两个踩过的坑**：
> ① 重装 hook 时新 `open` 若忘了写 `this.__u`，拦截条件永远不成立、请求被**原样放行**；
>    而界面弹出的"保存成功"是**真的** —— 极易误判成"我的改动生效了"。**判据只能是事后读服务端定义**。
> ② 拦截后平台的"未保存"标记被清掉，**再点保存就不发请求了**；要重发就用记下来的 url/headers 自己发
>    （先把 hook 关掉，否则连自己发的请求也拦）。

> 📌 发/拦请求的**通用姿势**与判据纪律（含上面两个坑的完整版）见 **[[08-操作手法与判据纪律]] §6**。
