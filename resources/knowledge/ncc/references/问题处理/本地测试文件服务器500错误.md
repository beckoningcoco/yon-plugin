# 本地测试文件服务器 500 错误

## 环境

- **项目**: 天九
- **版本**: NCC 2312
- **场景**: 本地启动 NCC 环境，测试接口

## 现象

本地测试接口时，返回如下错误：

```
Server returned HTTP response code: 500 for URL:
http://127.0.0.1:8096/fs/service/default/files/f9468e69-7721-40f3-834e-ab0afbf99c4f?params=BG7ne3tTuEDRZUwmyhc39E...
```

文件服务器（fileserver，端口 8096）返回 500，接口调用失败。

## 原因

本地启动的 NCC 环境，文件服务器连接的是本地数据库。接口返回的文件 UUID 对应的文件记录存在于**测试环境**（如 `123.57.249.193`），但本地机器上没有该文件的实际数据。

文件服务器在尝试下载/读取该文件时找不到文件 → 500 错误。

**注意**：此问题只在本地调试时出现，测试环境/生产环境上文件完整，不会报错。

## 解决方案

### 步骤 1：找到是哪个文件

在测试环境数据库执行以下 SQL，定位报错的文件：

```sql
SELECT *
FROM sm_pub_filesystem
WHERE filelength > 0
  AND (filepath LIKE '%1001D110000000ADN8BL/%');
```

> `filepath` 中的路径前缀根据实际情况调整，可以改 URL 中 UUID 对应的 filepath。

### 步骤 2：备份该条数据

将查询到的记录导出备份，或直接记录其内容，便于后续恢复。

### 步骤 3：删除该条文件记录

```sql
DELETE FROM sm_pub_filesystem
WHERE filelength > 0
  AND (filepath LIKE '%1001D110000000ADN8BL/%');
```

### 步骤 4：跳过下载流程

删除记录后，接口调用时将跳过该文件的下载流程，不再报 500 错误。业务逻辑不受影响。

## 总结

> 本地环境缺少测试环境上传的文件，导致文件服务器找不到文件报 500。通过 SQL 定位 → 备份 → 删除后即可跳过该流程。**测试环境不会出现此问题。**
