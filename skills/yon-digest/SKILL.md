# 消化一份素材

四步，一步都不能跳。**每一步的产出都从工具拿，不要凭印象做。**

```
1  重叠门禁    digest_audit（不给 product）      值不值得做
2  摸底        digest_plan                       分几章、每章从哪行到哪行
3  写页面      按下面的规范写                    一章一页
4  验收        digest_audit（给 product）        七项全过才算完
```

## 第一步：值不值得做

先跑门禁，**不要先读文档**：

```
digest_audit(source="<源文档绝对路径>", vault="<vault id>")
```

不给 `product` 就是只跑门禁模式。看重叠率：

- **≤ 85%** → 有增量，继续
- **> 85%** → 大部分内容已在库里。**先问用户增量在哪**，别急着做

实测过一份红皮书与库里已有官方文档重叠 91.2%——不跑这一步就会花大力气生产 91% 重复的内容。

## 第二步：摸底

```
digest_plan(source="<源文档绝对路径>")
```

它给你：页数、字符数、章节骨架、**每章的 offset 与 limit**。

**把 offset/limit 直接交给 read 工具分段读，不要按页号自己算范围。**

> ⚠️ 这条是踩出来的：按页号切章，把 2.3 部署架构的尾巴（p15–16）划给了下一章，
> 而负责下一章的人按"只写这一章"处理，**那半节从知识库里消失了**，直到最后
> 核对才发现。章常常跨页，`digest_plan` 给的范围是按标题边界算的。

它还会提示：源文档没有一级标题（章是从 `3.1`/`3.2` 的前缀推出来的，**标题是生成的，引用时用范围不要照抄标题名**）、图可能只剩图题、章节格式认不出来（这时要改配置）。

## 第三步：写页面

**一篇文档 = 1 个 `wiki/sources/` 索引页 + N 个 `wiki/topics/` 主题页**（通常一章一页）。

### frontmatter 五个必填

```yaml
---
tags: [标签]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [raw/articles/<源文件名>]     # 必须指向 vault 内的路径
platform_version: "BIP V5"            # 必填
project: ""
last_verified: YYYY-MM-DD             # 必填
status: unverified                    # 从文档抽取、未经环境实测的一律 unverified
source_type: doc
---
```

`status` 别随手写 `verified`——那个值表示"在真实环境验证过"。从文档读来的知识是 `unverified`。

### 正文必须做到

| 要求 | 为什么 |
|---|---|
| **每节标页码**，格式 `（p23）` | 用 **PDF 物理页号**。原文正文的页眉印的页码比物理页小 1，两者不要混 |
| **覆盖本章全部小节**，一个不落 | 验收会算覆盖率 |
| **照录清单、表格、步骤** | 不要概括成一句话——摘要式糊弄会让覆盖率掉到 20% 以下 |
| **照录约束**："必须/禁止/不支持/注意"一条都别丢 | 这些最容易被摘要吃掉，又最不能丢——使用者会因此踩坑 |
| **标识符原样保留** | `UCF-MDD`、`cdatarule`、`getQuerySchemmaByCond`（原文拼写）都不改写、不规范化大小写 |
| **图缺失就标注** | 写"原图未随文本抽取，此处无法还原"。**绝不凭图题想象图的内容** |
| **代码残缺就照残缺记录** | 注明"原文此处可能为代码片段，抽取后残缺"。**绝不补全代码或配置** |
| **原文笔误照录并加注** | 比如原文把 OMG 写成「OMGz」——照录，然后注明应为 OMG |
| **编者注用 `>` 引用块** | 见下，这是契约不是风格 |

### 编者注必须用引用块

```markdown
> 原文此处把 OMG 写作「OMGz」，应为 OMG 的笔误，上面按正字记录。
```

**这不是排版偏好，是契约**：`digest_audit` 的保真率检查会跳过引用块。批注里常常故意提到源文档没有的词（"原文拼写 `MddRefServcie`，疑为 `MddRefService`"）——后半截是要给的建议，不是事实声明。写在正文里就会被当成幻觉。

### 结尾两节

```markdown
## 原文没有讲清的
这里列真正缺的东西：图缺失、代码残缺、原文自己前后矛盾之处。

## 相关页面
- [[另一个主题页]]
```

## 第四步：验收

```
digest_audit(source="<源文档>", product="<页面文件或目录>", vault="<vault id>")
```

七项全过才算完：

| 项 | 阈值 | 不合格怎么办 |
|---|---|---|
| 结构完整 | frontmatter 五个必填 | 补字段 |
| 中文术语覆盖 | ≥ 85% | 有整节没写进去 |
| 二级章节覆盖 | ≥ 60% | 漏了小节 |
| 约束句覆盖 | ≥ 85% | 把限制条件略掉了 |
| 保真率 | ≥ 98%（两个口径取低） | **看逐条出处**——真幻觉要删，合法引用/批注要改成引用块 |
| 溯源密度 | ≥ 50% | 加页码标注 |
| 可寻址 | ≥ 70% | 产物太概括，源文档的术语进不去 |

**保真率报的"找不到"不等于幻觉**。报告会给出每条的出处，逐个判断：引用别处来源的（保留）、批注原文拼写的（移到引用块）、原文用文字描述层级而产物写成点号路径的（可保留），**真正编造的要删掉**。

## 它验证不了什么

**只能验证"覆盖"与"保真"，验证不了"正确"。** 产物忠实照录了原文的错误取值，照样判合格。涉及配置值、接口路径、参数名时，用前请对照真实环境验证。

**还有一处已知漏网**：纯英文单词形态的臆造（`DAO`、`Service` 这类不成标识符形态的词）逃过保真检查。

## 关于阈值

在 `~/.dsh/yon-panel/digest_config.json`，九组参数可改（阈值、章节模式、术语词表、页码格式等）。按素材类型调整——网页素材没有页码，`pageMarkPattern` 要换；章节编号形态不同的文档要改 `chapterPattern`。

**这些数是实测校准出来的起点，不是"正确的"数。** 85% 和 98% 能分开实测样本，换成你的素材类型可能需要调。

## 一份做完的样子

实测一份 133 页红皮书（6 章）：

```
sources/xxx.md     4.4 KB    文档级索引：是什么、六章导航、读它的提醒
topics/xxx-第1章.md  6.5 KB
topics/xxx-第2章.md 28.9 KB
...                        一章一页
```

验收结果：中文术语 98.0%、标识符 99.1%、二级章节 100%、约束句 88.9%、保真率 98.0%、溯源 191 处（100%）、可寻址 20/20。判定合格。

**对比**：同一个检查器对一份 1.1 KB 的"摘要式"产物判不合格——术语 2.8%、可寻址 5.0%。那份摘要列的六章内容与文档真实的六章**没有一条对得上**，是照标题想象出来的，而它标着 `confidence: EXTRACTED`。
