## 0. 这个设计器管什么、不管什么

| 层 | 管什么 | 去哪看 |
|---|---|---|
| **数据层** | 语义模型、SQL 口径、SQL 里的参数语法、静默错误 | 语义模型设计器；[[07-经验-语义模型报表开发]] |
| **展现层** | 表样与字段绑定、单元格属性、筛选器控件、参数绑定、打印/导出模板 | 本文与其子文档 |

**一句话**：SQL 决定「数对不对」，设计器决定「长什么样、能不能筛」。两边都要动；漏了展现层，
表现就是"筛选器摆在那儿不生效"。

## 1. 地址形态

```text
自由报表：  https://<host>/iuap-data-common/ucf-wh/intelliv/index.html#/report/query/edit/<报表ID>?serviceCode=report-51&locale=zh_CN&systenant=<租户>&listType=DIRREPORT
语义模型：  https://<host>/iuap-data-common/ucf-wh/intelliv/index.html#/semantic/query/edit/<模型ID>?serviceCode=report-28&locale=zh_CN&systenant=<租户>&listType=DIRSEMANTIC
```

- 同一个设计器前端，靠 `listType` 区分打开的是「报表」还是「语义模型」。
- 是 SPA：切菜单、换选中对象都**不改 URL**，判断"现在在哪"只能看内容区。
- URL 末尾常出现重复的 `serviceCode=...` 参数（平台自己拼的），无害。

## 2. 界面分区

| 区域 | 位置 | 实测说明 |
|---|---|---|
| 顶部菜单 | 最上方 | 表样 / 字段 / 公式 / 筛选 / 编辑 / 插入 / 数据 / 浏览 —— 是**功能切换**，不是导航 |
| 格式工具条 | 菜单下 | 字体、字号、加粗/斜体/下划线、边框、表格样式、合并、换行、数字格式（常规 / `.00` / `.0`）、冻结、识别扩展区域、识别交叉点、扩展区域 |
| 左侧字段区 | 左 | 上方是**数据集（语义模型）切换器** ＋ 「显示编码」勾选 ＋ 字段树；字段节点可拖拽（`draggable=true`） |
| 中间画布 | 中 | Handsontable 网格：A/B/C… 列头 + 1/2/3… 行号 |
| 右侧属性面板 | 最右 | 随选中对象切换：选中单元格 →「单元格 设置」；选中筛选器 →「<类型> 设置」 |

> 实测视口宽 2552px，右侧属性面板贴最右。用 `browser_eval` 定位时**按标签文字找**，
> 不要按 x 坐标硬编码。

## 4. 用 `browser_*` 驱动设计器的纪律（实测）

> ⭐ **这一节是早期版本。** 分类整理过、并且补上了「判据纪律」和「脚本清单」的版本见
> **[[08-操作手法与判据纪律]]** —— 动手前先看那一篇。下面 7 条仍然有效，留作对照。

1. **下拉菜单失焦会自己收起**。「插入」「筛选」这些是 `a.dropdown-text`，菜单项在
   `.wui-dropdown-menu-item`。**打开菜单与点菜单项必须在同一次 `browser_eval` 里连续做完**，
   分两次工具调用必失败（实测：第二次找不到菜单项）。
2. **下拉的 option 用完不销毁**。读某个 select 的选项时要过滤
   `getBoundingClientRect().width > 0`，否则会把上一个下拉的残留选项一起读进来
   （实测「筛选器类型」的 9 项会污染后面「来源」下拉的读取）。
3. **React 受控输入框**：设值要用 `HTMLInputElement.prototype` 的 value setter，再派发
   `input` / `change`；只派发事件不改值不生效。搜索类输入框还需补一次 `Enter`（`keydown`/`keyup`）。
4. **点击用 `mousedown` + `mouseup` + `click` 三连发**：部分组件只监听 `mousedown`。
5. **拖拽暂未见可靠做法**：字段是 `draggable=true` 的树节点，落点是 `.f-choosepanel`；本文
   未实测用合成 DragEvent 完成它。优先找属性面板里等价的「拖入字段」入口。
6. **列表未必是 `<table><tr>`**：`innerText` 或虚拟滚动区域里的可见节点比 `querySelectorAll('tr')` 靠谱。
7. **别只看 `browser_snapshot`**：这个设计器大量 `div` 当按钮，快照枚举不全；`browser_read` 的文本往往更全。

## 5. 设计器背后的接口（想直接读配置时）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/iuap-data-analytic/report/design/<报表ID>` | GET | 报表设计态定义 |
| `/iuap-data-common/ds/getSource/<数据源ID>` | GET | 数据源连接信息（含 `filters` 字段），**不是**字段列表 |
| `/iuap-data-common/ds/getFilters` | **POST** | 筛选器（用 GET 会返回 405） |
| `/iuap-data-analytic/component/ana/queryAllComponent` | GET | 组件 |
| `/iuap-data-common/semantic/model/get/<模型ID>` | GET | **语义模型定义**（`data.model`：`tables[0].sql` = SQL 正文、`params` = 参数声明）。语义模型的 `serviceCode` 是 `report-28` |

> 想抄一张报表的配置，先抓 `/report/design/<id>`；想看某数据源挂在哪，抓 `/ds/getSource/<id>`。
