## 开工纪律

1. **先确认产品线与报表 ID**：这是旗舰版的数据工场（`#/report/query/edit/<id>`，`listType=DIRREPORT`）；
   NCC 的报表是另一条线，不适用。
2. **设计态 ≠ 运行态**：文档说的是设计器操作，改动要**保存**才生效。动使用者的报表之前先说清要改什么，
   动完告诉他改了什么（别默默改）。
3. **能复用已登录的页面就复用**：先 `browser_targets` 找使用者开着的设计器页面再 `browser_attach`，
   不要自己开新页面重新登录。
4. **组织树优先用语义模型字段组树**（树形参照 →「来源」选语义模型），**不要**挂平台组织档案参照——
   两边不是同一个 ID 空间，过滤会恒不成立且不报错。
5. **"点了没反应"先怀疑操作方式**：这个设计器的下拉菜单失焦即收起，开菜单与点菜单项必须在
   同一次 `browser_eval` 里连续完成；输入框分两种 —— 参数值/脚本类用原型 setter + `input`/`change` 即可，
   而**筛选器「名称」这类属性框不认合成事件**，必须走真实键盘输入（`browser_type`，先 `focus()`+`select()`
   再输入可整体替换），否则改名看着成功、保存后打回原形。
6. **要拖字段进「拖入字段」区时，合成 `DragEvent` 无效**（HTML5 拖放要真实手势）：走 CDP
   —— `Input.setInterceptDrags(true)` → 在源元素 `dispatchMouseEvent(mousePressed)` 后连续 `mouseMoved`
   （浏览器会回发 `Input.dragIntercepted` 带真实拖拽数据）→ 在目标坐标 `Input.dispatchDragEvent`
   （`dragEnter`/`dragOver`/`drop`）→ 关拦截。每拖一个字段后拖放区位置会右/下移，**要重新取坐标**。

## 常见问题速查

| 现象 | 先查 |
|---|---|
| 筛选器摆上了但不生效 | 数据设置 →「参数绑定」做了没；语义模型 SQL 里有没有 `${param('编码')}` 与 `<#if>` 兜底 |
| 参数绑定的**参数下拉是空的**（"暂时没有数据哦~"） | 语义模型改过参数、报表缓存旧元数据。新参数属于**主数据集** →「更新模型」（左侧字段区**加号 → 选择模型字段 → 右上角「更新模型」**）；属于**另一个数据集**（如合计）→「更新模型」同步不到，要**整页刷新 F5** 才出现 |
| **筛选器下拉是空的**（"暂时没有数据哦~"） | 这是**筛选器自己取不到数**，不是报表没数据。先看三样：① 它引用的模型是不是**副本**（认编码 `..._copy1`，别看中文名）；② 模型 SQL 用的参数是不是**同名**、值被别的数据集抢走了；③ 该用「参照」却配成了「树形参照」（模型无层级字段时，面板里子级/父级字段下拉是空的）。详见 `报表设计器/02` |
| **配筛选器 / 筛选器不生效** | 加筛选器、筛选器下拉空、参数绑定、值字段拖不进去、模型加了字段报表看不到、参数下拉里没有新参数 | `bip/references/旗舰版/报表设计器/01-筛选器与参数绑定.md` —— **§8 完整流程**（①「插入→自定义筛选器」用**真实指针**；②「名称」用**真实键盘** `browser_type`，任何 setter 都只改 DOM；③「值字段」**只认 CDP 真实拖拽**；④ 参数绑定三个下拉：参数 / `筛选器字段` / 该筛选器绑定的字段）。**§9** 拖拽脚本 `drag-node.mjs`（setInterceptDrags → mousePressed → 分段 mouseMoved → dragIntercepted → dispatchDragEvent）。**§10 模型加了字段或参数后**：① 加号→「选择模型字段」→「更新模型」（会弹确认窗+整页刷新）；② **勾选字段**（控件是 `span.wui-tree-checkbox`，**点节点文字只会高亮，不会勾选**） |
| **表样要插列 / 删列 / 往单元格写字** | ⚠️ **先读** `bip/references/旗舰版/报表设计器/03-表样结构操作与结果验证.md`。**五条要点**：① **先拿到 `hot` 实例**（`fiber.stateNode.hotInstance`；`window.hot`、`Handsontable.instances`、元素上的 `hotInstance` **都不是**），**之后一切读写都用它的 API**；② **找列索引只有一个可靠来源：`hot.getDataAtRow(1).indexOf('列名')`** —— DOM 的列头字母（与 `hot` 索引错位，实测 DOM 说 `销户时间=V`、`hot` 里是 47）、`th`/`td` 数量（同一张表能数出 24/36/37/50）、x 坐标对齐（列头宽 100 ≠ 数据列宽 185）、`data-col`（恒为 null）**全都会给出偏差**；③ **插列**：`hot.selectColumns(col)` 选中整列 → 顶部「插入」→「列」（若弹「插入」对话框，必须选「整列」+列数 1+确定）；④ **往单元格写字只能用「编辑 → 粘贴」**：本机 `Set-Clipboard` 放好字 → `hot.selectCell(r,c)` 选中 → 点「编辑→粘贴」→ 保存。**`hot.setDataAtCell()` 只在内存生效、保存不进去，严重时把整块画布渲染成空白**（`browser_type`/`setValue`/合成 `keydown` 则只在 DOM 打转）；⑤ **刷新后第一件事是看有没有「未保存的改动」弹窗**，拿不准就**刷新 + 点「否」** = 完全回到服务端定义 |
| **报表查出 0 行**（合计也空） | 先把 SQL 里的参数**换固定值在库里实跑**（`datasource_query`）：能出数 = 参数问题，出不了 = SQL/数据问题。★★★ **三条最高频**：① **模型参数的默认值压根没被带上**（参数设置里有默认值，报表取数拿到空——不是被抢，是没人传；关键列必须 SQL 内 `<#if>/<#else>` 兜底）；② **同名参数冲突**（该参数在报表里只有一个 paramId，却有多张数据集用它 → 非主数据集的拿不到值）；③ **改动没保存**（模型页面「执行」读**编辑态**，报表取数读**已保存定义**；保存时若弹「已被对象引用」必须点「修改」） |
| ⭐ **同一份数据两处不一样**（报表预览 比 语义模型预览 少）/ 使用者说"我没绑这个参数"/ 问"是不是缓存" | **先看 `数据 → 参数 → 参数设置` 里该参数的「默认值」** —— 默认值可能被设成**常量**（藏在「设置默认值」二级弹窗：权限标签 / 系统变量 / **常量**），常量默认值 = 每次执行都强塞给模型，模型 SQL 的 `<#if param('x')?? && param('x')!=''>` 因此恒成立、行数变少而**不报错**。⚠️ 清默认值**未必**清掉运行值：平台取数用 `value`（还有 `vOrCs`/`defaultParseVals`/`baseParam.value`），清完要**保存 + 刷新**再核对这几处。详见 `报表设计器/04-参数设置与默认值.md`。**判断"缓存还是配置"别靠界面找** —— 按 `报表设计器/05-排查方法论-配置还是缓存.md` 四步走（扫 localStorage/sessionStorage/cookie 排除本地缓存 → 读前端 React 里的 `analysisModel.params` → 与服务端 `report/design`、`semantic/model/get` 对账 → 库上数行数闭环） |
| **合计行不跟着筛选动** | 明细与合计是**两个数据集、两个参数名** —— 报表侧要各绑一条；合计模型 SQL 里也得有对应的 `<#if>` 过滤 |
| 组织树选出来的值过滤不到数据 | 树是不是用**语义模型自己的组织字段**组的（不是系统参照档案）；模型里有没有 `parent_id` 这类层级字段 |
| 加筛选器的入口找不到 | 顶部「插入」菜单最后一项「自定义筛选器」 |
| **新建语义模型点「确定」没反应、不发请求** | 名称是多语言输入组件，`set_value`/`fill` 只改 DOM 不进 state → 必须 `browser_type` 真实键入（详见 `报表设计器/09` §1.1） |
| **模型「参数设置」里「新增参数」只生效一次 / 确认不关闭** | 有未填的空行阻塞 → **填一个增一行**，全部填完再「确认」（`报表设计器/09` §1.4） |
| **表头多列粘贴挤进一个格子** | 纯文本剪贴板不分列 → Clipboard API 写 `text/html` 表格再「编辑→粘贴」（`报表设计器/09` §1.7） |
| **「批量字段绑定」字段加不进右侧** | 点字段行**右侧的「+」**（`.ap-tianjia`）；加号不消失，**按索引逐个点**，否则同一字段加 N 遍（`报表设计器/09` §1.8） |
| 筛选器类型有哪些可选 | 实测 9 种：树形下拉 / 下拉 / 树形参照 / 日期 / 左树右表 / 参照 / 平铺 / 输入框 / 系统参照 |
| **该用「参照」还是「树形参照」** | 选**平铺列表**里的一项（如组织体系列表）→ **参照** `REFERENCE`，模型只要有"值列+显示列"；选**树上的节点**（如组织层级）→ **树形参照 + 树类型=父子树** `REFERENCE_TREE`，此时来源模型**必须有子级 ID 与父级 ID 两列**，否则「子级字段/父级字段」下拉是空的、配了也查不出数。⚠️ 定义里 `tflds` 是 **`[父级, 子级]`**，与面板顺序相反。样板见 `报表设计器/01-筛选器与参数绑定.md` §5.5 |
| 「来源」下拉里选不到想要的模型 | 该模型没挂在这张报表上，或它不含组树需要的字段（如只有汇总指标、没有组织字段） |
